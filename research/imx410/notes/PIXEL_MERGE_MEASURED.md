# 感光元件怎麼合併像素 —— 從 RAW 反推 (2026-09-17)

素材:`~/Downloads/vs6000x3000/`,同一場景、同 ISO 100、一分鐘內拍的三個檔:

```
SDIM0317.DNG    6064x4042  14-bit  1/125   全解析度靜態(Compression=7)
A001_001_...    1936x1090  12-bit  1/50    原廠 FHD CinemaDNG
A001_002_...    2016x1344  12-bit  1/50    本專案的 OG2K build
```

工具:`../pixmerge.py`(只要 rawpy,不用相機)。

## 一句話

**每個輸出像素可以取用 9 個同色感光點。原廠 FHD 用掉 8.5 個(等於完整的 3×3 平均),
OG2K build 只用 4.1 個(每軸三取二)—— 同樣的輸出解析度下,OG2K 丟掉了 9 個裡的 5 個,
代價是 0.53 格雜訊。** 合併是正規化平均(不是電荷相加),而且視窗不重疊。

## 怎麼量的

散粒雜訊給了一把直接的尺:`σ² = K·μ`,K 是每電子的 DN 增益。把 N 個感光點平均起來,
訊號不變而變異數降為 1/N,所以 **σ²/μ 會變成 1/N**。拿全解析度靜態當 N=1 的基準,
任何模式的 `N_eff = (σ²/μ)_靜態 / (σ²/μ)_該模式`。

曝光時間不同沒關係(σ²/μ 與曝光無關),取景不同也沒關係 —— 這是本次唯一不依賴
跨檔對應關係的量測,也是唯一站得住的一條。

做法:自動搜出各檔最平坦的亮區(σ²/μ 最小的 8 塊),扣掉三次多項式趨勢再取殘差變異數。
不用人工挑區域,四個 CFA 通道各自獨立算。

## 結果

```
                    σ²/μ (12-bit 當量)     N_eff
SDIM0317 全解析度        0.0650            1.00   ← 基準,一個感光點
FHD 1936x1090            0.0076            8.53
OG2K 2016x1344           0.0159            4.10
```

四個通道分別是 R/G1/G2/B,彼此一致(FHD 8.1–8.8、OG2K 4.1–4.6)。

**為什麼可用的是 9 個:** 輸出也是 Bayer,所以同色輸出像素的間距是 2 個輸出像素 =
約 6 個感光點 = 每軸 3 個同色位置 ⇒ 3×3 = 9 個同色感光點,而且彼此不重疊。
`8.53 ≈ 9`(全取)、`4.10 ≈ 4`(每軸三取二,就是 Sony 常見的 "加二跳一")。

## 三個排除掉的替代解釋

**不是電荷相加。** 相加會讓訊號亮 N 倍。拿兩張影片都拍到的同一片柏油路面比:

```
FHD 303 DN   OG2K 296 DN     同 1/50 → 增益差 2.4%
靜態 111 DN @1/125  ×2.5 = 278 DN     與影片同級
```

1×、4×、9× 三種合併給出同樣的 DN ⇒ **合併後有正規化,是平均**。這同時也證明
σ²/μ 的差距不是增益造成的(這是本量測唯一的系統性風險,已壓到 2.4% 以內)。

**不是雜訊抑制,視窗也不重疊。** 平坦區的雜訊頻譜(PSD ÷ 變異數,白雜訊 = 各頻帶 1.0):

```
                 0.05  0.11  0.17  0.23  0.29  0.35  0.41  0.47  cyc/px
靜態             3.98  1.08  1.00  0.89  0.95  0.86  0.85  0.91
FHD              3.38  3.09  1.31  0.97  0.80  0.75  0.84  0.80
OG2K             2.64  2.29  1.21  0.96  0.90  0.78  0.85  0.90
```

三者的尾端都平在 0.8–0.9 ⇒ **雜訊是白的**。若有內插式縮放或空間降噪,相鄰輸出像素
會共用輸入樣本、雜訊會相關、高頻會滾降。沒有。所以兩條影片路徑都是乾淨的
不重疊合併,沒有藏著的 NR。

> ⚠️ 本文上一版曾說 FHD 的雜訊被強烈相關(高頻只剩 0.09)。那是**區塊取太大**
> (96×96)把雲層結構算進殘差造成的假象,已撤回。區塊必須小到真的平坦。

## 沒能定的事

- **類比 binning 還是數位平均**,分不出來。兩者在散粒雜訊主導的亮區完全同形;
  要分只能量 μ→0 的讀出雜訊底(類比相加後正規化是 σ_r²/N²,數位平均是 σ_r²/N,差 N 倍)。
  這批亮部素材裡讀出雜訊遠低於量測誤差 [P]。
- **合併發生在哪一級**(感測器讀出 / CRCT 的 hbin,vbin / RWZM),這三個檔看不出來。
  `REDUCTION_INVENTORY.md` 記的列舉是 hbin ∈ {1,3,5}、vbin ∈ {1,3} —— 能產生每軸 ÷3,
  但那個列舉不保證 ÷3 是「三個都平均」還是「三取二」。本文量到 OG2K 是後者。
- **各模式實際的裁切/間距**。全域相位相關給 0.96、局部特徵比對給 1.02–1.04,兩者矛盾,
  多半是三個檔之間鏡頭狀態也動過(靜態的視角明顯不同)。**結論不依賴它** ——
  不論間距是 3.00 還是 3.12,可用的同色點都是 9 個。
- 我一度用「同物理頻率下的頻譜比」去佐證前置濾波寬窄,結果依賴上面那個對應關係,
  **一併撤回**,不列入證據。

## 這答掉了 `SENSOR_MODE_METADATA.md` 的一個未決

那份筆記把 `+0x4C/+0x50` 認定為「有效 X/Y geometry scale」,並明講
**「但究竟是 charge binning、skipping,還是其他」沒有證據**(該文 §未決;
另有「`_MIX` 與 2x2 geometry scale 一致,但 MIX 不足以證明 charge binning」)。
它也記下 OG2K 的基底 **M139 = 2016x1344、3x3、6048x4032 ≈ 全感測器** ——
與本文「可用同色點正好 9 個」的前提一致。

本文的量測給出那一格的值:**M139 標示的 3x3,實際只平均了 9 個裡的 4 個**,
是加二跳一,不是三個都加。而原廠 FHD 的那個模式是把 9 個都用上的。
所以 `+0x4C/+0x50` 的 3 是**間距**,不是抽頭數 —— 兩者在這顆感測器上不相等。

## 這對 OG2K 的意思

同樣 2016×1344 的輸出,兩條路的差別是:

```
每個輸出像素收的光    FHD 路徑 9/9        OG2K build 4/9
雜訊功率              1.00                2.08        → 0.53 格
前置濾波              每軸 3 抽頭          每軸 2 抽頭  → 較銳、較容易混疊
```

OG2K 不是「從感測器拿到更多」,而是**比原廠 FHD 少收一半的光**。若那個 ÷3 能改成
三個都平均(硬體看起來做得到,原廠 FHD 就是這樣跑的),同解析度下可以白拿 0.5 格。
值得單獨查:是哪一級決定了「三取二」,以及那一級能不能改 —— 這關係到 OG2K/OG3K
的畫質上限,而不只是幾何。

## 工具

```sh
./pixmerge.py <全解析度.DNG> <模式A.DNG> <模式B.DNG> ...
```

第一個檔當 N=1 基準,印出各檔的 σ²/μ、N_eff 與雜訊頻譜。前提是同 ISO;
曝光與取景可以不同。附帶的 `load.py` / `flat.py` / `align2.py` 是過程中的散件。
