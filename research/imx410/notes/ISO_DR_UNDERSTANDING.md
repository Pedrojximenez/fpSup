## 0. 一句話

**ISO 不是加光,是「把已經接到的光看大」。** 看得越用力(增益越高),能記錄的高光範圍越窄、而暗部的改善追不上高光的損失,所以寬容度就掉了;數位增益更是純損。真正該做的是**用快門/光圈接更多真的光(ETTR)**。

---

## 1. 核心觀念:增益 ≠ 曝光

- **曝光**(進多少光子)= 快門 × 光圈。這才是「真的水」。
- **ISO 增益** = 只是把訊號放大 / 換個量杯來讀,不會多收一個光子。
- 因此 ETTR 的做法是:**在基礎 ISO 用快門/光圈把高光填到接近爆點**,而不是拉 ISO 變亮。

### 水桶比喻(全文通用)
- 每個像素 = 一個接雨的水桶;快門/光圈 = 接多久、桶口多大 → 桶裡的**水量**。
- 桶滿 = 最亮的白(爆點);幾乎空 = 最黑。
- **寬容度** = 同一張裡能同時看清「快滿的桶」和「只有幾滴的桶」。

## 2. 三軸增益模型(fp/IMX410)

韌體把感光元件增益拆成**一個「大小」+ 兩條「讀出模式軸」+ 一層數位**:

```
增益大小:  類比 code(reg 0x3D–0x40,≤ 30 dB)──超過──▶ ISP 數位增益(四通道)
讀出模式①  CG 軸:LCG ↔ HCG      (reg 0x05E1;雙原生切換 640 / 3200)
讀出模式②  AR 軸:Normal ↔ High  (reg 0x05E2 / 0x041F;code ≥ 0x0DFD ≈ ISO 800 切)
```

| 項目 | 事實 | 來源/信心 |
|---|---|---|
| 增益法則 | `linear = 4095/(4095−code)`;`code = round(4095·(1−10^(−dB/20)))`;`dB = 20·log10(rel%/100)…` | CONFIRMED (v8 @0xC0323580) |
| rel-gain 表 | ISO 100→117、每檔加倍(0xc0746728,11 檔);ISO 100→102400 共 60 dB | CONFIRMED |
| 類比上限 | **30 dB**(≈ ISO 100→3200);超過送數位 | 模型級 CONFIRMED(codex EXPANDED_ISO)。每台微調 = OTP `S+0x68`(ROM=0) |
| 類比暫存器 | **0x3D/0x3E(+鏡像 0x3F/0x40)** 才是主類比;0x5C/0x5D 是 test-only | CONFIRMED(更正舊筆記) |
| CG(LCG/HCG) | reg 0x05E1 + trim 0x05A6/0x05A8;HCG dB 基準減 `S+0x7c` | CONFIRMED |
| AR(Normal/High) | reg 0x05E2、0x041F=0x0E(LCG)/0x1D(HCG);code≥0x0DFD 切 | CONFIRMED |
| 數位增益 | **全在 ISP**,感光元件無數位增益暫存器;unity=100;`set_gain_state 8` 關掉 | CONFIRMED |

**AR 是什麼:不是多一層倍率,是「高類比增益時換一套讀出/偏壓配置」的模式切換**,為該增益段重新最佳化噪聲/線性,與雙原生 CG 切換**正交**。CG × AR = 4 種讀出組合。

## 3. 為什麼增益上去,寬容度會變小

先記:寬容度 = log2(可用滿井 ÷ 讀噪)= 從「最亮能記到哪」到「最暗還分得出」的檔數。

### ① 類比增益:高光天花板掉得比噪聲快 → DR 淨減
- 滿井固定。升 1 檔類比 = 訊號進 ADC 前 ×2 → ADC 在**一半的光**就飽和 → **高光天花板 −1 檔/檔**。
- 讀噪(換算輸入端)也會降,但**降不到 1:1**(有一部分噪聲在增益之前、以電子數計是固定的)。
- 兩者相減 → **每檔 DR 淨掉一些**。（量杯換小 → 滿桶更早溢出;賺的暗部乾淨追不上丟的高光。）

### ② 數位增益:純損,砍寬容度最狠
- 類比到頂後再高 ISO,只能在 ADC **之後**做數位乘法。
- 噪聲在 ADC 那刻已定型 → **數位乘法不降噪**;只是更早撞最大碼 → **高光又掉**。
- = 高光白掉、暗部零改善。等同「在 max-analog ISO 拍 + 後製 +EV」。**這就是要排除的 ISO。**

### ③ 雙原生:為什麼有個「跳回升」
- HCG 改變像素浮動擴散節點的電荷→電壓比,是一個**讀噪明顯更低**的硬體基準點。
- 所以 DR 對 ISO 的曲線**非單調**:一路掉 → 到 HCG 切換點**讀噪 floor 降下來 → DR 跳回升** → 再一路掉。
- 加上 AR 軸,實際上會有**兩個台階**(CG 一個、AR 一個)。

## 4. ISO 不變性 / 「只動曲線」(低段無損失)

**現象:** 錄影低段(約 ISO 100–800)看不到 DR 損失。**原因 = 那段的「ISO」比較像貼便利貼改亮度,不是真的換會吃高光的增益。**

- **RAW 是線性資料**,低段的 ISO 可只當**沖洗增益 / DNG 亮度標籤**貼上去,類比讀出維持 base → 高光天花板不動 → 寬容度不變。
- 就算動了一點類比增益,那段是 **ISO-invariant**:高光掉多少、讀噪降多少剛好抵銷 → 工程 DR 看起來平的。
- **代價**:既然只是便利貼,**也沒有真正降噪好處**(機內拉 ISO ≈ 後製拉亮)。呼應 ETTR:這段該去接更多真光,ISO 給不了你更乾淨。

### 為什麼便利貼套下去不會爆:管線比感光元件杯大
- 感光元件杯(拍照)= **14-bit(16383 格)**。
- 內部處理管線(黑階/WB/demosaic/CCM/tone)= **16-bit(65535 格)= 大 4 倍的水缸**。
- 把杯水倒進大水缸做數學(乘曲線、白平衡、調色),缸比杯高 4 倍 → 不溢、細節不被四捨五入 → **這就是低段「只動曲線」不損失的關鍵**。
- ⚠️ 「16-bit」是**內部管線**,不是感光元件讀出。感光元件真實讀出:拍照 14-bit、CinemaDNG 12/10-bit(見 §7)。

---

## 5. 爆白只能看「感光元件輸出」,不看管線、不看直方圖

- 爆白 = **感光元件那一刻**光子填滿井、ADC 撞 14-bit 天花板;那一刻資料就死了。
- **16-bit 管線是下游**,只是搬運已爆的值,再多空間也救不回 → 看管線會**騙你**。
- **顯示直方圖更下游**(套 gamma + WB),對 RAW 爆點不準。
- 正確標尺:
```
有效刻度 = [BlackLevel(底) … WhiteLevel(爆點)]   ← 都在感光元件線性域
判爆白:  拍照看 14-bit;CinemaDNG 看當前品質(8/10/12,最深 12)
```
- **這是 ETTR 選「live-view 線性 RAW」當量測源、而非直方圖的根本原因。**

## 6. 雙原生:拍照 100/640 vs 12-bit CDNG 100/3200

韌體 `v30` 依 gain_state 決定 HCG 切換門檻:

| mode | gain_state | HCG 門檻 |
|---|---|---|
| 0 | through(live-view) | OTP `S+0x84`(每台) |
| **1** | **acq(拍照擷取)** | **ISO 640** |
| 2,3 | through_acq / movie | 640 |
| 5,6 | 8/10-bit | 640 |
| **7** | **12-bit CinemaDNG** | **ISO 3200** |
| 4,8 | movie_raw / digital_off | 永不切 |

→ **拍照雙原生 = 100 / 640**;**12-bit CinemaDNG = 100 / 3200**。

### 為什麼 12-bit 用 3200-hold,拍照(14-bit)用 640
一句話:**HCG 的好處(低噪)只有位元夠細才看得到。**
- **12-bit = 只能看粗刻度**。HCG 那副細刻度**細到超過 12-bit 能分辨** → 換過去看不到降噪好處,卻白丟高光容量 → **死守 LCG(胖大杯)到 3200 保高光**。這是 12-bit 的權宜之計。
- **14-bit = 看得到細刻度**。HCG 的乾淨暗部**真的用得到** → **640 就切**,直接拿到乾淨雙原生。
- 所以「為什麼不給拍照用 3200-config」:對 14-bit,3200-hold 是**錯的工具** → 會在 640–3200 一路用 LCG 粗刻度(暗部更髒),換來 HCG 本來就處理得更好的東西 → **整體更差**。不是好東西被藏,是不適合 14-bit。

### 為什麼「cdng12 640 不好」(社群經驗的韌體解釋)
12-bit 下 ISO 640 ≈ 16 dB 類比增益,卻卡在三個好處都還沒到:

| 事件 | 觸發 | 640 處境 |
|---|---|---|
| HCG 低噪重定基準 | ISO 3200 | ❌ 還早,仍在噪的 LCG |
| AR HIGH 讀出重最佳化 | code≥0x0DFD ≈ ISO 800 | ❌ 差一點沒到 |
| 類比增益吃高光 | 累積中 | ✅ 已吃掉 ~2.7 檔高光 |

= **壞處全拿、好處全沒 → DR/噪聲曲線的局部谷底。** 所以 12-bit 就拍 **100 / 3200 兩個原生**,別停在 640。

## 7. 位元深度與杯子刻度

位元深度 enum(`FUN_c02DA870`):`0→12, 1→14, 2→16, 3→10, 4→8`。

| 模式 | 感光元件杯刻度 | 備註 |
|---|---|---|
| 拍照 DNG | **14-bit → 0…16383** | 實測 6064×4042 |
| CinemaDNG(預設) | 12-bit → 0…4095 | |
| **CinemaDNG(8/10/12 三選一)** | 12-bit → 0…4095(最深) | **沒有 14-bit CDNG**;見下方訂正 |
| 16-bit | (無真實讀出) | enum 有值 + `raw16bit:` log,但**零擷取模式/gain_state/選單** → 對 fp 是框架值/內部容器,**不是感光元件讀出模式** |

**訂正(2026-09-15):先前寫「CinemaDNG 可選 14-bit」是錯的,收回。**
那是把除錯指令 `imager createraw <rawbit>` 的參數當成了選單選項。實際證據:

- 韌體只有三個 CDNG 品質字串:`Qual:8bit` / `Qual:10bit` / `Qual:12bit`(0x748318、0xBA12DC 兩處)。
- 影片增益狀態有四個:`<flag> [4:movie raw 5:movie raw 10bit 6:movie raw 12bit 7:movie raw 8bit]`。
  **沒有專名的 `movie_raw_14bit`**,但 generic state 4 `movie_raw` 已存在且有效;
  它不切 HCG、使用 generic digital ladder。能否供 RAW14 使用及黑階/白階校正
  是否正確仍待驗,不能直接推成「沒有 gain state」。
- 70 筆感測器模式中 8 筆 RAW14 全部是 1/1 1/1(零縮減),名稱表 250 格裡
  所有 `_MIX` geometry-reduction 模式一律帶 `_12BIT`,**不存在 `ACQ_MIX`**。

→ 錄影的爆點標尺永遠是當前 CDNG 品質的 WhiteLevel(12-bit 時 4095),
只有拍照 DNG 才是 14-bit 的 16383。詳見
`projects/open-gate/notes/OG14_FEASIBILITY.md`。

## 8. 延伸 ISO(擴展)行為

- **延伸-低(ISO 6/12/25/50)**:全部 clamp 成 ISO 100 的請求(pull/曝光指數);RAW 讀出增益還是 100 → **救不了高光、給不了更低類比**。
- **延伸-高(ISO 51200/102400,及類比上限以上的高 ISO)**:靠 ISP 數位增益;等於後製乘大低 ISO RAW → **不增 SNR、不增資訊**。

## 9. 實務結論(給 ETTR 用)

**乾淨 ISO(不砍寬容度)= 雙原生 + 純類比步,絕不進數位區。**

- **總 60 dB 中,前 30 dB 類比(乾淨),後 30 dB 數位(砍寬容度)。** 30 dB ≈ ISO 100→~3200。
- **拍照白名單**:ISO **100 … ~3200**,**優先落原生 100 / 640**(還可考慮 ~800 AR-HIGH 讀出重最佳化點)。
- **12-bit CDNG 白名單**:鎖 **100 / 3200 兩個原生**,避開 640 谷底。
- **排除**:延伸-低 6–50(=ISO100 無意義);超過類比上限走數位的高 ISO(51200/102400 確定,6400 以上逐漸摻數位)。
- **ETTR 的 ISO 上限** = min(使用者選單上限, ~ISO 3200 類比邊界);超過就走**光圈開大 fallback**,不進數位區。
- **保險**:全程 `imager set_gain_state 8` 關數位,硬體層確保絕不誤入數位區。

### 可玩的開關
- **`imager high_gain_off 1`**(`FUN_c0320ca0` 寫物件 +0x37):force LCG。可讓拍照也「胖大杯撐到底」拿最大高光天花板(代價:14-bit 下暗部更噪,一般不建議常態)。
- **`imager set_gain_state <0-8>`**:切讀出模式(8=關數位)。
- 直寫 `i2c w 0x05E1`:手動切 CG。

## 10. 一頁速記

- ISO = 放大,不是加光;ETTR 用快門/光圈接真光。
- 三軸:類比 code(≤30dB)+ CG(LCG/HCG,640/3200)+ AR(Normal/High,~800)+ 數位(ISP,純損)。
- 增益↑→高光天花板↓比噪聲降得快→DR↓;數位增益純損;雙原生/AR = 讀噪重置台階。
- 低段「只動曲線」不損失,因為內部管線 16-bit > 感光 14-bit,有頭空間;但也沒降噪好處。
- **爆白看感光元件 14-bit 輸出(WhiteLevel),不看 16-bit 管線、不看螢幕直方圖。**
- 拍照雙原生 100/640(14-bit 看得到 HCG 好處);12-bit CDNG 100/3200(粗刻度保高光);12-bit 640 = 谷底別碰。
- ETTR 乾淨 ISO:100…~3200,優先原生,關數位。
