2026-09-24。僅分析現有素材，沒有修改 DNG、TIFF、相機或 Resolve 專案。

## 使用者後續補充：靜幀及受管理的輸出

使用者確認這兩張來自 Resolve 內建截圖／靜幀功能，並描述流程為「P3 D60 input、無轉換直接映射進 DWG，再由 DWG 自動轉換成 709」。因此本次量到的是這條受管理流程的最終影像反應，不應稱作直接的 P3 D60／場景線性輸出。

使用者已進一步確認：「無轉換」指 **Input DRT=None**，不是將 P3 數值直接重新指派為 DWG。本機官方 Resolve 21 手冊第 233–235、241、245–246 頁說明 RCM 的輸入→時間線與時間線→輸出轉換；Input DRT=None 關閉輸入 tone mapping，不能解讀成停止色彩基底轉換。專案預設 Input Color Space 也不直接支配 RAW 的來源識別；RAW 由其解碼／原廠色彩資料路徑管理。這項確認不需要新增 CST；其他個別片段／節點及輸出映射細節未逐一核查。

**解讀收斂：**原廠 CM 的改動確實影響最終影像，仍是有效結果。以下矩陣擬合及特徵值只描述這個場景的近似反應，不能當作已驗證的 fp 場景線性輸入轉換。DWG→709 可能含 tone/gamut mapping；反解一條假設的 sRGB 曲線不足以保證撤銷整個顯示轉換。中性方向保留也不能獨立證明輸入校準正確。現有數值不需重算，但其用途以此限制為準。

官方來源：`/Applications/DaVinci Resolve/DaVinci Resolve Manual.pdf`，標題 DaVinci Resolve 21 Reference Manual；靜幀匯入／匯出另見第 3406–3407 頁。

## 結論

在 A/C 使用相同解碼與後續處理的前提下，這輪結果支持 **fp 原廠 normal ColorMatrix 已被 Resolve 實際使用**。差異呈现大致保留中性方向的固定矩陣特徵，不是單純曝光變化，也不是上一輪 B 的兩倍色度探測效果。

這是「原廠 metadata → Resolve 輸出反應」的正面驗證，尚不等於完整 DNG 算法一致、跨光源校準或絕對色準驗證。這次估計出的 A→C 矩陣只用於檢驗，不可拿來製作通用 LUT／IDT。

## 實際數值

- 有效畫面平均通道絕對差為 **336.11 / 65535**；99.83% 像素至少一個通道不同。
- A/C 的有效畫面均沒有任一通道等於 0 或 65535；本次輸出未見貼零／頂格。這不代表其他場景或上游階段絕不裁切。

sRGB transfer 假設下，估计矩陣對 `[1,1,1]` 的輸出約為 `[0.99906,1.00018,0.99947]`，特徵值約 `[1.69107,1.22308,0.99987]`。直接以儲存值擬合時，中性輸出也接近 1。這是「中性方向大致維持，色彩方向改變」的證據，不能將兩個較大特徵值簡化成全畫面的飽和度倍率，也不是對場景實際灰卡的測量。

另從 A/C 的 DNG 矩陣獨立推導：在「都使用 CM2 端點、Bradford 色適應及中性正規化」的示例模型下，預測特徵值為 `[1.69659,1.23130,1]`，與上述估計量級相近。這增加了原廠矩陣解讀的合理性，但不是逐值驗證：插值、色適應及 TIFF transfer 的假設均未被實際 Resolve 設定完整確認。推導及限制見 [矩陣檢验原理](/Users/dido/Developer.localized/SIGMAfp_re/research/imaging-hw/native-calibration-20260924/ac-matrix-invariants.md)。

## 為什麼還不能宣告完整正確

1. TIFF 沒有 ICC、TransferFunction、WhitePoint 或 PrimaryChromaticities；不能單憑它確認最終輸出色域／Gamma。sRGB 假設在平坦區域只是稍好，全部未裁切像素反而是直接儲存值模型較好，因此不能據此唯一認定輸出 Gamma，更不能反推 RAW gamma 被改動。
2. 改變 ColorMatrix 即使保留 AsShotNeutral，仍可能改變由矩陣推回的光源白點、色溫插值與色適應。不能拿 `inverse(CM_C) × CM_A` 的裸矩陣，直接要求最終 TIFF 數值完全一致。
3. 固定矩陣擬合是對這一張、有限色彩範圍的測試，不是覆蓋整個色域或兩個校準光源的校驗。
4. 原廠矩陣來源已確定；其對 OFF RAW 的完整物理適用性、原廠 profile 是否含顯色偏好及實際色準，仍是不同問題。

因此目前可把「Resolve 不讀 fp 的 ColorMatrix，所以 metadata 路線不可行」排除為這組測試的解釋。仍不能將本輪結果描述為已重現 Sigma 全部原廠色彩或已完成通用修復。

## 對工作流程的意義

保留 **原廠 CM＋該機身修正 → Resolve RAW 解碼 → 明確的工作色域／Gamma** 這條路徑。不要為了得到可見飽和度改標為 BMD Gen1，不要再對 C 疊加一次機身補償，也不把 Standard look 任意乘入輸入校準。

現有 TIFF 已足以確認此次輸出反應，不需為重複證明「有差」再匯出。P3 D60 → DWG、Input DRT=None → Rec.709 的流程已由使用者確認；若要逐值核對線性解碼，才需要更完整記錄個別控制及输出映射，並使用保留負值／超範圍值的浮點輸出。色卡不是驗證 metadata 計算行為的前提。
