# Resolve TIFF A/B 分析（2026-09-23）

## 輸入與可確定的內容

- `Timeline 1_01_00_02_04.tif`：較早的時間碼，依提供順序推測為 A。
- `Timeline 1_01_00_06_27.tif`：較晚的時間碼，依提供順序推測為 B。
- 兩張均為 2000×1334、未壓縮、RGB、每通道 16-bit unsigned integer TIFF。
- 未含 ICC、TransferFunction、WhitePoint 或 PrimaryChromaticities，無法單憑檔案確認 P3 D60／Linear。
- 有效畫面列取 `[104, 1230)`，其外為上下黑邊。
- 實際 RGB code values 全部為 64 的整數倍：16-bit 容器中的數值落在 10-bit 量化網格上。這指出輸出鏈有此量化，不能推論相機 RAW 只有 10-bit。

## 色彩反應

未做 transfer 假設的整體平均 RGB 絕對差約為 799.43 / 65535，與兩張 JPEG 的可見差異一致。

針對遠離零值與上限的像素，以空間交錯區塊分割擬合／保留驗證，估計較早影像到較晚影像的 3×3 轉換；詳見 `resolve-tiff-analysis.json`。另在較平坦且兩張每通道都介於 0.04–0.90 的區域抽樣，測試直接線性、sRGB 反解、純 2.2／2.4 次方四種假設。

平坦區域在 sRGB 反解假設下較符合固定矩陣：儲存數值的 MAE 約 41.57 / 65535（約 0.65 個目前的量化階），直接線性假設約 67.44 / 65535。sRGB 假設下的估計矩陣：

```text
later_linear ≈ T × earlier_linear

T = [ 1.77399690  -0.69831266  -0.07656114 ]
    [-0.21111154   1.27901428  -0.06735623 ]
    [-0.21324204  -0.71182158   1.92496551 ]
```

特徵值約為 `1.00020, 1.98339, 1.99439`，與測試矩陣「中性方向大致保留、兩個色度方向接近放大 2 倍」的設計一致。這是有條件的模型擬合，不能據此唯一確定 export transfer、色域或 Resolve 內部實作。原場景色彩範圍有限，且有縮放、量化和貼零區域，擬合仍有局限。

## 零值與量測邊界

較早影像在有效畫面中沒有任一通道為零；較晚影像的藍通道約 12.687% 為零，紅通道約 0.000444% 為零。兩張皆無通道達 65535。

B 的測試矩陣故意擴大色度，可能使部分線性 RGB 分量變成負值。這些 TIFF 的 unsigned integer 儲存不能保留負值；零值現象與這種限制相符，但檔案無法指出零值究竟在 RAW 解碼、後續處理或輸出轉檔的哪個階段產生。不能用此結果判定原相機缺陷或原 RAW 已裁切。

## 本輪結論

在使用者維持 A/B 其他設定相同的前提下，唯獨更動 ColorMatrix1/2 就得到符合預期方向與量級的輸出變化，支持 Resolve 目前的解碼流程實際使用這些矩陣資訊。

「矩陣修改能影響 Resolve」的實驗已取得正面結果。正式校準的準確度、兩端點是否分別生效、精確插值算法、負值與超範圍值保留仍未驗證。TIFF 已足以支援本輪測試；只有後續需要精確追查浮點範圍或完整線性矩陣時，才需要浮點輸出。
