# 原廠高格率路徑（>99 fps）與錄影載體格率（Ver.5.02）

2026-10-14。整理自 RES-Lab 的 240p 工作，這裡只留相機本身的事實。
詳細逐行查證：[HIGH_FPS_PATH.md](../../../projects/res-lab/validation/20261014-hirate-preview-research/HIGH_FPS_PATH.md)、
[PARITY_AUDIT.md §4](../../../projects/res-lab/validation/20261014-parity-audit/PARITY_AUDIT.md)。
標記：**[F]** 程式碼或實機證實；**[I]** 推論。

## 1. 「高格率」怎麼判定

- **[F] 通道格率** `chfps(ch)` 存在 `0xC31DF574 + ch*0x1B0`，由 FUN_c01d1630 從通道設定 cfg+0x10 寫入。
  cfg+0x10 來自錄影 profile 的 **PARAM 記錄 +0x30**（FUN_c0434ef8，經 MovSigProcess FUN_c0429910）。
- **[F] FUN_c01cec08(ch)** = `chfps(ch) > 99.0`（常數在 DAT_c01cef80）。這是全映像唯一的格率門檻；
  沒有找到 `==120`、`==100` 或依格率索引的表。
- **[F] 不看 mode id，也不看 profile id。** 只看 PARAM 記錄 +0x30。
- 兩條旗標：
  - **C31DDB70+ch**（FUN_c01c79a0）= FUN_c01cec08 且 FUN_c01d3558（cfg+0x84 = canvas +0x90）。
    成立時，S2R／R2V／R2Y／Y2Y 從「每幀等硬體事件」改成固定 `dly_tsk(8)` 輪詢；
    MANAGER 停車；DMA 改成連續／自動重載；每幀的幾何與 ISP 重新設定被跳過。
  - **描述子 +4 bit12**：FUN_c01caba0 依 FUN_c01cec08 設定，不看 +0x90。
    讀者有 FUN_c0189298（時脈閘門，§2）、FUN_c0179b38、FUN_c01cb9b8（+0x100 存 1 而不是 2）、FUN_c017e5e0。

## 2. 通道 0 時脈閘門 C0189440

- **[F] FUN_c0189298（Thumb）：** 一般模式依 `寬×2×高×fps×(位元+3)/10` 選 45/90/180/360 M 檔位與 N/16 工作週期。
  bit12（>99 fps）時直接固定：**ch0 = 0x1249（5/16）**、ch1 = 0xFFFF。
  結果寫到 FUN_c01cfe70 結構 +0xD0/+0xD4。最後由哪個硬體區塊使用，還沒查。
- **[F] 實機：** 把 C0189440 的 `movw ip,#0x1249`（0x2C49F241）改成 `#0xFFFF`（0x7CFFF64F）後，
  12-bit 239.76p SSD 從 14.7 s 增加到 36–40 s（A001_324 對 A001_328／329）。
  240p 和 120p 用同一個固定值，不會跟著格率加倍。
- 同一組 bit12 的其他讀者還沒改，影響未知：FUN_c01302f8（>99 時 VD IRQ 跳過 FUN_c019e270 的 1 秒看門狗）、
  FUN_c01cb9b8、FUN_c0179b38、FUN_c01d6980、FUN_c01c9e38（239.76 的顯示格率掉到 30.0）等。

## 3. 每幀仍然在跑、不受旗標影響的工作

- **[F]** 中斷處理（IRQ 0x3f、0x1c、0x1d、0x79、0x7a）每幀都跑，240p 時次數翻倍。
- **[F]** VDD 任務 FUN_c0130408 每個 VD 跑一輪。它的 2 ms 忙等條件是 C31DF60C = canvas +0xB8；
  原廠全部 306 個 profile 這一欄都是 0，所以錄影時不會忙等。
- **[F]** S2R 每輪仍然重建描述子（FUN_c01caba0，431 行），但被 8 ms 輪詢節流。

## 4. 錄影載體格率（選單 enum）的影響

「載體」指原廠選單上的格率 enum。實際感測器格率可以不同：例如 239.76p 掛在 119.88（enum 7）或 29.97（enum 3）上。

- **[F] 錄影時關掉一個 LV 顯示通道：** XC_RecMgrImpl v46 C0372278 → FUN_c03a1558。
  條件是 CinemaDNG、某設定值不是 0/3/4，而且 **enum 6–10（100 或 119.88）**。
  成立時呼叫 FUN_c0423e60 → FUN_c042a6d8 → FUN_c01d88a0；結束時由 v47 C0372298 → FUN_c03a1608 → FUN_c01d8928 恢復。
  enum ≤ 4（含 29.97）不會關。
- **[F]** 其他看 enum 的路徑都和吞吐量無關：時間碼（FUN_c037ff70、FUN_c01fed68）、DNG FrameRate 標籤（C00C9BD0）、
  音訊重設、MOV 位元率表 C0B9BA08。
- **[F] writer 批次（C03A5144）和 96 格描述子池（cmp #0x60，C03753CC 等）** 不看格率、mode 或 pid。
  RAW 池是 94 格：在途 94 張沒回收時就會以 `vbuf/94` 停止。
- **[F] 畫面上的錄影計時 = 幀數 ÷ 載體格率。** 239.76p 掛在 119.88 上顯示約 2 倍的時間，掛在 29.97 上約 8 倍
  （A001_328：9534 幀，WAV 39.8 s，畫面顯示 1 分多）。

## 5. 量測資料（SSD，12-bit 除非註明）

| 條件 | 結果 | 片段 |
|---|---|---|
| 239.76p，原廠時脈閘門 | 14.7 s 自停 | A001_324 |
| 239.76p，時脈全開 | 36–40 s 自停 | A001_328／329 |
| 239.76p，10-bit，原廠閘門 | 90.9 s，手動停 | A001_325 |
| shell 或 HDMI 開著 | 請求速率約 188–204 fps，很快停 | A001_320／322 |

所有片段的幀數除以 WAV 長度都約 239.5–239.8，感測器確實跑在 239.76。
