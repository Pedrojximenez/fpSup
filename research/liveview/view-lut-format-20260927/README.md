# fpScope Custom View LUT：可載入格式與安全切換／還原

> 2026-10-09 後續證據見 [統一 color sup](../../../projects/lut-sup/README.md)。
> 本文是早期研究，以下「tone 只作用在 Y」、C_SAT_C=`30117280`、MOV/JPG 必然跟隨、
> 大範圍替換 ROM 曲線的建議不再作為實作依據。原生 SIGSEQ 有一／三通道 tone dispatch；
> C_SAT_C 的正確 MMIO 是 `30117B00`；原生 effect 已確認同時改矩陣、CEQ/CEQ24 和 tone 指標。
> pixel 算式與 MOV/JPG 路由仍待驗。現行試驗採逐 mode 可復原設定，不以半庫錯誤曲線搜尋 active slot；
> 原生 tone RAM 有 owner，不能借作 LUT staging。完整 `.cube` 不會降成本文的單一曲線。

2026-09-27。領自路線圖 **fpScope → Custom View LUT（S2 55%）** 的下一里程碑
「建立可載入 LUT 格式與安全切換／還原」。前半（LUT RAM patch 的可見效果）已由使用者完成。

離線工作：格式由 Ver.5.02 ROM 量出,工具已對原廠曲線驗證。**沒有操作相機。**

## 格式（實測,非推測）

| | |
|---|---|
| 索引表 | `0xC0971118`,**88 筆 × 8 bytes** = `{uint32 ptr, uint32 id}` |
| ptr 間距 | **4096**（`0xC0971F34`、`0xC0972F34`、…） |
| 曲線庫 | `0xC0971F34`,88 × 4096 = `0x58000` bytes |
| 每條曲線 | **2048 點 × uint16 little-endian** |
| 定義域 | index 0..2047（11-bit 亮度輸入） |
| 值域 | **0..8191**（77 條上限 8190、11 條 8191) |
| 約束 | 非遞減（88 條全部成立） |

### ⚠ slot 與 id 差 1

索引表第 N 筆（**slot** N,0-based）的 `id` 欄位是 **N+1**。88 條全部如此。

**colour mode "Off" 用的是 slot 82 / id 83 @ `0xC09C3F34`**。
用錯編號就會改到隔壁那條,而且畫面照樣會變（同家族的鄰居),不容易發現。
本目錄的工具一律用 **slot**。

### 88 = 8 家族 × 11 對比階

`slot = family × 11 + (對比階 + 5)`。原廠各家族的硬切點**不一樣**:

| family | slot | 到頂 index | max | |
|---|---|---|---|---|
| 0–3 | 0–43 | 1919 | 8190 | |
| **4** | **44–54** | **2047** | **8191** | **完全不硬切** |
| 5 | 55–65 | 1919 | 8190 | |
| 6 | 66–76 | 1873 / 1875 | 8190 | |
| **7** | **77–87** | **1918** | 8190 | **Off 的家族** |

所以「原廠一律在 93.7% 硬切」是錯的 —— **family 4 那 11 條一路到 2047 才到頂,完全沒有壓平。**
這代表硬體本身不強制切,是曲線設計的選擇。

Off（slot 82）原廠:`min 0, max 8190, 到頂 index 1918` —— 最上面 6.3% 壓成同一個值,
這才是 OFF 監看看不到高光的直接原因。

> **⚠ 2026-09-28 更正。** 初版寫「值域 0..8190（不是 8191）」與「原廠 88 條全部在 index 1919 到頂」,
> 兩者都是從 **3 條樣本**過度推廣。掃完 88 條後:max 有 8190 和 8191 兩種、到頂 index 有
> 1873/1875/1918/1919/2047 五種。`fpcurve.py` 的上限檢查也跟著放寬（超過 8190 改為警告而非錯誤）。

## 工具

```
python3 fpcurve.py dump 1                    # 取出原廠曲線 → .bin + .csv
python3 fpcurve.py make --shape log -o v.bin # 產生 log 型監看曲線
python3 fpcurve.py from1d mycurve.cube -o v.bin
python3 fpcurve.py check v.bin               # 格式與約束驗證,不合格回傳 1
python3 fpcurve.py diff curve_id01.bin v.bin
```

`check` 會擋下:點數不對、超過 8190、有負值、非遞減被破壞。**寫進相機前一定要過這關。**

內建形狀：`identity` `linear` `gamma22` `log` `log-soft`,加 `--headroom` 保留頂端餘量。

`--shape log` 產出的曲線在 **index 2047 才到頂**（原廠是 1919）—— 高光那 6.3% 不再被壓平。

## 安全切換／還原協議

### 原則

1. **換指標,不要原地覆寫。** 索引表是 `{ptr, id}`;把某一項的 ptr 指向 RAM 緩衝區,
   還原就是把原本的 ptr 寫回去。比覆寫 ROM 安全一個數量級,而且可以熱抽換。
2. **永遠留著原始 4096 bytes。** 用 `dump` 先存檔,並記下 sha256。
3. **寫入後先回讀比對,再啟用。**
4. **保留一條 known-good**：ROM 的 id=1 原樣,任何時候可以退回去。

### 韌體指紋檢查（寫入前必做）

表的位址是版本相依的。寫之前先驗證那裡真的是索引表：

```
讀 0xC0971118 起 88×8 bytes，確認：
  · 88 筆的 ptr 嚴格遞增且間距都是 4096
  · 第一筆 ptr == 0xC0971F34
  · id 欄位是 1..88 的排列
三項有任一不符 → 拒絕寫入（韌體版本不同,位址要重新定位）
```

### 驗證階梯

一次只改一件事,每一階都要看到預期結果才進下一階：

| 階 | 寫什麼 | 預期 | 沒達到的意思 |
|---|---|---|---|
| 0 | 不寫,只回讀索引表 | 指紋三項全過 | 位址錯 / 版本不同 |
| 1 | 把原曲線**原樣**寫回 | 畫面**完全不變** | 寫入路徑有問題,先別往下 |
| 2 | 寫一條明顯錯的（例如反相） | 畫面明顯變 | 這條 id 不是當前生效的那條 → 見下節 |
| 3 | 寫回原曲線 | 畫面回復 | 還原路徑有問題 |
| 4 | 寫真正的 log 曲線 | 高光出現層次 | — |

### 當前生效的是哪一條 —— Off 已知

**colour mode Off、對比 0 = slot 82 @ `0xC09C3F34`**,由 [fpLog](#實例fplog) 實機確認。

其餘模式用 `slot = family × 11 + (對比階 + 5)` 推,但**哪個 family 對應哪個 colour mode 尚未建立**。
要定位其他模式,用二分法：

```
把 slot 0..43 全部換成明顯錯的曲線 → 畫面有變？
  有 → 目標在 0..43,再切一半
  沒有 → 在 44..87
```

約 7 輪。**每輪結束都要完整還原**,不要累積未還原的修改。
換模式或改對比會換到同家族的別條 —— 要全模式一致就得換掉整個 `0x58000` 區塊。

## 實例:fpLog

`~/Downloads/share/`（= `AutoRun-12.txt`,兩者逐位元組相同）是這個格式的第一個完整產品:
把 **ARRI Log C V3 EI 800** 寫進 slot 82。獨立驗證結果:

| 檢查 | 結果 |
|---|---|
| `mem set` 筆數 | 1024,位址 `0xC09C3F34`..`0xC09C4F30`,間距 4 → 恰好 4096 bytes |
| 寫入位址 vs 索引表 | 索引表[82] `ptr=0xC09C3F34` **相符** |
| 曲線約束 | 2048 點、非遞減、`min 760 / max 4730`,在 0..8191 內 ✓ |
| 取樣 | `0→760, 256→2954, 1024→4129, 1918→4673, 2047→4730` |

它用 `mem set` 一次一個 32-bit 字寫滿整條,RAM-only,拔電池即復原。
**寫到一半的表會讓高光帶色邊** —— 所以它在螢幕上放計數器,並在卡上留 `LOGC82.BIN` 當完成證明。
這正是本筆記「驗證階梯」第 1–3 階要防的失敗模式,它們用產品化的方式解決了。

注意 fpLog 文件裡的「curve #82」是 **slot**,不是 id。

### 三個已知的坑

1. **不確定 ISP 何時讀曲線。** 筆記記著「串曲線進 ISP 的函式未定位」—— 可能是模式切換時 DMA 一次,
   也可能持續讀。熱抽換後若沒反應,先試切換一次模式再看。
2. **tone 在 ISP 裡,不只影響螢幕。** JPEG 和 H.264 會跟著變;CinemaDNG 不受影響（RAW 不經過 tone）。
   要做純監看 LUT 而不動成品,得改用顯示端那條路（3×3 + 16 點 gamma,見
   [isp-colour-blocks-20260927](../../imaging-hw/isp-colour-blocks-20260927/README.md)）。
3. **曲線只作用在 Y。** tone 在 YCbCr 之後,CbCr 不會跟著縮。把 Y 大幅拉平（log 化）會讓畫面
   看起來過飽和,需要用 `C_SAT_C`（`0x30117280`）配套調整。

## 界線

- 沒有操作相機。格式與約束是從 ROM 量出的,**切換機制與 ISP 重載時機都未實測**。
- 位址為 Ver.5.02；其他版本必須先跑指紋檢查重新定位。
- 「原廠 93.7% 硬切就是高光看不到的原因」是**必要條件不是充分條件**：
  [upstream-clip-audit.md](../upstream-clip-audit.md) 的結論仍然是「不能證明或排除 tone 之前已發生
  pixel clipping」。**換曲線之前先驗證來源**,否則拉直了也救不回來。
- `--shape log` 是形狀示範,不是校準過的監看曲線;真正要用應該從目標顯示轉換反推。
