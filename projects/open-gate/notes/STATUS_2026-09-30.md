### CSV 的兩條硬規則(都是踩到才知道的)

```
① 結尾 CRLF 不能省      少了它最後一列不會被 parse
② 欄位要**整欄拿掉**     留空(`,,`)那一列畫不出來,要連表頭一起移除
```

### 界線在哪

```
彈出清單的那幾列          ✅ 純資料
游標範圍 / 列舉值對應      ✅ 純資料
──────────────────────────────────
選中之後那個值的呈現       ❌ 要 R2(收合摘要 / QS 圖磚 / 底列)
```

選了新的一列之後收合摘要會空白 —— 那一半是 OG3K 那 2538 words 花錢的地方。

## 2. 收回的結論(五個)

寫在前面,因為它們曾經被當成前提用過。

| 收回的 | 真相 |
|---|---|
| 「畫一列要 NBU」 | **錯**。是我們的 CSV 形式寫錯兩處。兩個失敗的實驗疊起來看起來像強結論 |
| 「CRCT 對 CDNG 是惰性的」 | **測錯組合**。bin + RWZM unity 落在選擇器的分支 B,mux = Crmf,binning 抽頭根本沒被選 |
| 「hbin/vbin 與 RWZM 只能擇一」 | **反的**。要選到 Hbin2 抽頭**必須**兩個一起用(分支 C/F) |
| 「USB 線壞了、失敗率 1.7%」 | **量測方法錯**。讀隨機位址把本來就不可讀的當成掉包;用已知可讀位址重測 210 次,0 失敗 |
| 「字串 0308 不會解析」 | **看錯表**。TEXT 走 `.nloc`(key = fnv1a),`0308 = 14 bit` 十七國語言都有 |

共同的教訓,寫進 §8.9:**先做一個只動一個變因的實驗,再談結論。**
解開整條的是 `WHY_NOTHING_CHANGED.md` 建議的探針 —— 改既有一列的文字,
那是第一個**只需要單一機制**就能觀察到的實驗。

## 3. 解開的機制

### CRCT 的啟用條件是路徑分支(§6.2)

`FUN_c0325228` 依 (錄影 RWZM, 預覽 RWZM) 分六支:

```
B  錄=預覽且 unity     mux = 1 Crmf      ← 我們那次失敗的實驗在這裡
C  錄=預覽、非 unity    mux = 4 Hbin2     ← 主管線吃**錄影的** bin 與 RWZM
E  錄≠預覽、預覽 unity  a7 沒啟用          ← 原廠 UHD,bin 取自**預覽**欄
```

原廠 306 列分布 B:172 C:36 D:81 **E:17**,而那 17 列正是「預覽 x3/x3」那批。
**原廠有串,但串在預覽側;錄影欄 306/306 全是 x1。**

我們的畫布本來就把 preview/record 的 RWZM 寫成同值、bin 也兩欄都寫,
所以**只要 `rwzm != unity` 且 `bin != 1` 就自動落在 C**。引擎的正向公式
`out = (in/bin)*1024/rwzm` 本來就是串接的 —— **主機側一個字都不用改**。

⚠ `hbin = 5` 的五抽頭係數兩筆 reduction record 裡都沒有,x5 先別用。

### 選單的地圖(§8.4 / §8.5)

```
B2_5_1 檔案格式  2 列        B2_5_2 位元深度 3 列  配對表 4 筆 ← 多一個備用
B2_5_3 壓縮      2 列(CDNG 下隱藏)
B2_5_4 解析度    2 列        配對表 3 筆 ← 多一個(OG3K 用掉了)
B2_5_5 格率      9 列        配對表 9 筆 ← 零預留,所以要搬表
```

**QS 完全不用另外做**:格率那項與選單共用同一個轉換器(整個映像裡只有
一處拼出那張表的位址),而 QS 根本沒有位元深度項。

### NBU 索引可以改指向,但只在開機時(§8.8)

```
索引表 0xC18EB49C   221 列 x 0x20 BE   +0x0C = 集合位移(基底 0xC18C0460)
B2_5   0xC18ECA9C   hash 0xD570BB11 = fnv1a(b"B2_5")   ★ 寫入點 0xC18ECAA8
```

執行期改無效(連換語言重建整個 UI 都撐得過去)。**但卡片 loader 在 UI 初始化
之前寫入,那個時機沒被否定** —— fpSup-Formats 就是那樣出貨的。
