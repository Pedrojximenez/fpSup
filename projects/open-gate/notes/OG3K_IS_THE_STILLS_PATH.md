# 韌體本來就有 3K:那是 S 尺寸 12-bit 靜態照片的路徑

2026-09-13。回答「流程中有沒有已經存在的隱藏 3K 流程或資料可以選用」。

## 有,而且全部在拍照側

```
0xC0BE5CF0[3]  {1, 43, 98,  →"12BLOW"}
0xC0BE5D70[3]  {1, 83, 143, →"12BLOW"}
```

那兩張表是**拍照**的表(鍵是 `LOW` / `12B` / `12BLOW` / `CROP` / `LOWCROP` /
`12BCROP` / `12BLOWCROP` —— 位元深度與裁切的組合,tag = 1 而非 movie picker 的 5)。

所以 **profile 43 是「12-bit + 低解析度」的拍照 profile**,也就是 fp 的
**S 尺寸靜態照片**:

| | |
|---|---|
| RAW 幾何 | 3032x2012 |
| 裁切 | 3008x2000 @ (12, 6) |
| 感測器視窗 | 3032x2012 |
| 感測器模式 | 98(p43)/ 143(p83) |
| 預覽 | 柵格 2024x1341、可見 2000x1334 |
| `+0x1C` | 2 = 3:2 標記 |
| `+0x30` 畫格率 | −1.0(照片沒有畫格率) |
| RAW RWZM `+0x64/+0xD4` | 0x3FF = unity |

**這解釋了為什麼一換上 p43 錄影就乾淨**:它不是我們硬湊的,是韌體自己的
3:2 全高擷取路徑,只是原本服務照片。

## movie 側完全沒有 3K

- picker 三張表(0xC0BE5810/59B0/5B50,各 26 筆):沒有
- 回放名稱表(0xC0BE4508 三組各 4 筆,UHD/FHD/UHDCROP/FHDCROP):沒有
- CINE 選單表(0xC0B51044,14 列):只有 4096x2160、3840x2160、1920x1080
- profile 表 306 列中,只有 43 與 83 帶 3032x2012

3032x2012 的感測器模式有四個:**98、11、117、143**。

## 一個因此發現的風險

**我們在寫 p43 的 `+0x030`**(畫格率 −1.0 → 30.0 等),而 p43 是 S 尺寸
12-bit 照片實際在用的 profile。寫死會影響拍照。

已改成跟著選單旗標還原(和那六個預覽 profile 同一個機制):
未選 OG3K 時一律寫回 −1.0,選中時由 `fmttable` 在 picker 命中時寫入該格率。

## 設計原則(使用者的要求)

> 儘量依照 fp 原有的設計去增加功能,儘量不動原本的東西。

依這個標準檢查整套,**我原本違反得很徹底**:

| 原本的做法 | 問題 |
|---|---|
| 改 `0xC0BCFE80/84` | 挪用 720p 這個真實格式的比對對 |
| 改 `0xC0437C34/38` | 把 `"HD"` 的字串指標改指向 `"OG3K"` |
| 改 `0xC0BE44DC` | 換掉函式指標表的一格 |
| 改回放名稱表的 `FHDCROP` 槽 | 挪用仍在服役的格式槽 → **畫面直接黑掉** |

正確的模式是 **hook 只新增一個 case,其餘原封不動往下走** ——
`fmttable` 一直是這樣做的(只認自己的鍵,其他 `pass`),所以錄影那條線乾淨。

`og3kname` 已改為 v2:自己呼叫原函式在用的輸出函式 `FUN_c01f578c`,
所以前三項全部不需要 —— 四個原廠位置加一個 vtable 槽,換成一個 hook。

回放名稱表那一項已完全退回(`WITH_PLAYBACK = False`)。失敗原因寫在下面。

## 回放:為什麼挪用名稱表會黑畫面

回放 profile 的特徵是 `+0x30 == −1.0f`,共 18 個:

```
51/61/71      3856x2170 / 3840x2160   UHD        raw[0,0]
53/63/73      1936x1090 / 1920x1080   FHD        raw[0,0]
371/381/391   3856x2170               UHDCROP    raw[0,0]
373/383/393   1936x1090               FHDCROP    raw[0,0]
41..46, 43    3032x2012 等             (照片)     raw 有值
```

**回放 profile 全部是 `raw[0,0]` 的純預覽 profile。** 我只看 `+0x30 == −1`
就把名稱表槽指向 p43,而 p43 有完整的 RAW 半部 —— 配置器拿它做回放時多了
一整套不預期的欄位,顯示鏈崩掉。

那一欄就印在我自己貼的表裡,我看到了卻沒解讀。

要依設計加回放,需要一個**純預覽的 3:2 profile**,而現成的回放 profile
沒有 3:2 的(全是 `+1C = 1` 的 16:9)。profile 列是「每欄一個陣列」,
無法新增列。所以正確的擴充點還沒找到 —— 在找到之前不再動相機。
