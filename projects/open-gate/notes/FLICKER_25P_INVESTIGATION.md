## 2. 他的檔案量到什麼 [C]

`R001_371`,52 幀:

```
ImageWidth 3856 x 2170      DefaultCropSize 3840 x 2160
FrameRate  25000/1000 = 25.000
ExposureTime  1/60          ← 25p 的 180° 應該是 1/50
ISO 100
```

**1/60 在 25p 下恰好是 150°,不是 180°:**

```
角度 = 曝光 ÷ 幀期 × 360 = (1/60) ÷ (1/25) × 360 = 150.0°
```

### 2a. 物理上這完全決定閃或不閃 [C]

50 Hz 市電 → 光以 100 Hz 脈動 → 週期 10 ms。
列亮度的調變深度 ∝ `|sinc(T / 10ms)|`:

```
1/50 = 20.000 ms = 2.000 個週期  →  |sinc| = 0.0000%   完全沒有帶狀
1/60 = 16.667 ms = 1.667 個週期  →  |sinc| = 16.5%     明顯帶狀
```

**不是「差一點」——正確值給出的是數學上的零。** 所以只要曝光是 1/50 就不可能閃,
是 1/60 就一定閃。這也解釋了為什麼他切到快門速度模式(自己設 1/50)就乾淨。

亮度差只有 **0.26 檔**,符合他說的「不暗」。

### 2b. 逐幀量測佐證 [C]

52 幀整幀平均亮度峰對峰 **0.003 檔** —— 沒有全域明暗脈動,
與「帶狀而非閃爍」一致,也與 1/60 的預期一致。

## 4. ★ 方法論:`menu SetShutterSpeed` 不反映角度算出來的曝光 [C]

USB shell 的 `menu SetShutterSpeed` 讀到的是**快門速度模式的儲存值**,
與角度模式實際使用的曝光**無關**。上面那三段錄製期間它一直讀 `1/60`,
而錄出來的檔案是 `1/50`。

**所以唯一可靠的量測是錄一段、讀 DNG 的 `ExposureTime`。**
我前面用它做的所有讀數(各幀率、各曝光模式)全部無效,已作廢。

## 8. 附帶發現:OG3K + Super35 錄影失敗(與本案無關)[C]

追這件事時實機重現的**另一個真缺陷**:

```
OG3K + crop 0（全片幅）    → A001_164  3024x2010  25.000  1/50   ✔
OG3K + crop 1（APS-C）     → 按下錄影,完全不產生 clip           ✘
```

原因:`FUN_c043b828` 組鍵時會接 `"CROP"`

```c
if (*(char *)(p + 0x17)) strcat(key, "CROP");
```

鍵變成 `OG3K25CROP`。我們的格式表只有八個無 CROP 的鍵,原廠表也沒有 OG3K,
兩邊都查不到 → NULL → 退回 `T3[0]` → 組態與其他 hook 不一致 → 錄影失敗。

**這從 v0.1 就存在**,不是 v0.2.x 引入的 —— 只是沒人測過這個組合。
原廠 UHD/FHD 都有 CROP 變體(`UHD25CROP`、`FHD30CROP`…)所以沒事。

修法三選一(見 `OG2K_PLAN.md` 的討論):

1. 加八個 `OG3K<rate>CROP` 指向同樣的 entry —— **表格空間不夠**
   (`TABLE+0x1E0` = 480 bytes,八筆已用 384,加倍要 768)
2. **選了 OG3K 就把 crop 鎖成 0** —— 語意正確(open gate 與裁切互斥)、
   成本最小、不需要新空間。**建議做這個**
3. 用 `mode 131`(1984x1320,3:2 APS-C)做真正的 Super35 —— 那是新功能,
   詳見 `research/imx410/notes/SENSOR_MODE_METADATA.md` §7

## 9. 測試框架 `build/fpcam.py`(2026-09-15)

這一天連續測錯五次之後寫的。它強制五件事:

```
1. 唯一可信的量測是錄下來的 DNG        —— 不再用 menu 讀數當代理指標
2. 每次錄影必須證明產生了新的 clip      —— 否則丟例外,不會拿到上一段的紀錄
3. 設定用 apply() 設定並讀回驗證        —— 讀不回同一個值就是錯誤,不是警告
4. session 開頭抓基線、結尾還原          —— 中途所有改動都寫進 JSON log
5. DNG 逐 IFD 解析,主影像 = 面積最大者 —— 不再被縮圖 IFD 的 8-bit 蓋掉
```

第一次使用就抓到一個原本會被誤判的狀況:
`SetMovCinemaDNGQuality 設成 0 但讀回 4` —— UHD 在該幀率下不接受 12-bit。
舊做法會照樣錄下去、拿到 8-bit 的檔案,然後把它當成 12-bit 的結果去推論。

用法:

```python
from fpcam import Camera, run
TESTS=[dict(name='OG2K 12-bit',
            set=dict(MovRecSize=4, MovCinemaDNGQuality=0),
            expect=dict(ImageWidth=2016, ImageLength=1344,
                        DefaultCropSize=(2000,1334), BitsPerSample=12))]
run(Camera(log='/tmp/t.json'), TESTS)
```

`Camera.resident()` 會比對卡上 VSHL 的 sha256 與 build 目錄,直接印出
「現在跑的是哪一版」—— 對著不知道版本的機器下結論也是那五次錯誤之一。
