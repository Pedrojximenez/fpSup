## 2. 規則

**幾何** — 感測器形狀 = 交付比例 ÷ 變形倍率，在片幅框裡取最大內接矩形（寬比例受寬限制、高比例受高限制，
即電影慣例）。「填滿」取代 Open Gate。每個組合都一定有解：一般衝突照「優先」退讓；只有物理上不可能才反灰。

**分工**

| 層 | 負責 |
|---|---|
| 感測器窗口 | 垂直裁切（改善捲簾）；水平只有固定寬度 6064 / 4160（`0001`） |
| SoC 接收端 | 比 4160 更細的水平裁切（不改善捲簾）；窗口必須與感測器送出的行數一致，否則一格都完成不了 |
| 感測器 bin/skip | 整數倍縮小；1×2、1×3 純垂直縮減已在 fp 實測可行 |
| RWZM | 任意比例縮放、變形還原、超取樣 |
| 記錄矩陣 | 只修對齊用的幾個像素（寬度 16 的倍數） |

**捲簾** ≈ HMAX × 涵蓋行數 ÷ 垂直縮減 ÷ 72 MHz。HMAX：14-bit 911、12-bit 445–450、11-bit 全寬 400、
11-bit ≤4160 寬 335（約 96 fps）。水平裁切本身不改善捲簾，唯一例外是窄到 4160 以下才能用快速 ADC。

**優先** — 畫質：1×1、12/14-bit ADC，再 RWZM 縮小。RS：垂直縮減、矮窗口、11-bit 快速 ADC。

**FPS** — fps = 72 MHz /(HMAX × VMAX)。⚠ SoC VMAX（`0x30100020`）只有 14 位元，寫 >16384 會卡死 shell；
只調 VMAX 的下限約 13.3 / 9.9 / 4.8 fps（HMAX 330 / 445 / 911），更低要另找方法。生成器必須夾住 VMAX。

**垂直縮減** 會把 OB 列從 40 減到 5，要加 `0018 = N` 補暗列，否則 CRCT 鉗位會吃掉影像列。

## 3. HDR

| 種類 | 狀態（imx410-lab） | 限制 |
|---|---|---|
| 空域 | 已實測：`0242=01` + `0738=V`，2×2 格棋盤 | 只能 1×1；ISO ≥ 800 才有淨收益（3200 約 +1.7 檔）；裁掉頂端 V 列；快門 ≥ V 行。UI 措辭建議「高 ISO 高光回復」，強度 1–3 = V 0x20/0x40/0x80 |
| 時域交替曝光 | 已實測 | 內部格率加倍、資料率加倍、快門上限減半；移動物有鬼影 |
| 時域交替轉換增益 | 可行 | 只改善暗部 |
| 電腦端合成工具 | `hdr_ml.py` 已可用 | 沒有它 HDR 素材無法使用 |

## 4. profile / DMA / 畫布（本專案核心）

已知（見 `IMX410_FULL_DESIGN.md` §11、§12.20–21、res-lab RESCUSTOM_STATUS）：
- 畫布：`+0xF4/F8` = 實際讀出；>60 fps 必寫 `+0x90 +0xB0 +0xC0 +0xDC +0xE4 +0xFC +0x100`；
  目標是任何配置都落在「vbuf 乾淨停止」路徑，不凍結。
- profile：donor 選錯（p13 空殼）是四次凍結的根因；預設逐欄等於已驗證組態，只有需要的軸才偏離。
- DMA：原廠 DMA 表頭 + 64 MiB 批次；>99 fps 時脈閘門家族（C0189440 已知，其他未處理）；RAW 池 94 格。

做法：離線把原廠全部 profile / 畫布 / DMA 抽成矩陣 → 每欄歸類（幾何決定 / 格率級別決定 / 全同 / 規律不明）
→ 生成器輸入原廠參數須逐欄重現（先做 mode 12）→ 之後一次只偏離一個變因上機。

## 5. 守則

- 設定區只存原廠合法值（格率存載體格率；自訂 FPS、14-bit、HDR 只放記憶體或卡上自己的檔案）。
- 程式與資料向分配器要記憶體，不碰 cave 位址。
- 上機前先說明會做什麼、會不會寫設定區，等使用者同意。
