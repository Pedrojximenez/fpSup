# 事故:改 live view 毀掉數十段錄影素材

2026-09-12。3000×2000 open gate 專案。

## 發生什麼

為了修「錄影時 live view 右邊有空隙」,我在 `rowpatch_og3k.S`(掛在
`C043A19C` 的 canvas hook)裡加了預覽相關的寫入,其中一項是把

```
+0xD8 / +0xE0   3032 / 2012   →   0 / 0
```

依據是對方交接包寫著「preview width from PARAM+0C, **overridden by nonzero
+D8**」—— 我讀成「+D8/+E0 是預覽柵格的覆寫,設 0 表示不覆寫」。

**那是錯的。** 而且 `rowpatch_og3k.S` 自己的註解就寫著 `+0xD8` 是
**producer-side width/height pair**。關掉它之後,producer 改去讀
`+0x0C/+0x10` —— 我把那裡設成了預覽的 `2024x1341`。

## 損害

| 片段 | 症狀 |
|---|---|
| A001_001..014 | 正常(動手之前) |
| A001_015 起 | 只有左上約 1936 寬的區域有畫面,其餘是未初始化記憶體 |
| A001_047 起 | 連 strip 都縮成 3032x1341,檔案 6,179,328 B 而非 9,229,824 B |

中間有幾段正常(027、029、032、039),對應我來回改組態、而 canvas 尚未
因模式切換重建的時刻。

素材無法救 —— 那些像素從來沒有被寫出來過。

## 為什麼沒有及早發現

1. **只看 live view 不看檔案。** 每一輪我都問「畫面對不對」,沒有要求錄一段
   然後檢查 DNG。標頭一直是正確的 3032x2012,肉眼看 live view 也「修好了」。
2. **信了別人的文件勝過自己的註解。** 兩者衝突時我採用了外部說法,而本地
   註解是這台機器上驗證過的。
3. **在錄影路徑上做顯示層的實驗。** canvas 同時決定 RAW 幾何與預覽,我把它
   當成可以隨便試的地方。

## 規則

- **canvas(`C043A19C`)只放錄影幾何。** 預覽要改就改 profile 表或顯示層
  hook,不要碰 canvas。
- **改完錄影路徑必須錄一段並解 DNG 檢查**,不是看 live view。檢查項目:
  檔案大小、strip 長度、以及「右側 1936 以外的區域相鄰行是否仍相關」。
- `og3k_plan.py` 的 `check()` 現在會擋:rowpatch 的十個 PUT 必須完全等於
  A001_001..014 驗證過的那組,多一個都不給建置。
