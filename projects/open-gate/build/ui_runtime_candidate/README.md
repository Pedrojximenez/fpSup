# OG3K native UI runtime candidate

This package is coupled OpenGate test material, not a product release.  It adds the OG3K Settings summary, both Quick Set resolution animation families, and the UHD/FHD/OG3K footer using a private NBR pack.  It does not modify stock icons or the HUD Resolution family.

The parser-copy mechanism was camera-proven in archived FP3K v0.3.2 on the same firmware, but that proves only the timing of that package.  Because the current AutoRun is slower, this build records one persistent hit bit for every selected NBU record; a ready private pack alone is not evidence that an already-parsed screen was repaired.  A full cold-boot camera run has now validated the current CINE Settings summary/list, both Quick Set OG3K values, and the three-choice footer.  A follow-up run exercised one FHD transition plus three one-second UHD and three one-second OG3K recording transitions without a freeze, then revalidated the OG3K Quick Set assets.  This does not validate sustained media writing: an earlier OG3K attempt froze and this SD card is too slow for a long UHD/OG3K run.  See `camera_postboot/MANIFEST.md` and `camera_freeze_20260914/MANIFEST.md`.  Inactive screen/style variants, playback, and faster-media duration regressions remain untested.  Do not run size_ctl, cfgring, cfgsnap, appendobs, elemobs, xcitrace, the 0xC0733400 log family, zoomlog, og3ktile, or livepatch while it is resident: those diagnostics overlap its state/code ranges.  The firmware's built-in `gui image log` and `display capture` are safe.

A fresh 0xC0732700..0xC0732748 dump can be decoded locally with `python3 ../decode_og3k_ui_state.py STATE.BIN --summary`. Acquiring that camera dump is a separate memory read and requires explicit per-read consent.

Any fresh installation still requires proving the runtime stability of 0xC0793060..0xC0793EF4, followed by a real battery-out cold boot.  Measure only the second QS draw because the first can contain the previous frame's assets.
