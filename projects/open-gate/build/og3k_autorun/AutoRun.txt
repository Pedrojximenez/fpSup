# ============================================================================
# USB shell.
#
# The camera keeps its own PTP gadget exactly as the firmware builds it, so the
# firmware owns the descriptors, creates and enables the endpoints, and
# re-creates them after a record-mode reconfiguration. Only the interface-class
# word needed by the command shell is changed in this minimal test build.
# The optional EP 0x83 streaming patches are intentionally absent.
#
#   EP 0x01 OUT  commands      EP 0x82 IN  replies      EP 0x83 stock / unused
#
# The worker understands one command: `shl <line>`, which runs <line> in the
# firmware's own shell and returns what it printed.  `mem set` and `mem save`
# come along for free, so the worker needs no memory commands of its own.
#
# Boot with the USB cable UNPLUGGED, then attach it.  The gadget is built on
# attach, so the patches have to land first; and the patched words sit in code
# that has not run yet, so no stale instruction-cache line can shadow them.
#
# The screen reads fpSup[........]0 through fpSup[########]100 while this runs
# and OG3K! when it is done.  A bar that stops means the load stopped there.
# ============================================================================

# --- OG3K: 3032x2012 open gate, every CinemaDNG rate up to 59.94 -----
# Sigma fp firmware Ver.5.02 ONLY; no runtime version guard.
# Cold-boot RAM patches only.  Remove AutoRun.txt and power-cycle to undo.
#
# The seven modes the FHD rates already use are turned into 2012-row
# modes.  Their sensor register records differ from mode 98 in only the
# mode id and the minimum-blanking field, so they are already the same
# 2x reduction and the same quiet analog profile; only the row window
# and the geometry height said 1708.  Timing is untouched, so every
# rate stays exactly what SIGMA ships.
#
#   23.976 -> mode 109      48 -> mode 220      59.94 -> mode 27
#   24     -> mode 218      50 -> mode 115
#   25     -> mode 125   29.97 -> mode 106
#
# 100 fps and 119.88 are NOT patched: 2012 rows at hmax 445 need
# 12.44 ms and the fastest 3032x2012 readout is 9.22 ms, so 119.88
# (8.34 ms a frame) is impossible and 100 needs mode 117 instead.
