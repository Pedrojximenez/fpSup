# OG3K native UI runtime candidate

This package is coupled OpenGate test material, not a product release.  It adds the OG3K Settings summary, both Quick Set resolution animation families, and the UHD/FHD/OG3K footer using a private NBR pack.  It does not modify stock icons or the HUD Resolution family.

The parser-copy mechanism was camera-proven in archived FP3K v0.3.2 on the same firmware, but that proves only the timing of that package.  Because the current AutoRun is slower, this build records one persistent hit bit for every selected NBU record; a ready private pack alone is not evidence that an already-parsed screen was repaired.  A full cold-boot camera run validated the unchanged native CINE Settings summary/list, both Quick Set OG3K values, and the three-choice footer in v0.2.0test.  That predecessor also exercised one FHD transition plus three one-second UHD and three one-second OG3K recording transitions without a freeze, then revalidated the OG3K Quick Set assets.  Separately, the previous single-callsite shutter-angle fix failed a confirmed real-mode idle-live-view comparison: FHD reported 16663 us while OG3K reported 6411 us with gain unchanged.  The revised fix now covers all four local angle conversion, metadata, and resolution-sync BL callsites through one narrow wrapper.  It still requires a battery-out cold-boot camera A/B and must not be treated as passed.  Stage2 places every section before cleaning/invalidating D-cache and then invalidating the whole I-cache, so armed branches cannot retain the old instruction stream. A CINE/STILL transition while OG3K remains selected is also hardware-pending; select FHD or UHD before leaving CINE until that transition is tested. Warm restart and hot reinstall are neither tested nor supported; use only a battery-out cold boot baseline.  The historical 2026-09-14 A001_082 freeze remains unexplained and is not the user-corrected freeze from this work.  Separately, current SD throughput is inadequate for sustained UHD/OG3K validation.  See the historical sibling evidence at `../ui_runtime_candidate/camera_postboot/MANIFEST.md` and `../ui_runtime_candidate/camera_freeze_20260914/MANIFEST.md`.  Inactive screen/style variants, playback, and faster-media duration regressions remain untested.  Do not run size_ctl, cfgring, cfgsnap, appendobs, elemobs, xcitrace, the 0xC0733400 log family, zoomlog, og3ktile, or livepatch while it is resident: those diagnostics overlap its state/code ranges.  The firmware's built-in `gui image log` and `display capture` are safe.

A fresh 0xC0732700..0xC0732748 dump can be decoded locally with `python3 ../decode_og3k_ui_state.py STATE.BIN --summary`. Acquiring that camera dump is a separate memory read and requires explicit per-read consent.

Any fresh installation still requires proving the runtime stability of 0xC0793060..0xC0793EF4, followed by a real battery-out cold boot.  Measure only the second QS draw because the first can contain the previous frame's assets.
