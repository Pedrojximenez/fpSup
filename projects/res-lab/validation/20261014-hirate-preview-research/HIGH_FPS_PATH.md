## 1. 每幀管線：任務與觸發源

任務建立於 FUN_c012bfa8（L27925–28140），名稱字串在 C07D2204 起：**[碼]**

| S2R（ch0/ch1） | FUN_c01c2c78（L110985）/ FUN_c01c3430（L111345） | MNGP1 / MNGP1_2 | `wai_flg(c98, 4/0x4000/0x3000000)`；c98 bit 由感測器介面 IRQ 0x1c FUN_c012fe10 設（L32051–） |

中斷登錄：FUN_c012ee18（L31237）：0x3f→c012fa08、0x1c→c012fe10、0x1d→c0130058、0x7a→c01302f8、0x62→c0130538；FUN_c0125448：0x79→c0125478。
**FUN_c0183308 = 「等下一個 VD」**（等 ca0 中目前輪到的位元，該位元由 IRQ 0x7a 經 FUN_c0183350 設，VDD 任務旋轉）。**[碼]**

幀描述子：每個 0x520 byte，10 格環（狀態陣列 C31DDB38）。+0x51c / +0x51d = 0 表示「(重新)開始後第一幀＝設定幀」，=1 表示「連續中的穩態幀」（FUN_c01c9c48 L116178；各任務 bVar1 時清 0）。**[碼]**
→ 下表的「穩態」指 0x51c/0x51d=1，也就是錄影/預覽持續中的每一幀。

結論：一般模式下，S2R/R2V/R2Y/Y2Y 每輪都**阻塞等一個每幀硬體事件**（感測器幀結束、引擎完成、VD），所以是「每感測器幀一輪」。**[碼]**

## 2. 旗標 C31DDB70+ch（FUN_c01c79a0）在穩態幀造成的差異

旗標只在 S2R 的設定幀重算（FUN_c01c7968，L111038 / L111388）。**[碼]**

### 2.1 核心機制：把「等每幀事件」換成固定 `dly_tsk(8)` **[碼]**

| 位置 | 一般穩態 | 高格率穩態 |
|---|---|---|
| S2R L111098–111138 | `wai_flg(c98, 4…)` 等感測器幀結束；另有 FUN_c0126010 次數迴圈 `FUN_c01258a8; dly(2)` | `dly_tsk(8)`（L111137） |
| S2R ch1 L111429–111434 | `wai_flg(c98,0x4000)` | `dly_tsk(8)` |
| R2V L111700–111716 | wai_sem bf8/bb4（引擎完成）＋FUN_c0184c80＋FUN_c0184e90；或 `wai_flg(c98,0x10010/0x10040)`＋FUN_c0183308 | 整段跳過，`dly_tsk(8)`（L111716） |
| R2YHDIS L112111–112126 | wai_sem bf8/bb4…＋FUN_c01c7da0 | `dly_tsk(8)`（L112126） |
| Y2YVDIS L112498–112513 | wai_sem bfc/bb8＋FUN_c0184c80＋FUN_c0183308；再 `wai_sem(b98,500)` | `dly_tsk(8)`（L112500），b98 也不等 |

8 ms ≈ 120 fps 的幀時間（8.33 ms）。**[推]** 穩態下這四個任務變成「約 8 ms 一輪的計時輪詢」（≤125 Hz），**與感測器格率脫鉤**。所以 239.76p 時軟體這幾條迴圈的次數和 119.88p 幾乎一樣，不會翻倍；硬體則自己每幀跑（見 2.3）。

### 2.3 硬體被設成自己跑（「移到硬體」）**[碼＋推]**

- **MANAGER 停車**：`旗標==1 && 上一個描述子 +0x51c==1` → `wai_sem(b9c, forever)`（L110842–110845）。b9c 只有停止流程 FUN_c01ca138 / FUN_c01ca5a0 會 sig（L116511、L116592）；S2R 設定幀只做 tmo=0 的清除（L111042–111044）。**[碼]** → 進入連續狀態後 MANAGER 不再每 VD 產生新描述子，也不跑 FUN_c01c9d28 等每幀計算。**[推]**（判讀依暫存器重用的反編譯，中信心）
- **引擎程式化時的高格率分支**：旗標經 FUN_c01cc868（L118938–118940，寫 C31DF084 = R2V 設定結構 C31DEEE4+0x1A0）與 FUN_c01cdbe0（L119237–119239，寫 C31DED5D = R2Y 結構 C31DECCC+0x91）帶進引擎設定。讀它的地方：
  - FUN_c0171ab0 L61640（R2V）與 FUN_c0175dd8 L63421（R2Y）：旗標=1 時，每個啟用的輸出 DMA 通道在 **0x30220030（6 通道 ×2 bit）/0x30230010（4 通道 ×2 bit）寫 0b11**，並設一組極大的界限值（0x79fffffe/0x6dfffffe/0x71fffffe/0x75fffffe）＋1FF8，「單次啟動」欄位 local_166/local_18a 清 0、local_144/local_168 設 1；一般模式改走單次啟動與 FUN_c0185248 的雙緩衝索引輪替。**[碼]** 這些欄位的硬體語意未逐一查證，但和「軟體不再每幀重啟 DMA（2.2 的 FUN_c0184c80 被跳過）」對得上 → **DMA 改成連續/自動重載模式**。**[推，中高信心]**
  - FUN_c0173f20 L62765–62890：旗標=1 時控制字 bit25–26 清 0（一般為 1），模式 2/4 水平再加 0x50。語意未知。
  - 感測器輸入 DMA 本身就是 8 格位址環（0x30182180…，目前索引 0x301821e8&7，FUN_c0181858/FUN_c01822b8），幀完成 IRQ 只讀目前索引。**[碼]**
- **另一個只看 >99 fps 的 bit（不看 canvas+0x90）**：FUN_c01caba0 L117136 把 FUN_c01cec08 寫進描述子 +4 bit12。讀它的地方：FUN_c017e5e0 L68470（不清 0x3021061c bit0 / 0x30230014）、FUN_c0179b38 L66763/66917/66955/67048/67140、FUN_c01cb9b8 L117835（+0x100 = 1，一般為 2）、FUN_c0189298 L75857（見 §5）。**[碼]**

## 3. 抽幀（每 N 幀才做一次）

- **FUN_c0181748（L70570）不是抽幀。** 計數器 C31DA924+ch 只有三處寫入：FUN_c0181748 自己遞減（L70588）、FUN_c0175dd8 歸 0（L63419）、FUN_c017e5e0 歸 0（L68473）。C31DA924 是 BSS（不在 seg1 映像內），初值 0。**沒有任何地方載入大於 0 的值。**→ 實際行為：`描述子+0x204 != 0` 且 `(base+0x3021061c)&1 == 0` 時，設 bit0 並寫 `0x30230014 = 1`（重新開啟某個區塊）。0x3021061c 的高位元是窗口數（FUN_c0105dd8 L3084、FUN_c0156f38：5/6/8/0xB/0x10 格），0x30230018–20 是窗口範圍 → **疑似統計/偵測區塊（AE/AF 類）的啟用位**。**[碼]／語意[推]** 高格率穩態中，R2V/R2Y 只要 `+0xC==0 且 FUN_c0125870()==0` 每輪都會呼叫（L111645、L112107），也就是每輪檢查並重新開啟。
- **_DAT_c31ddb4c 一半抽幀**（FUN_c01c3d38 L111820–111857）：FUN_c01d7d58==2 時隔幀丟棄送往 PATHHDR 信箱（FUN_c01c6e88）。FUN_c01d7d58 由 FUN_c01d7ce8（L126777）依模式碼 0x18/0x29（附參數）設，**和格率無關**。**[碼]**
- 計數器 C3032910（FUN_c01c7d18/30）：S2R 設成 cfg[5]+1，MANAGER 每輪減 1；找不到讀它來 gate 的程式。**[碼]**
- **沒有找到依格率選 N 的預覽/AE/AF 抽幀。** 高格率靠的是「軟體 8 ms 輪詢＋硬體連續跑」，不是抽幀計數器。

## 5. 依「確切格率」而且不會隨 120→240 等比縮放的地方

- **dly_tsk(8)**：固定 8 ms。**[碼]** 對 240p 是好事：軟體迴圈不翻倍。但也代表 240p 下軟體大約每 2 幀才跑一輪；如果這幾條迴圈裡有一定要每幀做的事（例如把描述子轉給下一段），240p 會跟不上。**[推]**
- **FUN_c0189298（L75779）**：一般模式用 `寬×2×高×fps×(位元+3)/10` 算頻寬，選 45/90/180/360 M 檔位，再從 C07D4224 的 N/16 工作週期表選遮罩。描述子 bit12（>99 fps）時直接固定為 ch0=0x1249（5/16）、ch1=0xFFFF，檔位 0。**[碼]** → 240p 和 120p 用同一個值，不會依格率加倍。寫到 FUN_c01cfe70 結構 +0xD0/+0xD4，最後給哪個硬體區塊用未查。**[碼]／是否夠 240p 用：未知**
- FUN_c01c9d28（L116195）用 fps 與常數 30 算行數；只在 MANAGER 連續狀態才跑，高格率時 MANAGER 已停車。**[碼＋推]**
- 沒有找到 `==120` / `==100` 或依格率索引的表。唯一的格率門檻是 99.0（DAT_c01cef80）。

## 6. 240p 仍然每幀在跑、最值得下手的地方

1. **中斷處理每幀都跑，不看旗標**：**[碼]**
   - IRQ 0x3f FUN_c012fa08：每次引擎完成 sig 最多 11 個號誌（高格率時沒人等，只是累加到上限）、FUN_c0131138（回呼 _DAT_c31d9648、FUN_c0181858/FUN_c01822b8 讀緩衝環）、FUN_c0130568。
   - IRQ 0x1c FUN_c012fe10（FUN_c0630d60/c0630620/c0631088、set c98 等）、IRQ 0x1d FUN_c0130058、IRQ 0x79 FUN_c0125478（FUN_c0129570/FUN_c0127508 大量影子暫存器複製、4 個回呼、sig c38/c34）、IRQ 0x7a FUN_c01302f8（FUN_c0130568(0,1)、set ca0/c98）。
   → 240p 時這些全部翻倍。
2. **VDD 任務 FUN_c0130408 每個 VD 一輪**（不看旗標）。`FUN_c019c508(0)==1 && FUN_c01d3dd8(0)==1` 時每輪會**忙等最多約 2 ms**等 C31DD6D8 bit0。240p 時 VD 間隔只有 4.17 ms，這可能是最大的單點成本。**[碼]／條件是否成立[未知]**
3. **S2R 每輪仍做 FUN_c01cab48(0,d,0x10)→FUN_c01caba0（431 行描述子重建）＋FUN_c01c31a0＋送描述子**，沒有 gate（L111169–111171）。目前被 8 ms 節流，不隨格率翻倍；如果改短 dly，這段就會跟著變多。**[碼]**
4. **FUN_c0181748**：高格率穩態每輪讀一次 0x3021061c，必要時重新開啟統計區塊（L111645、L112107）。成本很小。

## 追加：頻寬設定 0x1249 的去向（主控核對）

  高格率旗標（param+4 bit12，即 FUN_c01caba0 由 FUN_c01cec08 設）：通道 0 → 0x1249（16 格開 5 格）、檔位 0；
  通道 1 → 0xFFFF（全開）、檔位 0。寬 0xF00(3840) 時另改 0xFEEE。
- 寫入：FUN_c01895f0（L76162–76163）→ FUN_c019f440(0x30110440, 樣式<<16) 與 (0x30110448, 檔位)。
  FUN_c01d9e70 對 0x30110440/0x30110444 寫 0（關）或 0xFFFF0000（全開）→ 判斷為兩個影像通道的時脈閘控樣式＋時脈來源檔位。[推，中]
- 意義：這是節能用的時脈節流，不是 DMA 頻寬。原廠 119.88p 同樣是通道 0=5/16、通道 1=全開，所以 240p 與 120p 拿到相同時脈。
  若 240p 錄影的重工作在通道 0，5/16 會是限制；若在通道 1 則已全開。哪個通道在做事目前未證實。
