fpGyroSup r19：r17 排程讓步＋r18 raw 先釋放的混合流程

r18 的 DNG、GCSV、JSON 都有完整建檔，但從約 12.2 秒開始在幾乎每個 raw
區塊交界掉樣，完整率只有 83.11%。原因是整塊格式化期間沒有任何 CPU 讓步。
r19 每累積 64 KiB 文字只讓出 CPU 5 ms，不在該階段寫卡；整塊完成、raw
釋放之後，才以 64 KiB 分段寫入 SD 卡。

測試流程：
1. 開機等到 fpSup!。
2. 先錄約 20 秒。r18 的週期性問題在 12.2 秒後已會出現，因此這段即可
   判斷混合排程是否有效。
3. 若相機正常，再錄約 60 秒並正常停止。
4. 鎖解除時立即接錄一段 10～15 秒短片。
5. 最後一段停止後立即正常關機，確認會等 GCSV/JSON 完成。
6. 相機正常關閉後，把卡放回讀卡器並說「讀卡」。

立即停止測試的條件：
- 錄影自行中止、畫面凍結、卡燈或錄影燈異常長亮。
- 停止後超過約 15 秒仍不能錄下一段或正常關機。
- 若凍結，不要再錄；直接把卡交回讀取。

主要驗收：
- 每段 CINEMA 資料夾都有同名 GCSV 與 JSON，本版不會新增 GYR。
- GCSV 時間戳單調、正常間隔 400 us，不應再出現每約 1.5～2 秒一次的
  週期性缺口，也不應有超過 10 ms 的缺口。
- 一分鐘片段應接近 150,000 筆；r17 的 99.817637% 是最低比較基準。
- DNG 編號連續，錄影不會因 sidecar 工作而自行停止。
- GCSV/JSON 整套任務完成前，下一段錄影與關機保護仍須有效。

不要混合安裝 r18 與 r19 的啟動檔。
