fpGyroSup r24：三槽有序 queue + back-pressure 診斷版

r24 以 r23 為底，不改 2,500 Hz、GCSV 計算、64 KiB 寫卡或 5 ms 讓步；唯一
的資料管線改動，是把兩個 32 KiB raw slot 增加為三個。Writer 依 sequence
順序取 READY，callback 只會取得 EMPTY，因此不會以新資料覆蓋尚未寫完的槽。

本版也會在每段 JSON 加入 `fpgyrosup_backpressure`。它只使用 RAM 計數，沒有
新增錄影中的檔案或 SD 卡呼叫；可以直接判斷遺失發生在格式化、F_WRITE、寫後
5 ms 讓步，或其他階段。

請用與 A001_017 相近的負載測一段：
1. 開機等到 fpSup!。
2. 錄約 60 秒；前 30 秒保持相機較穩定。
3. 後 30 秒持續明顯手持晃動，幅度接近 A001_017，但不要撞擊相機或讀卡介面。
4. 正常停止；等整套 GCSV + JSON 任務完成、錄影鎖解除。
5. 可再錄一段短片驗證接錄，也可直接正常關機並等待關機完成。
6. 把卡放回讀卡器並說「讀卡」。

r23 A001_017 對照基準：
- DNG 1,813 張連續且大小一致。
- GCSV 151,514 / 154,313 筆，完整率 98.186154%，缺 2,799 筆。
- 五個主要缺口為 380.942、41.746、284.950、280.961、122.815 ms。
- 這五次都緊跟在需要第三次 64 KiB flush 的 block 後。

主要驗收：
- 錄影不可自行中止；DNG 編號連續，GCSV 與 JSON 完整，本版不會新增 GYR。
- GCSV 時間戳單調、正常間隔 400 us，所有列皆為完整七欄數字。
- `dropped_total` 理想值為 0；若非 0，四個 drop phase 計數應能說明來源。
- 首要比較是否消除 r23 的整批 122--381 ms 缺口，或把完整率推近 100%。
- 整套任務完成前，下一段錄影與關機保護仍須有效。

立即停止測試的條件：
- 錄影自行中止、畫面凍結、卡燈或錄影燈異常長亮。
- 停止後超過約 15 秒仍不能錄下一段或正常關機。

不要混合安裝 r23 與 r24 的啟動檔；AutoRun.txt、VSHL.BIN、PGEN.BIN 必須
全部來自這個資料夾。
