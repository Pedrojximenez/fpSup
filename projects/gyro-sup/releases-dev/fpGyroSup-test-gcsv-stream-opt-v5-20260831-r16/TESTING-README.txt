fpGyroSup r16：GCSV-only 串流吞吐優化測試

這版不會建立 GYR。r15 已證明 GCSV 與 JSON 可以在錄影任務內快速完成，
但即時處理只有約 1,500 筆/秒，造成約 37～40% 陀螺儀取樣缺口。r16 保留
相同 native lifecycle 與固定 RAM 用量，只優化 writer 熱路徑。

第一輪測試：
1. 開機等到 fpSup!。
2. 先錄 10～15 秒並正常停止，確認相機沒有凍結或自行停止。
3. 再錄約 60 秒，正常停止後等到可以再次錄影。
4. 若前兩段正常，再錄 10～15 秒並於停止後立即正常關機。
5. 相機自行關閉後，把卡放回讀卡器並說「讀卡」。

立即停止測試的條件：
- 錄影自行中止、畫面凍結、卡燈異常長亮。
- 停止後超過約 15 秒仍不能錄下一段或正常關機。
- 若凍結，不要再錄；直接把卡交回讀取。

主要驗收：
- 每段 CINEMA 資料夾都有同名 GCSV 與 JSON。
- 本版沒有新增 GYR。
- GCSV 時間戳單調，正常相鄰間隔為 400 us，且沒有超過 10 ms 的缺口。
- 約 60 秒影片應有約 150,000 筆以上取樣；實際標準以 GCSV 時間跨度除以
  400 us 計算，完整率應接近 100%。
- JSON 完整，下一段錄影與正常關機仍受到同一套任務保護。

r15 保留作為缺口基準；不要混合安裝 r15 與 r16 的啟動檔。
