# Gyroflow sup — SIGMA fp Ver.5.02 — 2026-08-30

插卡、開機、拍攝。每一段影片結束後,卡上就有 Gyroflow 需要的東西,**全程不接電腦**。

```
\A001_075.GYR                      原始陀螺資料(備查,Gyroflow 用不到)
\CINEMA\A001_075\A001_075.gcsv     陀螺與水平資料
\CINEMA\A001_075\A001_075.json     鏡頭 profile
```

實測:Gyroflow 穩定效果良好(使用者驗證,2026-08-30)。

## 安裝

把 `card/` 裡的三個檔複製到記憶卡根目錄,插進相機開機。螢幕出現 `fpSup!` 即為成功。

```
AutoRun.txt   339 條指令:配置 1 MB 池、寫入 loader、寫入並執行 pgenload
VSHL.BIN      四個區段:worker、logger、park stub、最後才寫的 hook word
PGEN.BIN      profile 生成器,開機時由 pgenload 讀進池記憶體
```

**還原**:把 `card/` 換成只有 USB shell 的舊 AutoRun 即可(見 `out/card_backup_*`)。

## 這一版做到什麼

- **profile 由相機自己算**,零主機輸入:讀 L-mount 鏡頭(名稱、焦距)、查韌體自己的
  IMX410 時序與幾何表、算出捲簾時間與 focal_px、格式化成 JSON 文字並寫檔。
  逐欄位與主機端計算相同。
- **捲簾時間取自那一段真正使用的模式**,在第一個區塊寫入時取樣(766 ms),
  避開錄影開始與結束兩端的即時取景模式。FHD 29.97 → mode 106 → 10.556 ms。
- **gcsv 由相機自己組**,與主機解碼器逐位元組相同。
- **凍結已修**。二分法定位(每組 7–9 段):沒有 logger 0 次、只寫 .GYR 0 次、
  加上 profile 0 次、加上 gcsv 約四分之一。兇手是 `gcsv_build` 在錄影剛結束時
  回讀 250 KB 再寫 600 KB,把檔案系統佔住,讓優先權 6 的 `SRecFile` 進不來。
  修法:**每讀一塊、每寫一塊都 `dly_tsk(5)` 讓出**,整段多花約 0.2 秒。

## 已知問題

1. **軟關機後下次開機會失敗,需要拔電池冷開。** 拔掉記憶卡也一樣,所以不是
   AutoRun 重跑造成的。留在相機裡的三樣東西是嫌疑:開機時借走的 1 MB bufmem
   配置、常駐的 GYROLOG 任務、打進韌體 RAM 的陀螺 hook。最可疑是配置沒歸還 ——
   拔電池正是唯一能重置配置器的動作。**尚未定位。**
2. 偶爾有一段不產生 `.GYR`(觀察到 A001_044、068、069)。原因未查。
3. `.GYR` 寫在卡的根目錄,不在片段資料夾裡 —— 它是錄影期間持續寫入的,
   而相機同時在那個資料夾裡寫近千張 DNG,不想在那時候加上我們的目錄更新。

## 判讀凍結

`\CINEMA\<clip>\SPP_metadata.xmp` **0 bytes 代表那一段當時卡死**(相機在錄影開始
時建立它,收尾時才寫入)。正常是 298–299。這是唯一能事後判讀的證據。
