## 2. 物理上限(模型,前提 P1)

| 媒體 | R(寫入期間) | 說明 |
|---|---|---|
| SD UHS-II(此卡) | ~265 MB/s | 有效上限 = R × 檔案大小 / 補齊後大小 |
| SSD | ~412 MB/s | 跑分 390 吃了固定開銷,不矛盾 |

- 判斷任一模式能否持續:**需求 = 補齊後每幀大小 × fps**,要 ≤ R × 工作比例。小幀時 cluster 補齊比例最大(1.1 MB 幀:SD 128 KiB +7.7%、SSD 512 KiB +43.6%)。
- 原廠在高資料率時會積壓,在途幀超過 94 就停錄;O2 讓在途幀與資料率脫鉤。

## 3a. 護欄(修正我們的功能踩到的原廠限制,不是優化)

| 名稱 | 內容 | 為什麼需要 | 狀態 |
|---|---|---|---|
| **FCAP**(批次幀數上限) | C063F826 `cmp r2,#0x80`(80 2A)→ `#0x28`(28 2A):每批最多 40 幀 | 原廠隱含前提「檔案夠大,一批扣不了多少幀」(原廠模式 2–8 MB/檔 ⇒ 8–30 幀)。LOSS 壓縮與 res-custom 小幀破壞了它,64 MiB 一批會扣住 40–134 幀而撞上 94 格。在途 ≈ k + k×(資料率/媒體速度) + 保留,媒體跟得上時 ⇒ k ≤ (94−保留)/2 = 40,與檔案大小、壓縮、解析度、格率無關,不需任何模組計算。一批不到 40 幀時不介入。 | 離線 7 項 + 上機通過(10-15,FHD 59.94p 壓縮 450 幀不停，每批 40) |

獨立 sup(ID `FCAP`),獨佔宣告字 0xC063F824;LOSS 與寫入層都不依賴它、也不得宣告此字。保留量 14 待從原廠描述子生命週期確認。

## 4. 執行順序

```
FCAP 護欄(獨立小 sup,讓產生小檔的功能都不再在 94 幀停錄,不依賴寫入層)
P1 已由程式碼確認成立 → O1(SSD 128 KiB)取決於 P4(相機怎麼選 cluster、接不接受電腦格式化)
O2 + O3(同一個寫入 task 模組)—— 解 94 幀停錄、SSD/SD 都受益
O4 → O5(先 V60 卡的 VSC,再舊卡的舊式)
O6、O7
```

## 6. 上機最少要做的三件事

在不能逐項測試的前提下,只有這三件事會改變方向,其餘都先用離線模擬:
1. **P1**:SSD 128 KiB cluster 錄一段(FHD 或 M12 120p),看 rec log 每批位元組與寫入時間。
2. **O2+O3 完成後**:同一模式對照原廠,看 94 幀是否還會停、duty 是否接近 1;抽檔逐位元比對。
3. **O5 完成後**:V60 卡與舊卡各錄一段,看 free AU 消耗是否等於資料量 / AU,檔案系統檢查通過。

## 7. 決策紀錄

- **2026-10-14 寫入模式**:暫定 SD 與 SSD **一律**使用本寫入層,不看使用者的 Write Mode(標準/自訂)。
  SSD 選「標準」時原廠在 C03A50F8 把 `mgr+0xD` 設 0、走每幀直寫分支;本層在該初始化之後把 RAM 的 `mgr+0xD` 設回 1,
  讓原廠一律走聚合路徑再由本層接手。只改 RAM,不寫設定區(第一守則);使用者的選單值照舊保存。
  UI(例如新增「自訂+」選項、設定區只存原廠值 + 旗標存自己的變數/BIN)之後再定。
- **2026-10-14 接法(依 WRITER_LOCK_SCOPE.md)**:不改 C063F048/C063F380。vol+0x4834..0x4848 是 RAM 裡的函式指標
  (完成回呼、arena acquire/add/release),在 C063F220 之後換成本層的,C063F310 排空時還原;C063F140 入口 hook 成
  「封塊 → 交給寫入 task → 取空塊(沒有就等)」。切塊仍由原廠門檻(+0x4828,設為 RU 倍數)決定。
  寫入 task 不拿 FS 鎖,自己 acquire 原廠 arena → 逐段 add → C01EB790 → release → 逐 cookie C03A55D0。
  **寫入 task 優先權數字必須 ≤ 6**(裝置號誌與 FS 鎖都無優先權繼承;SRecFile 是 6)。
  acquire 永不回 0(回 0 會讓整段錄影永久降級成同步直寫);「+4A58==0 立即回呼」改掛到最後一個未完成的塊(= wq 的扣住機制)。
- **2026-10-14 與 LOSS 的相容性**(lossless-sup session 回覆):
  - 正式版/預設/step-1 的 LOSS 與本層**沒有指令層級的衝突**;observer 檔頭方案(尚未實作)作用在 tag Subject 0xC31AC4EC
    與 C038C700,完成前的寫回仍在 C03A5490(提交之前),送出後不再碰檔案內容 ⇒ 與本層相容。
  - LOSS 原本 SL_EXCL 宣告並逐段寫 0xC0B9E5D8(批次設定字)。**2026-10-14 使用者決定:LOSS 刪除這項調整**,
    批次大小只由本層決定(C063F220 之後於執行期改 vol+0x4828)。本層不宣告 0xC0B9E5D8。
    ⚠ 本層出貨前,單獨使用 LOSS 的壓縮錄影會回到原廠 64 MiB,可能重現 EARLY_STOP_94(94 幀停錄)。
  - **只有 `--expand-slots` 量測版**(在 C063F1B8/C063F854 的 cookie hook、C037DF50.. 寫入防護)會衝突;
    不在任何正式版。上機測本層前,卡上必須先換回 LOSS 正式版或 step-1(目前相機上是量測版 4ee2ee1d…)。
  - LOSS 不依賴完成回呼的執行緒或 FS 鎖;幀只經原廠路徑釋放。
  - **已完成(lossless-sup,2026-10-14)**:LOSS 移除批次調整,不再宣告/寫 0xC0B9E5D8(宣告 14 → 13),build 47b15e07…,
    離線 49 項通過,未上機;同時捨棄 expand-slots/1016、寫入防護、預備 IFD、M12 改動,只留快取別名 + observer 檔頭。
