# Grip USB 開發路線

更新：2026-10-24，Asia/Taipei。現行目標是 LiDAR 保持接 Grip，研究 Grip USB 是否能輸出所需資料或控制 fp 電子鏡頭。主線不再要求移除 Grip。

## 入口與角色

| 路徑 | 已知 | 下一個未知 |
| --- | --- | --- |
| Grip 相機控制孔 → fp | df101fh/0505 參考有 USB host、PTP 與數值對焦 builder | 實體 Grip 版本配對；實際握手與啟用條件；數值是否隨 LiDAR 目標變化 |
| Grip 充電孔 → Mac | 官方列為電池充電孔 | 是否能列舉資料介面；需使用者選定並確認接線後唯讀觀察 |
| LiDAR → Grip 的資料孔 | 官方規格列 Power/CVBS/CAN；可正常提供 Grip 畫面／測距的歷史使用者回報 | 不將此孔的資料當作已由 Grip 相機 USB 輸出 |

相機控制參考路徑中，Grip 是 USB host、fp 是 PTP device；不能把一般 Mac host 直連視為已可側錄相機對話。若需要實機觀測，先檢查現有 fp 觀測方案及回歸問題，完成具體離線驗證後才部署；本次沒有操作相機或寫卡。

最新離線結果：[相機身分與數值對焦分流](research/camera-identity-numeric-gate-20261024.md)。原始VID分類器將1003→SIGMA kind8、04DA→LUMIX kind4；同一numeric action在SIGMA ioctl回3且不產生PTP，在LUMIX則組出9416/03010031。相機任務另需ops指標與共用gate通過；目前fixture未跑完整初始化。下一個離線重點是LUMIX初始化的gate寫入／握手必要條件；不把換VID當成完整方案。

## 順序

1. 使用者選定 USB 孔與連接端；核對當下接線、Grip 是否正常顯示、實機版本。普通充電孔的 descriptor inventory 與相機 PTP 接收紀錄分開。
2. 定位與實機版本相符的 USB driver、裝置辨識、session／能力查詢；保留原始命令與回覆，區分離線參考與 wire capture。
3. 先取得穩定的控制／數值觀測，再以使用者近遠目標對照驗證單位、失追／無效值與時序；不因數值接近距離就直接驅動鏡頭。
4. 把已確認語意接入 fp 原生鏡頭狀態及距離換算；測試手動對焦、原廠遙控、錄影等回歸。原 0.1.1 觀測版尚未解決舊原廠拉焦回歸，不能直接稱為可部署成品。
5. liveview、深度圖與點雲各自查 USB 來源；單點數值、Grip 螢幕有影像或內部 CVBS 不算已取得 USB 影格。

## 驗收

- 保存實體 Grip＋LiDAR 配置的連續 USB 對話與版本、線路、工具雜湊。
- 證明數值／控制隨目標或使用者操作變化，確認物理語意、無效值處理及可觀測延遲限制。
- 若交付 fp 對焦：在實際電子鏡頭完成近遠對照，保留原功能及失聯處理的實測證據。
- 若宣稱 liveview／深度／點雲：保存真實連續影格，核對場景變化、格式、單位，點雲另需投影／標定。

完成上述目標與證據後停止循環。缺使用者操作時只保留一次待辦；沒有新依據不重送失敗命令，不以反編譯數量或測試數量計功能成功。
