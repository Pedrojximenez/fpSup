# isp-lab 研究計畫（2026-10-23 起）

目的：把 ISP 路徑研究完整，與 imx410-lab（感光元件端）一起成為 **RES-Custom2** 的依據。
isp-lab 是開發工具，沒有 UI；介面就是 USB shell。測試時不把 CinemaDNG 真的寫進 SD/SSD，
而是像 imx410-lab 那樣用 USB 抓幾張回來驗證（例外：回放測試，見 §3.5）。

證據等級沿用 imx410-lab：**[M]** 上機量過、**[C]** 程式碼／韌體反組譯、**[I]** 推論。
起點資料：`../imx410-lab/notes/ISP_SIZE_RULES.md`（§5 那 12 條未解就是第一批題目）、
`../imx410-lab/notes/ARCHITECTURE.md`（四模組分工、驗證分層）。

## 1. RES-Custom2 要的答案

1. 任意裁切（長、寬）
2. 任意輸出解析度（長、寬）
3. 列出所有達得到的 FPS
4. 列出所有能做到 1–3 的方式（感光元件設定 × ISP 設定；同一組裁切和解析度可以有多種組合），
   **刪掉沒有優點的組合**，剩下的列給使用者選

### 1.1 裁切：一條固定規則，不給使用者選（使用者 2026-10-23 定：sensor 先切高）
- **高度先在感光元件端切**（少讀列 → 捲簾短、格率高），切不到的零頭再交給 ISP。
- 寬度在感光元件端沒有速度收益（格式寬只有幾檔、接收端 x 窗不會加速，ISP_SIZE_RULES §3.6），由接收端／ISP 處理。
- 感光元件端的粒度限制：起點 ≡1 (mod 4)、x 以 12 px 為單位，新合併類別只能全高 → 這些情況高度也只能由 ISP 切，要標出代價（讀了白讀）。
- 錄影路徑上 ISP 能怎麼裁還沒研究完：已知 TIM x 窗、DefaultCrop（rec 仍寫整個視窗）；RWZM 能不能只吃一部分輸入沒查過。→ §2 題目。

### 1.2 縮放：多條路徑，代價各不同，要列給使用者選

| 路徑 | 粒度 | 已知代價 |
|---|---|---|
| 感光元件合併（2×2、3×3、h2、v3…，GENERATOR §2） | 固定倍率 | 格率最高、捲簾最短；暗部雜訊比數位平均高 1.14–2.34×（CAPABILITY_MAP BINNING） |
| CRCT bin（H 1/3/5、V 1/3） | 固定倍率 | 不加速；畫質特性未量 |
| RWZM | 1/1024 一階 | 不加速；OG2K 實拍最銳利（memory og2k-sharpness-ranking），疊紋較多；分母大的比例會出現條帶（ISP_SIZE_RULES §2.9） |
| 以上串接 | — | 代價疊加；可落點更多 |

### 1.3 排除沒優點的組合（Pareto）
每個組合量一組代價向量：
`(最高 FPS, 捲簾, 銳利度 MTF50, 疊紋, 雜訊, 條帶, 位深, 預覽可用)`
A 在每一項都不比 B 好 → 刪掉 A。量測方法要固定（同一組標靶、同一套算法），數字才能互比。

## 2. ISP 鏈能力地圖（待填）

逐級查：能否裁切、能否縮放、粒度、上下限、**硬體極限還是政策**、錄影／預覽兩分支是否共用。

| 級 | 已知 | 要查 |
|---|---|---|
| 接收端（0x3010） | x 窗 12 px、y 窗要與感光元件一致（§3.1–3.5） | x0 非 12 倍數的任意值（§3.2 只測過 mode 10） |
| BUFA | 12-bit 截到 16 px 倍數 | 與寫入器粒度 8 的矛盾（§5-1） |
| CRCT | bin H 1/3/5、V 1/3 | 畫質；是否能裁 |
| RWZM（錄影 +0x64/+0xD4、預覽 +0x60/+0xD0） | 1024..16384、兩軸獨立 | 放大與範圍上限的真實硬體極限（§5-4）；條帶規則（§5-5）；能否裁輸入 |
| 寫入層／DNG | rec/act/16-10 邊（§1） | 留邊是否必要（§5-9）；奇數起始列的 Bayer 相位（§5-10） |
| 預覽分支 | 來源 ≤2100、可見 ≤2000（§2.10） | 大幅面配 240/280 時預覽走錄影路徑（§5-7） |

## 3. 每個組合的檢查點（使用者 2026-10-23 定）

| # | 檢查點 | 看什麼 | 怎麼抓 |
|---|---|---|---|
| 3.1 | **待機畫面** | LCD／HDMI 正常、FOV 與錄影一致、無花屏或凍結、長時間穩定 | 相機截圖（fp-camera-control）、偵測影像 `0xC375D8C0`、預覽傳輸計數 |
| 3.2 | **對焦時畫面** | (a) 半按 AF：AF 框位置對應正確、CDAF 收斂、人臉偵測正常（R28 格網要跟著新幾何）；(b) MF 放大：放大會換感光元件讀出（memory zoom-is-a-sensor-mode-change），自訂模式要能進得去、回得來、放大區域對到正確位置 | 截圖、AF 統計 peek（memory dfd-via-af-stats）、偵測影像 |
| 3.3 | **錄影時畫面** | 開錄第一秒無接縫（§2.6）、>60 fps 預覽走錄影路徑（§4.3）、無凍結、畫面上顯示的格率正確 | 停錄後讀相機截圖或事後檢查；**錄影中不碰 USB**（memory no-usb-during-rec-or-playback） |
| 3.4 | **實際 CDNG** | 檔頭（rec/act/原點/位深/FrameRate/ColorMatrix/BlackLevel）、內容與 imx410-lab BUFA RAW 參考比對（FOV、Bayer 相位、條帶）、幀連續 | IMXL C-a capture sink 寫進 DRAM，停錄等 10 秒後用 MEM1 拉回；代價向量（§1.3）在這裡量 |
| 3.5 | **回放**（最後一關） | 相機內回放：縮圖、播放畫面、非標準尺寸是否顯示正確、不當機 | **要真的寫卡**：C-a 只會在卡上留下空檔案，沒辦法回放。所以這一關用短片段實際寫 SD；回放中不碰 USB，看完再讀截圖 |

### 3.6 自動化（使用者 2026-10-23 定）
測試要能整批自動跑，**不能受 SD 卡限制**（res-lab 的錄影證據幾乎都靠使用者手動錄 SSD，還被 shell／HDMI 開關混淆過多次）。
- **CDNG**：C-a sink 寫進 DRAM，SD 頻寬（約 94 MB/s）不再是門檻；DRAM 只夠幾張到幾十張，驗證用夠了。
  未知：非快取複製（`copy_us`）追不追得上高格率；追不上時 94 格 RAW 池會用完、錄影自停，那是工具的假象，不是配方的問題。
  對策：抓前 N 張後改 IX_DISCARD，持續性另外判斷。
- **回放**：C-a 會在卡上留下正確目錄結構的空檔案；停錄後用 putfile 把抓到的 DNG 填回去，再用按鍵注入進回放、直取 LCD 畫面判讀。
  這樣回放也不受 SD 寫入速度限制。（待證：填回的檔案韌體認不認、要不要配 WAV）
- **畫面**：要能**直接取得 LCD 上的畫面**，不靠相機截圖或 HDMI（§3.7）。
- 錄影中、回放中不碰 USB：畫面取樣由相機端 hook 寫進 DRAM 環，停止後再拉。

### 3.7 LCD 畫面直取（待研究）
- 起點：`research/imaging-hw/notes/IMAGE_CHANNELS.md` 頁首 2026-10-09 更正 —— 顯示 ring `0x49801000` 起 4 筆，
  按 descriptor 寬度（例 1620，每列 3240 B）可**線性**解成 YUYV 4:2:2 全彩（lut-sup 實檔證據）。舊的「tiled、別解」已作廢。
- 只取**影像層**。**OSD 不做**（使用者 2026-10-23：從畫面判讀文字沒效率）。格率、解析度、REC 狀態、對焦框位置這些，直接讀韌體裡的變數或設定，不從畫面辨識。
- 要查：各顯示模式（待機、放大、錄影、>60 fps、回放）下 ring 的寬高與 stride 從哪個 descriptor 讀；錄影中取樣的 hook 點；與 RAW／DNG 做 FOV 比對時的座標換算。

規則：任何會經過模式切換的配方，必須先通過 imx410-lab 的第 1 層（感光元件端驗證，RESWEEP_DESIGN §9）。

## 5. 工作順序（使用者 2026-10-23 同意：用 RES-Custom2 的需求排順序，工具只做研究需要的最小版）

isp-lab 是研究工具，**不是 RES-Custom2**。配方安裝用最小手段（直接寫 profile 欄位、借現成原生動作切換），
不經 res-custom consumer；「出貨路徑驗證」是 RES-Custom2 自己的事，它會拿 isp-lab 的檢查工具去驗。

| 階段 | 做什麼 | 完成標準 |
|---|---|---|
| **0 工具校準** | 三條抓取管道在**原廠模式**（UHD、FHD、OG3K）各跑一次：LCD 影像層、BUFA0 mux=1 參考 RAW、DRAM 抓的 DNG | 抓回來的東西跟原廠行為一致（尺寸、FOV、內容）；工具本身沒驗過，後面全不可信 |
| **1 單一未知數** | 只用原廠感光元件模式，一題一個小實驗（ISP_CAPABILITY_MAP §3）：CRCT 錄影 bin、RWZM 極限、留邊、奇數起始列、待機 FOV、AF 格網、放大、回放欄位… | 每題一個明確答案，回填規則表 |
| **2 代價量測** | 4–5 個代表性目標（暫定：全寬 16:9 FHD、3:2 2K、2.39:1 裁切、小畫面高格率、非等向；待使用者挑），每個目標列出所有可行路徑，用同一套方法（沿用 REDUCTION_KERNEL_MEASURED）量銳利度、疊紋、雜訊、條帶 | 歸納出 Pareto 規則 |
| **3 接自訂感光元件** | 只用 imx410-lab 第 1 層通過的配方，跑五個檢查點 | 規則在自訂模式下仍成立 |
| **4 交付** | 規則表 + 可重用的五檢查點工具 | RES-Custom2 拿去用 |

ISP_CAPABILITY_MAP 第 11 題（主機進 UI thread 套用）降級為「RES-Custom2 才需要」。

## 6. 與 imx410-lab 的分工（2026-10-23，與 sigmafp-re-40 討論定稿草案，待使用者確認）

- **邊界 = BUFA0、抽頭 mux=1（Crmf）**：在 DCLP 箝位／DEFC 壞點／PDAF 校正之後，CRCT Vbin/Hbin/Hbin2 與 RWZM（BUFA1）之前。
  原廠 306 個 profile 的 CRCT 合併全關，所以 mux=1 = 感光元件輸出 + 箝位 + 壞點，是 isp-lab 的參考 RAW。mux 0（Gain）韌體從不用，不當基準。
- **imx410-lab 負責**：感光元件、接收端、DCLP、黑位參考、DEFC/R68、列數、幀率。`plan()` 只算 RWZM 比例，不設定 RWZM。
- **isp-lab 負責**：RWZM（BUFA1）之後、SIG、CDNG 寫入、LCD。
- **CRCT bin**：原廠全關，維持關閉、不算任何一邊；isp-lab 若要用它做合併，當新能力另外驗。（→ §1.2 表裡的 CRCT 列改為「新能力，待驗」）
- **安裝**：兩條路徑是同一機制（8 張模式表經描述子 0xC2F1E654 由韌體切換）。vmode.py（借 host 10 放大、必須 KEEP_WINDOW=True）給 imx410-lab 測試；
  res-custom SEC_VMODES（donor + 覆寫）是出貨用。imx410-lab 會寫 `export_overrides(plan)` 並加兩條路徑逐位元組等價的離線測試。
  ~~isp-lab 一律走 res-custom~~（10-23 撤回：isp-lab 用最小安裝手段，見 §5；出貨路徑由 RES-Custom2 驗）。
- **穩定介面**（imx410-lab 會維護，改前通知）：`readout_cfg.plan(key, cw, ch, ow, oh, fps)`、`smc.create(plan)`、
  `captures/smc_validated.json`（id = `key:CWxCH>OWxOH@fps`，含 light/dark）、`export_sim.py` 的 JSON、之後的 `export_overrides(plan)`。isp-lab 每次測試記這些檔案的 sha。
- **錄影中與回放中不能用 USB**（連 status 都不行）：這兩個檢查點只能由相機端 hook／sup 存證據（DRAM 環）、停止後等 10 秒再取；
  錄影的開始／停止也要由 sup 自己觸發（主機事先下一個指令，之後不碰 USB）。
  **使用者 2026-10-23 選這條，但「別存太多，高幀數下會爆掉」**：
  - 固定預算：主機 arm 時給一塊固定大小的記憶體，存滿就停止存（不覆寫、不再要記憶體），錄影照常。
  - 按**時間**取樣，不按幀：LCD 畫面每秒固定幾張、DNG 取開頭 K 張再每隔一段取一張；存的張數跟格率無關。
  - 每一幀只記一筆很小的紀錄（幀號、時間戳、狀態），用來判斷掉幀與持續性，不存影像。
  - 複製不在錄影的關鍵路徑上做：hook 只記「要抓這張」，由低優先權工作複製；來不及就跳過並記一筆，不能讓 RAW 池（94 格）被拖住。
  - 主機端的判定要分清楚「工具跳過」和「配方掉幀」。

- **10-24 imx410-lab 交付「可用模式清單」**：`projects/imx410-lab/export/modes_verified.json`（export_modes.py，IMX410_RULES §75）。
  617 筆、38 類（12-bit 537、14-bit 80）；暗場已驗 512、未驗 105（`verified.dark = null`）。每筆有 crop/out/fps、時序、sensor_out（含 RWZM 比例）、
  donor＋感光元件寫入、ISP attrs。排除 h3、V3 開視窗；1x1 格式寬用實際行寬。**isp-lab 的感光元件端輸入一律從這份取**，模式表列用
  readout_cfg.plan + smc.create 重建。
  **10-25 更新**：640 筆，亮暗場全驗（IMX410_RULES §76）。V3 全高：每幀第 14 個輸出列後插 14 列未曝光 → 輸出 1330 列（w18 為 1324）、ISP y0 20→48；
  V3 視窗：往上多讀 16 列、y0 +16。`sensor_out.y_skip` 記多讀／跳過列數，attrs 的 y0／wstart／wh 已是修正值。
  **自算黑位時 OB 範圍要扣掉 y_skip**（多讀的列是影像，不是 OB）——ISP 黑位檢查項目要涵蓋。14-bit V3 2160 視窗：6064×720、捲簾 9.41 ms、≤ 92.9 fps。

## 7. 主動推送架構（使用者 2026-10-23 定：「錄影中與對焦中主動推送 liveview 給 USB，結束錄影時將緩存中的 CDNG 主動推送給 USB」）

測試全自動（使用者測不完），而且**相機主動推、主機只收**：錄影中主機不送任何指令。

| 時機 | 推什麼 | 規則 |
|---|---|---|
| 錄影中 | LCD 影像層（顯示 ring 一格，≈2.9 MB，與錄影格式無關） | 按時間取樣、設位元組預算、上一筆沒被收走就跳過；每張附幀號＋時間戳 |
| 對焦中（半按 AF、MF 放大） | 同上 | 同上 |
| 停錄之後 | 記憶體裡還在的 CDNG 幀（RAW 池最多 94 格） | 錄影中只記下取樣幀的位址與幀號（不複製），停錄後把那些緩衝直接指給 USB 推出 |

錄影本身照原廠寫卡（不載 ISPL 的 sink），sup 只負責：控制 task（韌體錄影腳本 recstate + key MOVON）、記位址、推送。
**不向配置器借任何記憶體**（10-23 事故的推定原因）；狀態放池。每次錄很短（約 2 秒），之後自動刪掉這段。

要先查清楚（離線→待機→錄影）：
1. LV 推送的掛點：顯示 ring 換格的地方（錄影中、半按、放大都會跑），不能在錄影的關鍵路徑上。
2. 記 CDNG 幀位址的掛點：寫入層交出每幀片段的地方（ULWR 掛過 C063F048/C063F140；只記位址不複製）。一個 DNG = 檔頭＋數段 RAW。
3. 停錄之後 RAW 池的內容還在不在、能撐多久（下一次錄影或模式切換前？）：第一次要拿卡上的 DNG 逐位元組對照。
4. EP83 推送：TRB 直接指向緩衝（零拷貝）；上一筆完成前不再 arm；推送後 ~1 s 內主機不送指令（memory hookpush-quiet-period）。
5. 錄影中從 sup 啟動 USB 傳輸：從沒試過——第一個要驗的風險。

第一步：控制 task 單獨（不推送）在原廠 FHD 自動錄 2 秒、自動停 → 同時驗證「停不下來是借光記憶體」的推定。
