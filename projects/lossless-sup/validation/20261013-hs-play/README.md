# 2026-10-13 HS280 119.88p 壓縮片段在相機回放時當機

卡上：`../20261013-hs-compress/deploy` 候選版（`a1a09ada…`，1016 格＋64 MiB＋M12 修正）。

## 第 1 次重現（`play_poll.py`，`poll-1.csv`）

PLAYON → 2.5 s → OK（播放最新片段），之後每 0.5 s 讀 LOSS 的 play 計數器（只讀）。

- 4.6 s：clips 2、seen 6（stock 2、decoded 4）、refused 全 0、每幀解碼 7.1～7.3 ms、scratch 1,548,288 B 正常取得。
  幀檔 416,768 B（使用者新錄的片段，不是 A001_012）。
- 7.6 s 起 USB 讀不到，之後 shell 逾時：相機當機。
- 按 OK 後約 1.8 s 只讀了 6 幀，比 120p 慢很多。

已排除：回放用的引擎提交 `C0630240` 的輸出上限是 `dst + 長度`，**沒有**錄影端 `C062FFF8` 那個 −1 MiB，所以不是 M12 同類問題。
到當機前沒有任何解碼被拒絕或失敗。

## 使用者手動測試（同日）

- 拔掉 USB 回放 HS280 壓縮片段：一樣當機 → 不是 USB shell 和讀卡衝突。
- LOSS **OFF** 錄 HS280 119.88p（全 RAW）再回放：**也當機**。

結論：當機和壓縮／LOSS 解碼無關，是原廠播放器回放 HS280（RES-Lab 自訂 1008×672 120p）片段的問題。
LOSS 的壓縮和解碼本身正常：當機前解碼的幀都成功，沒有被拒絕。

殘留疑點：LOSS OFF 時回放 hook 仍然在作用。對全 RAW 片段，它只讀檔頭，並從 RAW 池先拿 1.5 MB 解碼暫存區。
要完全排除，需要在沒有載入 LOSS 的卡上回放 HS280，目前還沒做（使用者要求候選版留在卡上）。
