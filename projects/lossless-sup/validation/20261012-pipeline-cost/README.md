# LOSS：新增 CPU 成本修正與逐幀管線

本輪找到並修正 DNG 尾表與補零的逐位元組讀改寫成本，並新增本地逐幀動畫。
原廠 64 MiB 批次門檻維持原樣；位置擴充沿用既有公式。
STOPFX 仍為 Ruari 的獨立 05STOPFX.BIN，未修改或合併。

## 修正原因

壓縮引擎完成事件使用原廠的阻塞等待，沒有改成忙等。
問題之一在完成後的 CPU 工作：透過非快取記憶體介面搬移約 1 KiB 的 DNG 尾表，
原本每個位元組都先讀取完整字組，再改寫完整字組。結尾補零也採用相同方式。
因此，硬體壓縮完成後仍多出大量記憶體存取。

- `trailer.c` 改用對齊字組讀寫；連續未修改的 IFD 欄位合併搬移。
  offset／byte-count 表也連續寫入，只有起訖邊界需要保留相鄰位元組。
- `codec_job.c` 以整個字組補零，只有不對齊的起訖部分讀改寫。
- TIFF 根 IFD 指標最後才發布，保留原有檔案內容與完成順序。
- 暫時的分段計時受編譯選項控制；正式 BIN 沒有分段陣列或新增的計時呼叫。

## 相機分段證據

FHD 1936 × 1090、12-bit、59.94p。分段區間與同一段錄影的原廠任務切換紀錄交叉比對，
計算任務實際獲得執行的時間，而不是把等待引擎的整段經過時間當成 CPU 時間。
觀察窗相對任務監測起點為 1.1–2.1 秒；診斷 USB 優先序兩邊同為 10。
前後分別在重開後量測；任務歸屬時間仍可能含中斷與記憶體等待。

| 工作 | 修正前平均 CPU | 最終修正平均 CPU | 修正前／後次數 |
|---|---:|---:|---:|
| 表頭 DMA | 0.0227 ms | 0.0220 ms | 54／58 |
| DNG 尾表 | 1.4170 ms | 0.4269 ms | 54／59 |
| 原生入列 | 0.0218 ms | 0.0209 ms | 55／59 |
| 引擎事件等待＋完成修補，每次呼叫 | 0.3516 ms | 0.1053 ms | 106／113 |
| 引擎設定與啟動 | 0.2673 ms | 0.3041 ms | 55／59 |

尾表平均 CPU 減少約 70%。這五段在觀察窗內合計的 CPU 歸屬時間從 13.09% 降到 5.75%；
這是已量測的五段，並非 LOSS 的全部成本。
整體 CPU 為 96.89% → 90.86%。中間版本另一次短測為 89.65%，
說明整機其他工作會影響整體百分比；不能把單段短測当成所有情境的固定增益。
較早的 OFF 83.18% 只作參考，來自前一輪、不同重開時段。

## 建置與離線驗證

- 尾表／編碼器 47 項測試通過：包含精確內容、對齊、邊界、全 1024 種補零長度、
  解碼與會破壞發布順序的 mutation 檢查。見 `stream-host-tests.log`。
- Frame hold 165 項測試通過。見 `final-hold-tests.log`。
- 實際保存的正式 BIN 在 ARM 模擬器 16 項測試通過，包含擴充位置、callback、
  loader ABI 與實質 mutation 檢查。見 `final-arm-tests.log`。
- 網頁佇列模型通過 conservation、RAW 配置保留、精確批次、跨批次幀、
  通道忙碌、輸入與位置公式檢查。

早期一次測試命令指定了不存在的 `native.test_flush_site` 模組，因而整個呼叫報錯；
修正命令後已取得上述 165 項通過結果。沒有將錯誤的測試呼叫標為成功。
主機沙箱中的 Unicorn JIT 曾收到 SIGILL；以既有 JIT 權限跑完整保存 BIN 測試後通過，
這不等同相機 CPU 的實機執行。

## 卡片更新與回復紀錄

每次更新只替換 10LOSS.BIN，保存原檔與 STOPFX 備份，並在重開前完整讀回核對。
原生刪檔／寫檔 ACK 有時遺失；不重播結果未知的写入，
僅在確認檔案已刪除且寫入工具尚未啟動後進行一次新的寫入。
正式版驗證見 [deploy-final/verified.json](deploy-final/verified.json)。

第一次較小版本更新時曾在讀回驗證前誤送重開，已向使用者說明並保留紀錄。
該次相機缺少 LOSS 檔案但 USB shell 仍可用，後續已補回並完整核對；
未帶著缺檔狀態試錄。重開工具現在強制要求對應候選的成功讀回與 SHA。

## 逐幀網頁

[本地逐幀管線](http://127.0.0.1:8765/fpSup/tools/pipeline-lab/)；來源在
`fpSup/tools/pipeline-lab/`。可慢放、暫停、逐幀／逐事件前進或拖曳時間。

每一幀保留幀號及位置，呈現壓縮通道／RAW 旁路、批次、實際資料過閘時間與完成回呼。
96 格不會在壓縮或資料送出時立即清空。跨兩批的幀要等最後一批回呼，位置才釋放。
可選原廠 96 格或兩批公式擴充、不同 RAW 尺寸、FPS、媒體速度、壓縮比與交接延遲。

這是十秒離散事件模型。預設 FHD 編碼約 14.4 ms，交接约 2.5 ms，參考本輪短測；
其他尺寸的編碼時間按像素數推估，交接時間可手動調整。
資料批次以精確 64 MiB 拆分；未滿一批的尾資料不在此窗內停錄結算。
模型只計算待完成 RAW 配置與兩份 spare，未納入整機其他配置、CPU 排程、
檔案操作成本或硬體記憶體仲裁。它不從動畫推估 CPU；CPU 欄是相機實測。
選取模型中的尺寸／幀率也不代表機身原生選單支援該組合。

完整機器可讀結論見 [status.json](status.json)。未 commit、push、更新發佈包或公開部署。
