# fpLossless progress 2026-10-01

## Shared UI string pool (fpSup/uishare/ui_pool) — lossless is its first user; card r on the camera

The goal is to merge with OG. OG3K's string alias hook (C05E5B58) requires reader+0x14 == the stock pool. Lossless used to replace the pool, which broke that check.

The fix is a convention, not an integrator:
- Every sup interns its private strings with `uis_intern()` at load time.
- The first intern copies the stock pool once (16 KiB room, never freed), with a 16-byte "FSPL" header before it, and switches the reader.
- Later sups append to that copy; offsets are never claimed in advance.
- Details: fpSup/uishare/README.md.

Lossless:
- FPLM format 2 carries the page, its private strings, and 18 {page offset, string} references. The references come from the builder manifest and are cross-checked against the page, so a stray word is refused.
- At load, menu_page.c interns each string and writes the offset into the page.
- Lossless no longer touches reader+0x14/+0x10 itself, and no longer keeps its own 176 KB pool copy.

Tests:
- test_ui_pool: 15 OK (8 mutations).
- test_menu_page: 26 OK (15 mutations).
- Card emulation: 10 OK.

Card r (build/testcard-20261001-r): fpSup.BIN 70911220…, AutoRun 35a3141f… (unchanged).

Camera (2026-10-01):
- The pool is the FSPL copy: capacity 0x2F02D, length 176,241 (stock + 89 B).
- All 18 page references resolve to their strings. "xxx" and "Footer05" reused their stock offsets (0x2A5C4, 0x12BC4).
- Row installed; operator: the menu is normal.

Next: OG accepts the FSPL pool (its alias check), is rebuilt, and is tested together with lossless on the camera.

## Two lanes + codec task (card w, 2026-10-01)

Goal 1, "start the engine the moment it finishes". The power cycle per job
(CLOSE/OPEN) is unchanged: that is goal 2.

- `frame_hold`: a hold is now also a lane (IDLE→HELD→RUNNING→FINISHED→
  COLLECTING→IDLE, FAULT). Arrival holds a frame in an idle lane and gives back
  finished ones; the codec task checks the engine every 1 ms and, in the same
  pass that finds it done, starts the waiting lane. HELD→RUNNING, HELD→IDLE
  (stop) and FINISHED→COLLECTING are claimed with IRQs off (C000EC14/EC24).
  `fpl_lanes_arrive/task/stop`; old `fpl_hold_arrive` path kept and used when
  no task could be created.
- card: second pipeline, spare and table (class-10 pool); task "FPLCODE",
  priority 12 (SRecRaw 15, SRecFile 6), 0x2000 stack, created at init;
  stop waits (1 ms sleeps, ≤1000) for the task, then abandons leftovers;
  flush looks in both rings.
- Host: test_frame_hold 138 OK (lane tests + 12 lane mutations caught);
  card emulation 11 OK (task descriptor checked). Built
  `build/testcard-20261001-w-og3k`; fpSup.BIN put and read back
  (sha256 5d7321d4…). AutoRun/FPSUPUI identical to card v.
- Status now reports combined engine load, chained starts and gap,
  held-to-start max, frames passed because both lanes were busy.

## Header by the firmware's DMA (card x, 2026-10-01)

Why the copy exists: the swap makes the firmware write S, but C038C5F8 DMA'd
the header (template C038A318 → frame[0x4C] − frame[0x14C]) into A. No tag is
edited in that copy. Stock DNGs: the header region is referenced by tags up to
0x133A4 (MakerNote 54 KB, profile tables, DNGPrivateData); frames of one clip
differ in only 9–27 bytes (< 0x7200).

C00FBB90 {src, dst, bytes, flags=0}: synchronous (twai_flg on its own flag),
own cache maintenance, own semaphore (task context). The swap now uses it for
the 0x15400 prefix, CPU uncached copy only if it refuses.

## Power kept on (card y) — failed; refusal hang fixed (card z)

Card y kept the engine powered: OPEN once, then per job only OPEN's block
reset C06304F0 + engine interrupt enable C0630480(1), CLOSE at stop. On the
camera every reused job came back with the engine's error bit (pattern 4):
A open ok, B kept → refused, A reopened ok, A kept → refused. So OPEN's power
or clock steps (C0708C60, C07095A8(5,1)) are needed per job; goal 2 is not
reached this way. codec_job keeps the option (input.power); the card passes 0.

The refusals exposed a real bug: with no output span the refusal path gave
pipeline_complete bytes 0 → INVALID → fault, the frame was never given back,
native stop hung ("stuck writing", 4 s take, 126 arrivals, 85 stop checks
finish_busy). Fixed: the refusal reports the job's destination (READY_RAW,
nothing copied); any failed completion gives the frame back. Tests for both,
mutation-checked. Built build/testcard-20261001-z-og3k (= x + the fix).

## In-camera playback, step 1: the hardware decoder works (2026-10-01)

The engine has a decode mode. C062FAD0 (behind C05A69E0) mirrors the encoder:
its own SUBMIT C062FEC0 → C0630240 sets the mode word C37CF87C = 2 (encode 1),
the ISR calls the decode callback (C062FCE1, sets flag bit 2), start C062FED8 →
C06303F8. Init C05A6890 takes word 8 = 1 (decode), word 5 the raw buffer, word 6
the compressed stream (1 KiB aligned). In stock firmware only
XC_PlayFuncSeqDngDeveloping (in-camera RAW development of a Compression=7 still,
"DNG_Decomp") calls it; fp never writes such stills, so this path had likely
never run on an fp. Normal playback shows the DNG's embedded preview.

Probe: projects/lossless-sup/tools/hwdecode (probe.c through callfn, run.py),
standby only, never in playback. A001_267 frame 1 (3024x2010 12-bit, 36 tiles
512x368, stream 3.24 MB at 0x13400):
- Output rows are the recorder's raster rows (4536 B, MSB-first 12-bit).
- C062FAD0 cannot do this frame: told the real height (2010) it decodes the
  first 5 tile rows and only the first tile of the last row; told the
  tile-padded height (2208) its last-band height is 2208 % (368 * rows) = 0 and
  the request is refused -- and it returns without CLOSE, leaving the engine
  open (the next OPEN then fails; CLOSE C062FE81 once to recover).
- Its steps done by hand for ONE band with the padded height (flag, tile count
  C302CDEC, clr, OPEN, request {w, 2208, fmt, tw, th, engine block[0..3], 0, 0,
  C062FCE1}, SUBMIT C062FEC1, START C062FED9, twai_flg(bit 2), clr, CLOSE):
  **0 of 6,078,240 pixels differ, 22.7 ms** (file read ~23 ms besides).
  The last tile row alone (copied to an aligned buffer, h 368): 0 differ, 3.8 ms.
- The engine writes whole tiles: the raw buffer must hold the padded height.
  A 2010-row buffer was overrun by up to ~0.9 MB once (the USB shell wedged
  after; camera rebooted).
- `mem save` does not overwrite an existing file: save under a new name.

## Playback step 2: decode in the player's frame read (card aa)

The CinemaDNG player (CinemaDngPlay) never reads Compression or the strip
offsets: its tag reader (C05C1A58) takes 0xC620, 256/257/258, 0x10A, 0xC764
only. Each frame file is read whole by C05C0C38 (file name from position/10,
f_read at C05C0EA0 into slot+0x14, capacity +0x18, read +0x1c); the read length
check at C05C0EAC only logs (C0011100) when the whole capacity was read.

New site C05C0EA4 (stock E595201C `ldr r2,[r5,#0x1c]`, bl to a fifth veneer at
cave+48; the record stays at +32): native/play_decode.c. A frame is decoded
only if all hold: TIFF LE, root != 8, trailer IFD Compression 7 with a
contiguous LONG tile table inside the bytes read, IFD0 at 8 the same frame's
uncompressed strip, capacity >= strip + pitch*h, strip 1 KiB aligned, no live
take. Then: stream DMA'd to scratch (and the partial last tile row separately),
whole tile rows decoded straight into the strip, the last row into scratch and
its frame rows DMA'd in, root put back to 8. Anything else is left exactly as
read, with the reason counted. Host: test_play_decode 23 OK, 10 mutations;
card emulation 12 OK (new play-shim test, mutation-checked).
Built build/testcard-20261001-aa-og3k, put and read back (26f4f8e4…).

### Card ac: FHD fixed; an OG3K display oddity (not ours)

FHD lossless played as garbage on ab: the recorder's raster rounds its LAST
row to 12 px (1936 → 1944: 2916 B, not 2904), so IFD0's strip is 12 B longer
than rows × pitch and the clip was not taken for ours. ac allows that slack
(LAST_ROW_SLACK) and checks the room against max(strip, rows × pitch). On the
camera: FHD and 3K lossless both play; FHD decode ~20 ms/frame, 3K ~59 ms;
0 refused. Stock clips untouched.

OG3K clips looked squashed with the resolution setting on FHD (2); after
switching to OG3K they were normal -- and stayed normal after switching back
to FHD. Same with card z (no player hooks): OG3K's own display, to look at
later.
