# fpLossless progress 2026-10-02

## A job the engine never finished (SSD long takes) — card ad

A001_200 (OG3K 29.97p, SSD, 3072 frames): compressed normally to frame 562
(18.8 s), frames 563–564 missing, nothing compressed after. A001_201: stopped
compressing after frame 1394 (46.5 s), no gap. Counters (card ac, not rebooted):
lane B still RUNNING, faults 1 (stop abandoned it), "both lanes busy" 601,
stops 13 / finished 1 / busy 12, lane stop result 5. Engine registers in that
state: 300D0000 = 0 (start bit gone), 300D0004 = 0, 300D0008 = 4, end position
300D00F8 = 0 (never written), interrupt enabled (300D0074 = 1), mode word 1,
encode callback C062FCB1, request geometry correct (3024x2010, 6x6 tiles).
One job neither finished nor signalled; the lane waited forever, the other
lane's held frame waited behind it, every later frame passed raw, and the two
held frames were only given back at stop (lost once, in A001_200).

Fix:
- codec_job: fpl_codec_job_abort -- keeps 300D0000/04/08/0C/64/74/F8/3FC in
  stall_regs, then CLOSE (power off, block reset, IRQ off) and the job is IDLE.
- frame_hold: a RUNNING job not done after STALL_POLLS (250 checks, each >= 1
  tick + the task's 1 ms; UHD's normal job is ~50 ms) is given up on: aborted,
  and the frame goes out as an engine refusal would (unchanged); the lane is
  free and compression goes on. Counted in hold.stalls.
- card: dual lanes only. If the codec task, either spare, lane B's table or
  pipeline cannot be had, the admitted take is undone (rec workspace finished)
  and records as stock. The single-lane and no-task paths are gone from the
  card (frame_hold keeps fpl_hold_arrive, whose tests cover the shared
  handoff/swap/promise code).
Tests: codec_job + 3 (abort), 1 mutation; frame_hold lane tests for a job that
never finishes once (given up, next frames compressed) and for a starved task
at stop; 2 mutations. Single-lane tests removed. All suites and emulation OK.
Built build/testcard-20261002-ad-og3k (OG3K + shell + FS2), put and read back
(959745b1…). putfile staging was slow (repairs) while the stuck lane polled.

## 48p playback garbage: scratch taken too early (card ae)

Card ad on the camera: SSD A001_211 (OG3K 48p, 44,208 frames, 15.3 min)
recorded fine -- 49% compressed in every stretch to the end (no stall). Its
playback, and a short 48p SD take's, showed garbage. Counters (short take):
clip recognised (size 3,137,536 -> 9,196,544), scratch taken -- and freed 5
times for 5 clips of ours; the frame read found no scratch (refused 'scratch').
When the size changes the player frees its old pool (C05C2E90, where the
scratch was freed) and then makes the new one (C05C2D10). 30p tests happened
not to have an old pool to free.

Fix: clip open only records the need (scratch_want); a new site at C05C2D10
entry (stock E92D44F0, `b`, displaced push, resume C05C2D14; veneer cave+72,
cave block 80 B) takes the scratch when the pool is made; C05C2E90 still frees
it. test_play_decode 33 OK (camera order: clip, old pool freed, pool made,
frame decoded; 2 new mutations); emulation 15 OK (pool shim test,
mutation-checked). Built testcard-20261002-ae-og3k, put and read back
(a2828719…).

## First frame of every take uncompressed (card af)

Users report DaVinci Resolve plays a clip mixing compressed and uncompressed
frames only when its first frame is uncompressed. card.c now queues a take's
first arriving frame straight to the original (take_frames), so file 000001 is
always stock. Playback could no longer tell a clip of ours from its first
frame, so fpl_play_clip now sets scratch_want for EVERY clip whose IFD0 is a
stock strip we can decode (12/14/16/10-bit); a clip opening on a stock frame
keeps its size (already a stock frame's), one opening on ours gets the stock
size as before. Cost: stock clips of those formats also take the ~4.6 MB
scratch while playing. test_play_decode 35 OK (+2 mutations); frame_hold,
emulation OK. The first-frame rule in card.c has no host test (camera only).
Built testcard-20261002-af-og3k, put and read back (7ab5b059…). putfile staging
was slow again (134 s, 13,367 repaired); cause not looked into.
