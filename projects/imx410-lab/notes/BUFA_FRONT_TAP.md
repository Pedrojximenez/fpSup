# 最早的 RAW 落點：CRCT → BUFA DMA(2026-10-20,離線 RE,未上機)

證據等級:[C] 程式碼證實、[I] 推論、[L] 筆記裡的實測。

## 更正
- SIG0 的 RAWOUT 不在 0x30112800。韌體內建 dump `FUN_c01597b8`(blk_c01.c:49985-50003)的標籤是：
  RAWBLT = 0x30112800/830/870/890(shadow 0x30210448);RAWOUT = 0x301128C0..CC(shadow 0x302104D4)。[C]
  記憶 `bayer-not-in-dram-liveview` 的標籤錯了一格。
- `FUN_c019b488` 是 SIGSEQ 的啟動，不負責 arm RAWOUT;config+0x20 是 SIGSEQ 的遮罩值(0x71FFFFFE),不是 DRAM 位址。[C/I]

## 鏈路
SLVS-EC PHY 0x300E1000 → 接收組裝器 0x30100000(兩個通道)→ **CRCT 0x300F0000**
(DCLP 箝位、DEFC 0x300F0D00、PDAF 校正、Crmf、增益、vbin/hbin/hbin2、RWZM)→ **BUFA DMA → DRAM** → SIG(之後)。
- 視窗:`FUN_c0635ed8`(blk_c06.c:46833)寫 x 到 0x3010000C,寫 y 到 0x30100024(y_start<<16|y_end)。[C]
- BUFA0(a0 視窗):控制 0x30182100,行長依位深 enum(`FUN_c06306e0`),目的位址 0x30182180/184 由 `FUN_c0631640(addr)` 設定(實體位址>>2)。
  BUFA1(RWZM 輸出)有 5 個槽 0x30182280..2A0;BUFA7 位址 0x30182380。[C]
- 抽頭點 mux:a0 0x300F06B0、a7 0x300F06D0;0=Gain 1=Crmf 2=Vbin 3=Hbin 4=Hbin2 5=Spc。韌體從不用 0。[C]
- 錄影 `ContSet_Adr1`(blk_c03.c:19726)把 BUFA0/7/1 指向 `*(desc+0x38)` = raw_addr;拍照 `PreExpos_s` 也一樣(blk_c03.c:16887)。[C]
- 一般 liveview(選擇器分支 A)三個 BUFA 都關著 → 這就是待機時 DRAM 裡沒有 Bayer 的原因。[C]
- 原生旁路指令:`imager crmf_off / dclp_off / defect_collect_off / pdaf_cor_off <flag>`(blk_c03.c:163933-164110);合併旁路 0x30100980 bit4。[C]

## OB 列
- 每模式的 DCLP 箝位區在表 0xC0B5C638(stride 0x38,4 區);平均值從 0x300F0250/270/290/2B0 讀(`FUN_c0633688`)。[C]
- 模式 3/121:視窗 y 40..4082,箝位列 24..32 → OB 列確實進到了 SoC,只是被視窗裁掉。[C]
  實測 0x30100024 = 0x000E054E 與模式 147 的表一致。[L]
- BUFA0 幀大小直接由這兩個暫存器算(`FUN_c01250e8`):把 y_start 改 0 應該會多出約 40 列(需要把緩衝加大)。[C 機制 / I 結果]
- embedded data:找不到字串或路徑;推測 PHY 剝掉了封包標頭。未解。[I]

## 每幀完成
ISP 中斷來源 7(blk_c01.c:32097)→ `FUN_c0630620`(0x30182048 bit0)→ 回呼 `[0xC37CF8CC](arg, [0x30182184]*4+0x40000000)`。
錄影時是 `FUN_c031bb50`,它把位址交給 AcqInThr。啟停 `FUN_c06316b8(n)`(n=100 停)。BUFA0 有兩組位址(180/184)。[C]

## 方案(依風險)
1. **最低:在 liveview 自己 arm BUFA0。** 分支 A 沒人用 BUFA;不在錄影狀態 → 可以用 USB;後段完全不跑。
   要在任何錄影或拍照開始前解除 arm。共用的回呼全域變數是風險點。
2. 低：錄 CinemaDNG + IMXL sink。但 UHD 拿到的是 RWZM 之後的資料，錄影中碰 USB 也有風險。
3. 中:`imager createraw` 單張。
4. 中高：在錄影中改選擇器 `FUN_c0325228` 的輸出。
5. 不是最早:HDMI RAW 是 SIG 之後的資料。

## 要上機量的
BUFA0 在分支 A 能不能乾淨地跑;y_start=0 拿到的 0..39 列是什麼;x 能不能小於 8;CRCT 各級的順序;
dclp_off 改變了什麼;embedded data;能不能連續跑(兩組位址)還是每幀要重新 arm;
頻寬：全幅 12-bit 約 36.8 MB,USB 上限約 10 fps。

## 單幀 arm 步驟(2026-10-20 第二輪離線 RE,未上機)
原廠錄影 ContSet:c0630ad0 → c06316b8(100) → c06340c8(1,{0}) → c06340c8(1,{1}) → c06314d0(&w) → c0635ca8(mux) → c0631640(buf) → c06316b8(10);
之後每幀只換 c0631640(next),不重新 arm(BUFA0 會一直跑)。停止 = c06316b8(100) + c06305f0()。全是 Thumb(+1)。
- 視窗 struct 0x14 B:x0,x1,y0,y1(u16)、排除帶 +8/+0xA、kind +0xC(0 = 接收端整個視窗)、fmt +0xD、位深 enum +0xE、flags +0xF、回呼 +0x10。
- c06316b8(n) 寫 0x30182000:10→2、0xB→4、0x11→8、1→0x10、100→0(並清 0x30002060 bit0)。0x30002060:bit0 BUFA0、bit4 BUFA1、bit28 BUFA7。
- mode 8:高 1344 × 每行 756 words(3024 B)= 0x3E0400 B;行距 = 行長;0x30182180 = 實體位址>>2(下一幀)、184 = 正在寫的那幀。
- 完成：ISR `FUN_c012fe10`(blk_c01.c:32055)來源 7 = 0x30182048 bit0(寫 0 清);呼叫 [C37CF8CC] 後 signal [C2F14B28]、[C2F14C40],旗標 [C2F14C98]|=1。
- 風險：號誌 [C2F14B1C]「BUFMODEF」只在函式內短暫持有，可從 shell 任務呼叫;0x30000804 是寫 0 觸發的脈衝暫存器，c0630ad0 的 RMW 可能把 BUFA1 一起重設(改直接寫 0xFFFFFFFE);
  殘留的旗標 bit0 會讓下一次拍照或錄影提早放行，結束要 tk_clr_flg(0xC00169C8,ARM);**待機時 BUFA1 是開著的**(2004=4、2060 bit4),是 SIG 那一側在用，不能碰。
- 取一整幀不撕裂：第一幀完成後把 180 改指 scratch,正在寫的那幀會寫完。

## ★ 上機結果(2026-10-20 04:1x,v4 slim 卡,CINE liveview mode 8 MONIT1_60)
`bufa_probe.py frame captures/bufa_f1`(mux 1 = 原廠抽頭,kind 0,12-bit):
- 設定後讀回 2110 = 1344、2114 = 756 words,與離線預測完全相同;arm 後 **65 ms** 就收到第一幀(哨兵被覆蓋)。
- 停止並還原後只有 0x301821F0/F4/F8 跟基準不同(0x02F41001 / 0x20000 / 0x1833490),看起來是 DMA 自己的狀態/計數(0x2F4 = 756),不是我們設的值。
- 相機正常：未錄影、frame_count 持續增加、shell 正常。
- 解碼:**韌體 getter FUN_c031e6b0 的格式 = LE 32-bit 字內 MSB-first 位元流，每 3 字 8 像素**(`decode12.py`)。
  解碼後同色鄰點差 dx2 = 2.4、dy2 = 2.5 DN(其他三種常見排法 dx2 > 1000);2×2 相位：(0,1)(1,0) = 460、(0,0) = 372、(1,1) = 362 → 兩個 G 在對角，是真的 CFA。
  畫面是失焦的場景(對比低,155..828 DN)。
- MEM1 會把傳輸補齊到 1 KiB:小於 1 KiB 的寫入要改用 mem set(第一次的哨兵寫入因此被拒)。第一次失敗漏掉 2×4 MB 配置，重開機後歸還。

## mux 0 vs mux 1(2026-10-20 上機)
同一場景各取一幀:mux0 = 1.000 × mux1 − 0.4..−1.2 DN,四個相位的雜訊相同(R/B 3.4–3.8、G 6.3 DN)。
→ liveview 下 Crmf 等於直通，原廠抽頭(mux 1)已經是 a0 mux 能取的最早一級。兩幀都沒有任何 8σ 離群點 → 壞點校正(DEFC)多半在抽頭之前，待用 `imager defect_collect_off` 驗證。
0x301821EC..F8 每次都變 → 確認是 DMA 狀態，不是設定。

## ★ OB 列(2026-10-20 上機,`--ystart 0`,mode 8)
接收端視窗 y 從 14 改成 0 → BUFA0 高度 1344 → 1358,抓完後 0x30100024 已還原。
| 列 | 平均 | 標準差 | 備註 |
|---|---|---|---|
| 0 | 0 | 0 | 整列都是 0(虛擬列或 DMA 起始，未明)|
| 1–10 | 251.1–251.5 | 1.2 | 平坦，偶數/奇數位置相同 → 沒有 CFA 結構 |
| 11–13 | 255.1–255.3 | 1.2 | 比上一段高約 4 DN |
| 14 起 | 有效畫面 | — | 跟原本視窗的第 0 列逐點吻合(位移 14 時 MAD 2.5,位移 13/15 時約 102)|
- 黑位約 251–255,與已知 RAW12 黑位約 256 一致。OB 的雜訊 1.2 DN,比有效區 R/B 的 3.4 DN 低很多。
- 1–10 與 11–13 是兩種不同的列，推測其中一段是 DCLP 箝位用的有效 OB。要用 `dclp_off` 和改增益來分辨。

## OB 列的性質(2026-10-20 上機,mode 8,`--ystart 0`)
- **DCLP**(`imager dclp_off 1` / `0`):關掉後第 11–13 列從約 255 降到 252.2,跟第 1–10 列一樣;有效區也約降 1–3 DN(場景漂移，不能精確)。
  → 第 1–13 列是同一種黑列;DCLP 用第 1–10 列量黑位，從第 11 列起加約 +3–4 DN(目標約 256)。
- **增益**(`imager fixed_gain 1 <相對×100>`,117 ≈ ISO100):

| 相對增益 | OB 1–10 平均 | OB 雜訊 | OB 11–13 | 有效區 G 減黑 | 有效區最大值 |
|---|---|---|---|---|---|
| 117 | 252.3 | 1.00 | 255.2 | 106 | 578 |
| 自動(≈339)| 251.2 | 1.20 | 255.2 | 217 | 907 |
| 1600 | 251.3 | 2.46 | 255.2 | 722 | 2465 |

  → OB 雜訊隨增益變大、平均不變 ⇒ **是真的像素讀出(光學黑)**,黑位在感光元件內就箝在約 252。
  → 增益 ×13.7,RAW 只放大 ×6.8:其餘是後段(ISP)的數位增益。這是增益分配的直接證據(待與 ISO_FIRMWARE_COMPLETE 的類比/數位分界對照)。
- `fixed_gain 0` 不會解除固定增益(handler 只印字),要重開機。已在 2026-10-20 重開機恢復自動增益。
