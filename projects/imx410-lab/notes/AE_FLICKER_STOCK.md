# 原廠防閃爍（AeFlicker）完整 RE（離線，2026-10-21，未上機）

韌體 Ver.5.02 `out/MAIN_c0000000.bin`。[C]=反組譯/反編譯證實，[I]=推論。Tv 一律是 APEX×1024（Tv=1024·log2(1/t)，6803=1/100、7073=1/120）。

## 0. 一句話
**只在進 LV 時偵測一次**（AtOnce）：暫時切到 240 fps 的感光元件模式 12，拿 4 幀 AE 測光格的「列平均」做幀間比較 → 0 無 / 1 = 50 Hz / 2 = 60 Hz。
結果只存在 RAM，所有使用者都經過單一入口 `FUN_c0210118`。用法：把自動 Tv 對齊到 n/100 或 n/120 秒（APEX 查表），另外影響程式線選擇、閃燈、AF 曝光、LV 模式族。
**選單沒有對應設定**：178 個 `cam_*` 參數與字串都搜過，沒有 flicker。

## 1. 偵測
### 1.1 資料來源 [C]
- 硬體是 AE 評估區塊 **0x30058000**。`[0x30058000] bit0` 代表「可偵測」（`FUN_c02103d8`）。
  區域由 `FUN_c01276c0` 讀出：`0x30058010` = hst/vst（各 14 bit），`0x30058018` = hsize/vsize（各 10 bit），`0x30058014` 的 bit0-4 +1 = hnum、bit16-20 +1 = vnum（≤32）。
- 每格是一個 u16 亮度。DMA 緩衝的字址存在 `[0xC31D8C0C]`，換算成 `×4+0x40000000`（非快取別名）。`FUN_c0311740(0xC3201B14)` 會複製 hnum×vnum×2 bytes 回來。
- `initAeArea` @0xC0210170 要求 hnum>7 且 vnum>7。
- `FUN_c02103f8` 把每一列的 hnum 格取平均，得到 vnum 點的「列亮度剖面」，存在 obj+0x5C+k·0x40（3 組輪替）。
  所以垂直解析度只有 vnum（≤32）條帶，不是逐行。

### 1.2 流程（AE 任務內）[C]
1. `FUN_c039a928` 送出 AE 請求，請求結構 +0x18 = 偵測旗標、+0x24 = 禁止旗標。
   處理路徑：`FUN_c02082e0` → `FUN_c020a200` → `FUN_c0209808`（AE 模式 2 與 4）→ `FUN_c02096a0` 判斷 +0x18≠0 且 +0x24==0。
2. `FUN_c020f660` 做準備：
   - 曝光切到**感光元件模式 0xC**。`FUN_c032c7b8(0xC)` 回傳幀長（µs），模式 12 = 240 fps（見 MODE_TABLES_CONSUMERS +0x40）。
   - 依目前亮度重算 Tv，夾在「幀長+10」到 0x3400（1/8192）之間；增益夾在 ISO 上下限內。
   - 如果需要的增益超過上限 0x200（0.5 EV）就放棄：`[0xC3202240]=0xFF`，表示太暗不偵測，舊結果保留。
   - 最後 `FUN_c020b880(...,mode 0xC,1)` 套用固定曝光。`FUN_c020f568` 把 AE 評估區縮到 65%（[I]）。
3. `FUN_c020f228` → `FUN_c0210320` 做初始化：
   - 讀 AE 區，`[0xC320228C]=0` 清掉舊結果。
   - 初始化 50/60 Hz 兩個正弦模型（`FUN_c0229790`）以及比較器（`FUN_c0229bf8`），比較器要求目前 fps==**0xF0（240）**。
4. `FUN_c020fa98(obj,3)` 開始取幀：
   - 用 `FUN_c0321508(FUN_c03214d0(),cb=0xC020F9E0)` 掛上每幀回呼。回呼會對事件旗標 obj+0x11C 設 bit 2。
   - 每幀等待 100 ms 逾時（`FUN_c036d818`）。先取 1 幀參考，再取 3 幀（上限 `[0xC0910CB8]=3`），共 4 幀約 17 ms。
   - 每一對幀呼叫一次 `FUN_c0229cc0`（AeFlckComparison），兩幀分別是 A 與 B：
     - d[i] = (B[i]−A[i])·1024/B[i]，也就是每列的相對變化（1/1024）。
     - **ABS_AVE** = mean|d|，放在 obj[199]。
     - **LINEARITY** = mean|d[i+2]+d[i]−2d[i+1]|（二階差分，代表「非線性度」），放在 obj[200]。
   - 每個新幀 k 都跟前一幀比，結果進陣列 0xC3202260/0xC320226C；也跟前兩幀比，結果進 0xC3202274/0xC320227C。
5. 判定（立即數，**沒有**走 vtable；`AeFlckAtOnceModelBase` 的 vtable 0xC0910EDC 裡 v1/v2/v3 = 40/90/−40 是同一組值，但實際沒被呼叫）：
   - P = mean_k(ABS−LIN)，取相鄰幀。`P ≤ 40` → **0 無閃爍**。立即數在 `cmp #0x28` @**0xC020FECC**。
   - 否則 D = mean_k(ABS−LIN)，取隔一幀：
     - `D > 90` → **1 = 50 Hz**（`cmp #0x5A` @**0xC020FF24**）
     - `D > −40` → **2 = 60 Hz**（`cmn #0x28` @**0xC020FF3C**）
     - 其餘 → 0 無閃爍
   - 原理 [I]：在 240 fps 下，120 Hz 光變隔兩幀剛好同相（D≈0），100 Hz 隔兩幀差 0.8 週期（D 很大）。
6. 收尾：寫 `[0xC3202258]=P`、`[0xC320225C]=D`，`*obj=2`（完成），呼叫 `FUN_c03215c0` 拆掉回呼，再由 `FUN_c020b8e8` 解除固定曝光、回到正常 LV 模式。
- 死碼 [C]：
  - 正弦擬合評估器 `FUN_c0210698` 固定回傳 1。
  - 字串 `SIN PARAM/phase/cnt_fit/ContFitTh`、`D:EXP: ExpTime/LoShut`、`D COMP:60Hz` 都沒有任何引用。
  - 依幀率分的參數表 0xC0917F1C（60 Hz）與 0xC0917F6C（50 Hz）只在初始化時讀。
  - 結論：50/60 正弦模型（`calcAngularFrequency` @0xC0229848）有初始化但沒有參與判定。

### 1.3 什麼時候跑 [C 觸發點 / I 語意]
AE 請求模板 +4 位元組 = 1 的只有三個（在 ROM）：

| 模板 | AE 模式 | 呼叫者 | 情境 |
|---|---|---|---|
| 0xC0B9DA34 | 2 | `FUN_c039d9a0` else 分支 | 進靜態 LV |
| 0xC0B9DA60 | 4 | `FUN_c039dde8` else 分支 | 進錄影 LV |
| 0xC0B9DA80 | 2 | `FUN_c039e280` else 分支 | LV 類型 1 |

- 共同的分派者是 `FUN_c039bfa8`（LV 啟動，上游有 `FUN_c0396c88`，movRec 也會呼叫）。
- 以下情況不偵測：
  - 前一個 LV 狀態是 1 或 3
  - `[CamMgr+0x18C]==1`
  - 錄影 LV 下 `[+0x14]==10`
- **錄影中不偵測** [I]：錄影中不會送帶旗標的請求，而且偵測要切感光元件模式。

## 3. `ae flck` shell [C]
子命令表 0xC0BACEFC（{名稱, 說明, handler}），上層分派函式是 `FUN_c03dc228`。

| 子命令 | handler | 行為 |
|---|---|---|
| `get` | 0xC03DC2D8 | 呼叫 `FUN_c0208610`（**已套用鎖定**的值），查表 0xC0BACF94 {0 "noflck", 1 "50hz", 2 "60hz"} 印出 `flicker state = %s` |
| `set <x>` | 0xC03DC360（Ghidra 誤名 `noflck`） | 只比前 2 個字元：`no` → `FUN_c02087b8(1,0)`；`50` → (1,1)；`60` → (1,2)；**其他字（含 `off`）** → `FUN_c02087b8(0)` 解除鎖定 |
| `disp on N` / `disp off` | 0xC03DC420 | `FUN_c02087d8(printer, level)` 寫 0xC32007C4/0xC32007C8。N 對應：1→1（逐列剖面）、2→3（印不出東西）、3→2（逐列變化）、4→4（I:/D COMP/cnt/VARIATION 摘要）；`off` → 0 |
| `sim rec` / `sim <其他>` | 0xC03DC520 | `[0xC3200728]=1/0`，下一次偵測會**在卡上寫除錯檔** |

- `FUN_c02087b8` → `FUN_c021d320`：寫 `[0xC32006FC]=lock`；lock≠0 時寫 `[0xC3200700]=val`。**只存在 RAM，不寫設定區，重開機就消失**。
- 鎖定後所有消費者立刻改讀鎖定值，不需要重新偵測。偵測照樣會在下次進 LV 時跑，但結果會被鎖定值蓋掉。
- 副作用：
  - `disp on` 把 **shell 的 print 函式指標**存進 0xC32007C4。之後 AE 任務偵測時會從 AE 任務去呼叫它；shell 換掉或不在時有風險 [I]。用完要 `disp off`。
  - `sim rec`：
    - 偵測時用 `FUN_c001d038` 配置 (n+1)×hnum×vnum×2 bytes 的緩衝。
    - 用 `FUN_c020ee28` 寫 `YYYYMMDD_hhmmss.bin`：開檔模式 0x402，已存在就失敗。
    - 內容是 0x54 bytes 曝光/區域頭加上各幀格點，每個 byte `^0x5A` 再 `+0x20`。
    - 寫卡發生在 LV 啟動途中。
  - 回放路徑看 `[0xC3200729]`，全 ROM 沒有寫入者，屬於死碼。

## 4. Hook 點
### (a) 改良原廠 P 模式
- **最小侵入（不改碼）[C]**：寫 `0xC32006FC=1`、`0xC3200700=1/2`（就是 `ae flck set` 做的事）。可以用自己的實測結果覆寫原廠偵測；結果仍只有名目 50/60。
- **單點攔截 [C]**：`FUN_c0210118` 是所有讀者的唯一入口。在函式頭換成跳板，就能依我們的狀態回傳 0/1/2。
- **週期常數的位置**（全是名目值，沒有任何「Hz」浮點常數）：
  - [C] ROM Tv 表（30 筆，n/100 與 n/120 秒）：`0xC0911A0C`（50 Hz）、`0xC0911994`（60 Hz）。由 `FUN_c02140a0` 的 movw/movt @**0xC02140C8/0xC02140CC**、**0xC02140E8/0xC02140EC** 載入，量化器是 `FUN_c021b380`（取最近，log 中點）。改法：搬一份表到 cave，改這兩組 movw/movt。
  - [C] ROM `0xC0911A9C`（18 筆）/ `0xC0911AE4`（20 筆）：慢快門，`FUN_c02152e0` @0xC021535C 一帶。
  - [C] ROM `0xC0911B78` / `0xC0911B6C`（各 3 筆，1/400、1/200、1/100 與 1/480、1/240、1/120）：`FUN_c02154b0`。
  - **[C] RAM 表 `0xC2F18278`（50 Hz）/ `0xC2F182A0`（60 Hz），各 10 筆 s32**：位於 .data，**可以直接 mem set**，不用改碼。只影響 `FUN_c0215590` 的 sens-up 下限（`FUN_c021b458`→`FUN_c021b3f0`）。
  - [C] 立即數：
    - 閃燈：`movw r6,#0x1A93` @0xC022A4CC，0x1BA1 在同一函式。
    - AF：`movw fp,#0x208D`（8333 µs）@0xC0258334；10000 是由 fp 加常數和倒數乘法推出來的，要改就得改寫整個 `FUN_c0258320`。
- **精度限制 [I]**：
  - Tv×1024 的 1 單位等於 0.068% 曝光時間，所以 50.00 Hz 和 50.05 Hz 在 Tv 上只差約 1.4 單位，表本身勉強能放。
  - 但最後是 SHS 按行（hmax）量化。真正要對齊實測週期，應該在 Tv 決定之後、`FUN_c0321398`（曝光拆分）/ `FUN_c03257d0`（SHS 寫入）那一層，把曝光行數改成 round(k·T½/t_line)（§55/§56 的路線）。
  - 原廠表只負責「選哪個 k」。
- 偵測靈敏度 [C]：立即數 @0xC020FECC（40）、0xC020FF24（90）、0xC020FF3C（−40）。

### (b) 我們自己的模式
- 用 (a) 的鎖定或攔截 `FUN_c0210118`，讓 AE 的程式線、程式偏移、慢快門、AF 自動跟著 50/60 走，再在 SHS 層做精細對齊 [I]。
- 每幀時機可以用原廠同一套機制：`FUN_c0321508(FUN_c03214d0(), cb)` 掛上、`FUN_c03215c0` 拆掉 [C]。或用已知的 `FUN_c0313658`。
- 自己做偵測時的資料來源：
  - 可以直接讀 AE 格點：`[0xC31D8C0C]×4+0x40000000`，hnum/vnum 看 `0x30058014`。
  - 原廠偵測所需的 240 fps 模式切換，只能在 AE 任務的 LV 啟動流程裡發生；**不建議用 callfn 直接呼叫** `FUN_c020f660`/`FUN_c020fa98` [I]。
- 想讓原廠在特定狀態才偵測，可以改 ROM 模板 0xC0B9DA34/0xC0B9DA60/0xC0B9DA80 的 +4 位元組（屬於改碼區，要做快取維護）[C 位置 / I 效果]。

### 風險
- 整個模組**不寫設定區**（XC_CommonSaveData）[C：鎖定與結果都在 0xC32006FC/0xC320228C 一帶的 RAM]。
- 只有 `sim rec` 會寫卡。
- 改 ROM 表或改碼要做 I-cache 維護（`FUN_c000e91c`）。
- `disp on` 會留下 print 指標。
