# 讀出產生器設計（2026-10-21）

目標：使用者任選 位元深度 / 裁切 / 解析度 / 幀率 / 品質或低果凍，產生最接近的感光元件讀出；感光元件做不到的才交給 ISP（RWZM、打包）。
標記：[M] 上機實測、[C] 表格/程式碼、[I] 推論、[?] 未驗。細節見 IMX410_RULES.md §15 §21 §31 §33、L7_14BIT.md。

## 1. 感光元件能調的四個軸（彼此獨立，§21）

| 軸 | 選項 | 狀態 |
|---|---|---|
| AD 等級 | 14-bit HMAX 911 / 12-bit 445 / 11-bit 400（全寬）、335（寬 ≤ 4160） | [M] |
| 水平讀出格式 `0001` | 6064 或 4160 全像素；水平合併 2（3032）、3（2020） | [M]；**14-bit + 水平合併不行（T2）** |
| 垂直縮減 | 1 / 2 / 3（Family B，加 `0018` 補暗列） | [M] 1、2、3 都通過，14-bit 垂直 2:1 通過（T1） |
| 視窗 | 垂直：感光元件 0022–0025 任意；水平：接收端 START/END 任意（12 px 單位） | [M] |
| 幀率 | SoC VMAX，無段 | [M] |

## 2. 換算

- 捲簾 RS = HMAX × 讀出列數 ÷ 72 MHz；讀出列數 = 裁切高 ÷ 垂直縮減。
- 最高幀率 = 72 MHz ÷ (HMAX × (讀出列數 + 約 40–76 列額外))。
- 水平裁切在接收端做，不省捲簾；只有感光元件寬 ≤ 4160 時 11-bit 能降到 HMAX 335。

## 3. 位元深度對應

| 使用者選 | 感光元件 | 錄影端 |
|---|---|---|
| 14 | 14-bit AD（只能 1×1 或垂直縮減） | 14-bit 打包（L7 已通） |
| 12 | 12-bit AD | 原廠 |
| 11 | 11-bit 快速 AD（12-bit 字） | 12-bit 打包 [?] 是否要真 11-bit 打包 |
| 10 / 8 | 依優先：品質→12 或 14；低果凍→11 | 查表壓縮後打包 [?] 錄影端未驗 |

## 4. 解題順序

1. 由裁切 + 輸出解析度算縮放比 sx、sy。
2. 列出候選：AD × 水平格式 × 垂直縮減，剔除裁切放不下、幀率達不到、位元深度不夠者。
3. 品質：AD 越高越好、感光元件縮減越少越好（留給 RWZM 超取樣），在幀率允許下選最高。
   低果凍：RS 最小（HMAX 最小、垂直縮減最大、寬 ≤ 4160）。
4. 剩下的非整數縮放 → RWZM；位元深度壓縮 → 錄影端。
5. 原廠 70 個模式只當驗證：產生器對同樣的輸入必須逐欄重現原廠表。

## 5. 待驗證（品質比較）

- 3K 輸出三條路：(a) 6K 1×1 → RWZM 1/2；(b) 感光元件垂直 2:1 + RWZM 水平 1/2；(c) 感光元件 2×2（12-bit `0001=39`，14-bit 目前不行）。
  量：解析度（斜邊 MTF）、疊紋、暗部雜訊、RS、幀率上限。決定「品質」選項的預設。
- 10/8-bit 錄影端打包、11-bit 真打包。
- 11-bit 寬 < 4160 時 HMAX 能否再低（330 在 4160 失敗）。
