# IMX410 研究成果 → 開發計畫（2026-10-21）

依據：SUMMARY_2026-10-21.md、IMX410_RULES.md §41–§55、CAPABILITY_MAP.md。原始需求：使用者自選位元深度 / 裁切 / 解析度 / 幀率，自動生成最接近的感光元件模式（品質 / 低果凍選項），剩下的才交給 ISP（RWZM）。
守則（使用者定）：設定區只存原廠合法值，新值放記憶體與卡上自己的檔案；程式與資料向配置器要記憶體，不碰 cave 位址；每次上機前先說明、等同意。

## D1 讀出產生器
- **狀態 2026-10-22**：第 1 層驗證 10 種讀出全過（RULES §62）；重建測試 92.9% 欄位可由規則重建、留一 84.3%（§63），缺口在 R28/R38/R68。
- **本 session 只負責 sensor mode（模組 1）**；ISP 由其他 agent 負責（使用者 10-22）。交付物：`readout_cfg.py` 規則、`readout_validate/batch` 第 1 層驗證結果、`readout_export.py` 覆寫清單。
- **模組分工見 notes/ARCHITECTURE.md**（使用者 10-22）：1 sensor mode 生產器、2 ISP profile 生產器（res-lab）、3 res-custom（安裝）、4 新 UI；最終只留 3、4。
- **UI 流程（使用者 10-22 定）**：① 裁切範圍（高由感光元件窗；寬取最近的感光元件格式寬，其餘接收端裁）→ ② 解析度（1:1 或變形；分配給感光元件合併 / SoC bin / RWZM，RWZM 只能縮小）
  → ③ fps（決定可用讀出；選單用顏色提示）→ ④ 品質（受 ①–③ 牽制）。
- **簡化原則（使用者：分級太複雜、很多組合沒品質可選）**：只三色（綠 = 1×1 一般 AD／14-bit、黃 = 快速 AD 或 2×2、紅 = 3×3 以上）；
  每個 fps 只顯示最好的一色；品質選項只剩「畫質優先 / 低果凍」且只在兩者不同時出現；RWZM 比例分母 > 5 時提示最近的乾淨裁切尺寸，不另分級。
- 品質先只用捲簾（RS）區分（使用者 10-22：專案交給我做，先讓所有配置都能測，畫質實測之後再做）。
- 實作（2026-10-22）：`readout_cfg.py`（唯一規則來源：10 種讀出 × 格式寬 × 下限 × 視窗中心；`plan()` 產生完整設定），
  `readout_plan.py`（options / matrix / plan；含錄影合法性 = notes/ISP_SIZE_RULES.md：Z、rec 矩陣、16/10 邊、錄影 fps 清單、資料率），
  `readout_validate.py`（上機三項檢查，結果寫 captures/readout_validated.json，規劃器讀它標 verified），`readout_batch.py`（批次，每組一次開機）。
  `readout_gen.py` 為舊版，已由 readout_cfg 取代。
- 已知：錄影路徑不做接收端裁切（錄影窗 = 模式光柵）→ 非原廠光柵要錄進卡需把設定烘進虛擬模式列（TIM 首末列/寬），下一階段。
- **輸入**：位元（14 / 12 / 12 快速）、合併（1×1 / 2×2 / 3×3 / 3×6）、輸出寬高、目標 fps、優先（品質 / 低果凍）。
- **規則**（已實測）：
  - HMAX 下限：14-bit ≈ 860、12-bit 一般 ≈ 445、快速 ≈ 320（2×2 快速 330）。
  - VMAX_min ≈ 影像列 + 46 + 2·`0016`；fps = 72 MHz /((VMAX−1)·HMAX + tail)，tail 可做 1 個時脈（13.9 ns）的微調。
  - 1×1 快速：TIM 行長 = 接收端寬 + 4、DCLP（R38 +8）= 寬/12 + 1；垂直裁切 `0003/0022–0025`；水平裁切走接收端（12 px 單位）。
  - 3×3（mode 8 系）不能開感光元件窗（停輸出）。
- **產出**：從最接近的原廠列（donor）複製七張表 + REG 列，改上述欄位 → `vmode.apply`。
- **里程碑**：
  1. 離線產生器 + 預設表（例：4K 低果凍、1080p 120/192、條帶 500/1000 fps）。
  2. 每個預設自動上機驗證（曝光線性、接收列數、連拍無掉幀，`vmaxreal.py` / `hs11.py --burst` 的做法）。
  3. 接到 sup：選擇存自己的檔案，開機在 RAM 套用（loader v4）。
- **未知**：錄影鏈（RWZM / 編碼 / 寫卡）能否接受非原廠尺寸與幀率——第一個上機風險，先用一個預設試錄。

## D2 自動防閃爍
- 原廠已有 AeFlicker（50/60 Hz 偵測，`ae flck` shell 指令，RULES §57）。兩個方向待選：**優化原廠 P 模式**（換成實測頻率、細調快門）或**加自己的模式**。先查 AE 如何使用 flck 狀態（離線）並用唯讀指令確認。
1. **偵測**：一張短曝光（≈100 µs）÷ 一張全幀 → 燈的波形、深度；有閃爍就提示。
2. **快門對齊**：曝光取燈週期的整數倍（120 Hz 燈：8337.5 µs 的倍數）；SHS 以 2 列為單位（HMAX 450 時 12.5 µs）。
3. **幀率鎖定**（快門短於週期時）：量相位漂移 → 調 VMAX / tail 讓幀率 = 燈頻 / k，每幾秒閉迴路修正（市電會漂）。
- 里程碑：先做 PC 端原型（現有 flicker.py），再搬到相機（每幀列剖面的計算量很小）。

## D3 RAM 高速連拍
- 現況：IMXB `frame_cb` 只有 16 個緩衝 / 64 筆時間 → 擴成環形緩衝（N 個、循環覆寫、觸發後停止）。
- 待量：配置器一次能給多少記憶體（決定秒數：3032×160 每幀 855 KB → 1 GB ≈ 1.2 s @1029 fps）。
- 存檔：停止後寫卡成 DNG 序列（SD ≈ 94 MB/s，1 GB ≈ 11 s）或 USB 拉出。
- UI：觸發（按鍵）、預錄（觸發前 N 幀）。

## D4 低果凍 1×1 快速模式
- 先決：D1 的 1×1 快速預設 + 錄影鏈接受 4160 寬（RWZM 縮放到 UHD / FHD）。
- 品質代價：快速 AD 雜訊（待量，§40 的方法），寫進選單說明。

## D5 14-bit + 棋盤 HDR 錄製
- 錄 14-bit 棋盤 RAW（29 fps 上限）→ PC 合成工具（hdr_ml.py）收尾：高光色度降噪、校正曲線網格、14-bit 冷像素門檻。
- 機內合成（緩衝 V 列 + 查表）列為後續研究，不在第一版。

## 共同驗證規範
- 幀率與曝光一律用「代換 SHS + 鎖增益 + 固定快門 → 位準對 VMAX 線性」驗證；連續性用 frame_cb 連拍時間戳。
- 每個預設要有一組「原廠對照」同場景量測（雜訊、MTF、捲簾）。
- 上機：直接寫入先證明能出圖，才可經模式切換（RESWEEP_DESIGN §9）。
