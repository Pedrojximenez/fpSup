# ISO 依格式切換 HCG 與讀出設定(離線逆向,2026-10-22)

韌體 5.02,`out/MAIN_c0000000.bin`;行號指 `out/decomp/full/blk_c0X.c`。
[C] = 看過反編譯或映像資料;[M] = 實機量測(§60 `captures/isomap/isomap.json`);[I] = 推論。
上游完整 gain 筆記:`research/imx410/notes/ISO_FIRMWARE_COMPLETE.md`(本篇補上「誰設 gain_state」與「讀出切換」,並訂正兩處)。

## 0. 結論

1. **HCG(05E1)只由 `gain_state` 決定門檻**。錄影開始時依格式設定 gain_state,即時預覽一律是 0。
   → 使用者說的 12-bit = 100/3200、拍照與 8-bit = 100/640 **都由程式碼重現**;**10-bit = 100/640**;HDMI RAW = 100/3200;MOV = 100/640;即時預覽 = 100/12800(OTP 門檻)。[C]
2. **ISO 不會改變感光元件模式 id**。錄影的模式表只用「解析度+格率+EIS+CROP+位元深度表」查詢,沒有任何增益輸入。[C]
   「依 ISO 切換的第二種讀出」其實是 **0x05E2/0x041F 的高類比增益讀出**:類比碼 ≥ 0xDFD(≈18.03 dB)時開啟,與 HCG 無關。[C+M]
3. 預覽看不到 640/3200 切換的原因:**預覽時 gain_state = 0**,v30 改用 OTP 門檻 `S+0x84`(本機介於 rel 11697–14976 之間 → ISO 12800)。[C+M]

## 1. HCG 決策 —— `XC_ImageSensorIMX410::v30` @ 0xC03239C8(vtable 0xC0B5FCC0 +0x80)[C]

```
hcg = 0
if S+0x78 (OTP CG 致能):
  st==0            : hcg = (S+0x84 < rel)                 // 預覽,OTP 門檻
  st∈{1,2,3,5,6}   : hcg = (FUN_c00b8860(640)  <= rel)
  st==7            : hcg = (FUN_c00b8860(3200) <= rel)
  st==4 或 ≥8      : 不切
if G+0x37 (imager high_gain_off): hcg = 0
```
- `rel` = AE 的相對增益 = `FUN_c00b8860(ISO)`。曲線 @ROM 0xC0746728(11 點):`{100→117, 200→234, 400→468, 800→936, 1600→1872, 3200→3744, 6400→7488, 12800→14976, …}` = ISO×1.17 線性內插。[C]
  → 640 門檻 = rel 748 = 剛好 ISO 640;3200 門檻 = rel 3744 = 剛好 ISO 3200(用 `<=`,所以該檔本身就是 HCG)。[C]
- 預覽門檻 `S+0x84` 是 OTP(`FUN_c03344b0` 讀感光元件校正區 0xC00/0x1FE)。實測 ISO 10000(rel 11697)LCG、12800(rel 14976)HCG → `11697 ≤ S+0x84 < 14976`。[M]
- 呼叫順序:`FUN_c0312f18`(套用)→ `FUN_c03131e0`(取 gain_state;全域覆寫 `*(0xC343A78C+4)≠0` 時強制 8)→ v8 → v30。[C]

## 3. 感光元件模式是否依 ISO 改變 —— 否 [C]

- 錄影(LiveViewModeMgr key.mode = 2)由 v3 `FUN_c043be68` → `FUN_c043b828`(RAW)/`FUN_c043b988`(MOV/HDMI RAW)查表;表名 = 解析度+格率(+EIS)(+CROP),
  分表旗標 key+0x24/+0x25/+0x26/+0x45/+0x47 全來自設定區(`FUN_c0436b80`),**沒有增益/ISO 輸入**。表項 +8 = 感光元件模式。
- 同一格式三種位元深度用**同一個模式**(例:UHD30 = M7、FHD30 = M106、FHD30CROP = M107,在 5810/59B0/5B50 三表相同),只差 pid。
  所以 LOWP3/LOWP4 是「全寬/CROP」,不是低/高 ISO;F12 的 M111/M112 不在任何錄影表內。

| 格式(CinemaDNG,8/10/12-bit 同) | 模式 | CROP 模式 |
|---|---|---|
| UHD 29.97 / 25 / 24 / 23.98 | 7 / 123 / 151 / 101 | 102 / 124 / 152 / 108 |
| FHD 59.94 / 50 / 48 / 29.97 / 25 / 24 / 23.98 | 27 / 115 / 220 / 106 / 125 / 218 / 109 | 88 / 116 / 221 / 107 / 126 / 219 / 110 |
| FHD 119.88 / 100 | 58 / 89 | 103 / 118(HDMI RAW 表為 132 / 133) |

- 唯一隨曝光改驅動的是**預覽 mode 1 的 AF 碼**(`FUN_c0257ee8` 依 AE 程式表切 MOVAF30/60/120…,模式 3/8/0x38),那是依亮度,不是 ISO,且錄影不用。[C]
- 拍照表的 `LOW` 後綴 = 低解析度(3008×2000 或 1920×1280,`FUN_c043bdb0`),也不是 ISO。[C]

## 4. ISO 相關的其他暫存器 —— `v10` @ 0xC0323818(只在 `FUN_c03258b0()==0` 時寫)[C+M]

| 條件 | 0x05E1 | 0x05A6 | 0x05A8 | 0x05E2 | 0x041F |
|---|---|---|---|---|---|
| LCG,類比碼 < 0xDFD | 0 | 0x29 | 0x27 | 0 | 0x00 |
| LCG,類比碼 ≥ 0xDFD | 0 | 0x29 | 0x27 | **1** | **0x0E** |
| HCG,類比碼 < 0xDFD | 1 | 0x2A | 0x29 | 0 | 0x00 |
| HCG,類比碼 ≥ 0xDFD | 1 | 0x2A | 0x29 | **1** | **0x1D** |

0xDFD = 4095·(1−1/7.966) = **18.03 dB**。§60 預覽實測:ISO 1000(0xD91)→ 05E2=0,ISO 1250(0xE0D)→ 05E2=1/041F=14,HCG 段 041F=29 —— 全部吻合。[M]

## 5. 各 gain_state 的 ISO → 暫存器(模擬)

`offline/iso_state_sim.py` 照搬 v30/v31/v8/v10。OTP 量(參考碼 1.03 dB、HCG 偏移 14.41 dB、類比上限 29.97 dB、預覽 S+0x84)由 §60 擬合;
**預覽 25 個 ISO 的類比碼、HCG、05E2、041F、溢出數位增益全部吻合(0 筆不符)**。錄影各 state 是同一套程式碼換 state 推出來的 [I:假設錄影用相同的參考碼 `0xC3074950` 與 S+0x96 重映射]。

v31 是「數位分攤」:回傳數位 %(ISP 端,AE 數位狀態 0xC320209C),**類比只拿 rel/數位**。三種錄影 state 的差別就在這張分攤表:

| 200 | L 8.41 | L 2.39(數位 2×) | L 8.41 | L 2.39(2×) |

- **05E2 開啟點**:預覽 ISO 1250;拍照/MOV/8/10-bit ISO 6400;12-bit ISO 25600。[I:模擬]
- **12-bit 在 ISO 100–800 類比完全相同**(2.39 dB),差距全由 v31 數位(最多 8×)承擔;ISO 3200–5000 類比也幾乎不動。這是 12-bit 走「雙原生 100/3200」的實際形狀。[C:v31 程式碼;I:數位是否寫進 RAW 未驗]
- v31 只在 OTP `S+0x95≠0` 時啟用(預覽 200–400 類比不變 = 本機已啟用 [M])。

## 6. 訂正

- 舊筆記說 v31 的 `+0x95/+0x96/+0x98…` 屬於「另一個 sensor-manager 物件」。**錯**:`FUN_c0322020` = `*FUN_c0322e48(0)` = `G[0]` = **S**(OTP 結構),
  `S+0x94` 那個字的 byte 1/2 就是 +0x95/+0x96,`S+0x98/+0x9C`(預覽兩點)與 `S+0xA0/+0xA4` 都由 `FUN_c03344b0` 從 OTP 讀入。[C]
- 舊筆記把 v31 寫成「把 rel 往下對齊到節點、殘差給數位」。實際是**分段線性的數位倍率表**(例:st7 在 800–1600 恆為 8×、2500–3200 恆為 5×),類比 = rel ÷ 數位。[C]
