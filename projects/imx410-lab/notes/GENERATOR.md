# Sensor mode creator：參數與規則（2026-10-23）

程式：`readout_cfg.py`（讀出類別 + `plan()`）→ `smc.py`（產生 8 張表）→ `smc_validate.py`（韌體切換驗證）。
規則出處：IMX410_RULES（§ 號）、MODE_TABLE_RULES、`offline/mode_rules.py`。

## 1. 使用者輸入（`plan(key, cw, ch, ow, oh, fps, v016, hmax)`）

| 參數 | 意義 | 規則 |
|---|---|---|
| `key` | 讀出類別（§2 表） | 決定 AD、合併、格式碼、HMAX 下限 |
| `cw × ch` | 裁切（感光元件像素） | 換成合併後的格子：`sw = cw/mh`、`sh = ch/mv` |
| `ow × oh` | 輸出解析度 | 不能放大（`ow ≤ sw`、`oh ≤ sh`）；剩下的比例交給 RWZM（`rwzm = sw/ow, sh/oh`） |
| `fps` | 幀率（省略 = 這個設定的最高） | `VMAX = 72 MHz / (HMAX·fps)`，必須 ≥ 最小幀長 |
| `v016` | 垂直空白（0016） | 預設用類別值；只能低到實測過的下限 |
| `hmax` | 線時間 | 不能低於類別下限 |

## 3. 規劃規則（`plan()`）

1. **格式**：取寬度 ≥ `sw` 的最小格式；超出 0.5% 以內就把裁切修到格式寬（例如 3×3 的 OG）。
2. **垂直視窗**（只在 `sh` 小於全高 `4040/mv` 時）：`H = ceil(sh/2)`，視窗涵蓋 `2H·mv` 個感光列，以第 2080 列為中心，起點取最近的 **≡ 1 (mod 4)**，而且必須落在 56..4104 之內（§64）；寫入 `0003=1`、`0022/23` = 起點、`0024/25` = H。
3. **全高列數上限**（實測，SMC_VERIFY 第 14 輪）：原廠合併讀出影像固定 4032 感光列 → 2×2/垂直 2 合併 2014、3×3 1344、3×6 672；新 V3 類別（3 取 2）讀到 4074 感光列 → 1358（光照＋暗場 24/24，第 16/17 輪）；不做垂直合併（含水平 2/3 合併）4042（計畫用 4040）。全高時輸出列可超過 4040/v，以這個上限為準；要求更多會報錯。
4. **列數**：`接收列數 = 輸出列數 + over`（over 依類別實測）；`VMAX_min = 接收列數 + 2·0016 + 12`。
5. **時間**：`fps = 72 MHz/(HMAX·VMAX)`；`捲簾 = HMAX·接收列數 / 72 MHz`。線時間由 AD 等級鎖定、與寬度無關（§42 §45），所以提速只能少讀列或換快速 AD。
6. **寬度**：接收端寬度 = `ceil(sw/12)·12`（水平裁切由接收端做，不會縮短捲簾）；記錄寬度是 16 的倍數。
7. **快速 AD**：寫入 Family A 快速組（原廠 8 對 139 的差異）；窄格式的 TIM 行長 = 格式寬 + 4（§49）。
8. **新類別**：先寫它們的暫存器組（V2 / V3 / 配對組 / 0058），再寫格式碼；`0003=0`（全高）。

## 4. 產生表（`smc.create`）

8 張表的每個欄位都由規則算出，重建原廠 70 個模式時 22,750/22,750 全部相同（`smc.py selftest`）：
- **82 個明確公式**（`mode_rules.EXACT`）：
  - **TIM**：HMAX、tail、VMAX、接收窗 x0/x1/y0/y1
  - **META**：尺寸、合併方式、`vadd`、位元數、fps、HD 旗標、全寬旗標、`2·0016`、類別
  - **R14**：快門邊界，依 vbin
  - **R28**：AE/AF 16×16 格網，覆蓋約 95%
  - **R38**：DCLP 窗與 OB 區帶，依 vbin
  - **R68**：壞點表 id、裁切窗、座標換算型別（h2/v2 → 7、h3 → 2、v3 → 1、v6 → 3）、y 偏移（新類別 v2 → 2、v3 → 66，G7 暗場熱點實測）
- **116 個常數**。
- **126 個 REG 類別查表**：先取同 AD 原廠類別的感光元件暫存器值（14 → 16、12 / 快速 → 17、原廠合併類別 → 自己），再把規劃的感光元件寫入（格式碼、視窗、空白、新類別的暫存器組、快速組）覆蓋上去。
- **新類別的屬性**：`cls` = 它的 AD 類別；`y0` = 第一個完整影像列對（韌體切換、0018 關實測：垂直或混合合併 20、h2 40、h3 20）；全高列數上限見 §3 第 3 條；R68 y 偏移 v2→2、v3→66（G7）。

## 5. 每個生成模式附帶的特性

- **row_phase**：偶數垂直合併時，每一對的第二列偏 −1/vbin 輸出列（2×2 為 −0.5）；奇數合併為 0（§65）。後製要靠它修正。
- **捲簾與最高 fps**：由規劃輸出。
- **黑位**：原廠類別要和同類原廠模式比，固定增益下差 ±2/±3 DN；新類別用 SMC_VERIFY 第 12 輪量到的自己的參考（h3、14-bit 仍用 4/10 DN 上限）。
- **壞點表**：原廠合併類別用自己的表；新類別指向表 97，加上裁切、型別與 y 偏移；換算結果與暗場熱點吻合 97–98 %（同原廠，SMC_VERIFY 第 11 輪）。韌體在預覽/錄影時是否真的換算，要由 res-custom 安裝時確認。

## 6. 驗證狀態

| 層 | 原廠 10 類 | 新 14 類 |
|---|---|---|
| 第 1 層：直接寫入（列數、Bayer、列相位、線性、連拍） | 過 | 過（§67） |
| 韌體切換（smc_validate 光照） | 254 + 88 組過 | 12 類過（12-bit 10 + 14-bit 2）；h3 只限低增益 |
| 韌體切換（暗場黑位、每列） | 254 + 88 組過 | 12 類過（12-bit 78/78、14-bit 14/14）；各類自己的黑位參考 |
| 垂直裁切（視窗） | 過 | 未測（只能全高） |
| 壞點表（G7） | 原廠表（熱點 96–99 %） | 12-bit 5 類 97–98 %、14-bit 2 類 96.5–97.4 % |
| 錄影（ISP / res-custom） | 他方負責 | 他方負責 |
