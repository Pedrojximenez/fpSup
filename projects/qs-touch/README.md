# fp Touch QS

2026-10-22 更新。依本次使用者指定，以 QS 為第一個觸控與效能優化範圍：
從頂端下拉、長按重排、在 QS 內直接添加項目。

目前交付是**互動原型與獨立 C 手勢核心**，沒有載入相機、修改共用 loader、
寫入卡片或改變拍攝設定。ARM 產物只是未連結的物件，不能當 sup 安裝。
瀏覽器操作與數值都是示範；未建立瀏覽器與相機之間的連線。

## 操作決定

- LV 頂端 32 px（座標以 1024×682 計）開始下拉；面板位置跟隨手指，
  放手拉開至少 180 px 則展開，否則收回。這些是可調整的起始值，未作相機體感驗收。
- 僅頂端起始接觸由 QS 接管；其餘 LV 接觸仍交給原廠對焦／放大。
  一旦接管，整段接觸都不可再轉送 LV，即使手勢取消。
- 普通項目點按後只選取，在同一頁下方的調整列改值；不再逐項開另一頁。
  開關類項目直接切換。C 核心只發出啟用控制項的意圖，實際值與 setter 由原生擁有者處理。
- 瀏覽器一般 QS 在內容區上滑會收起；DC／RES 更多選項在欄位或空白區上滑則返回主 QS，保留設定。
  橫向翻頁或調值已鎖定、長按排序中不轉成上滑導覽；原生數字輸入與滑桿仍接收自己的輸入。
- 下方選項可直接點按，也可左右拖動：左推往下一個值、右推往上一個值，跨過半格就即時更新上方數值，
  放手後對齊中間選取框。上下拖動不改值，不會觸發 QS 翻頁；到數值兩端停止並給予少量回彈。
  拖曳取消則還原此段拖曳前的值，成功放手才合併保存。箭頭按鈕及鍵盤左右鍵仍可逐步調整。
  此選值手勢由預覽呈現端處理；相機端仍需獨立調值控制器，尚未實作在 `qs_touch.c`。
- 在項目或空格上左右滑動翻頁：水平移動超過 18 px 且為垂直的 1.5 倍時鎖定翻頁，
  放手至少移動 80 px 才換頁。第一／最後一頁不循環。
  翻頁不得啟用項目、修改值或更動排序；下方數值控制區不作 QS 翻頁。
  中間分隔橫線固定在面板上；僅八格項目容器跟隨左右拖動。
- 480 ms 長按進入編輯；容許移動 12 px。長按後同一段水平移動優先排序，
  不會被認成普通翻頁。長按與排序不發出拍攝設定變更。
- 編輯後直接拖曳排序，目標格以插入方式讓位；瀏覽器在放手後立即保存並回到一般 QS。
  系統中斷接觸只還原此次拖曳前順序，已成功放手的排序不回復。
- 排序時下方出現垃圾桶，拖入後提示「放開移除」，放手即從 QS 移除並保存；可從「＋」加回。
  跨頁拖曳由呈現端在邊緣停留後切頁。核心允許拖曳期間呼叫 `qs_page`。
- 「＋」直接開啟可添加功能清單，排除已存在的功能。添加後立即保存並回到新項目所在頁，
  可直接操作項目。每頁八格；核心預留 24 格，目前示範目錄有 21 種功能。
- 瀏覽器移除「取消／完成」，QS 鍵直接開／關。C 核心仍保留舊的編輯交易 API，未接收 v10 的保存政策。
- 雙指、失去接觸、離開畫面等取消事件不得被轉成點按。
  相機輸入轉接器在多指取消後必須等所有手指離開才重新接收。
- 原型亦可用 QS 按鈕開啟、鍵盤 Tab 選項目、E 進入編輯、方向鍵排序並即時保存、Esc 返回。

## 程式與效能邊界

`core/qs_touch.c` 是純 C11、固定容量、沒有 heap 配置、檔案 I/O、韌體位址、
鏡頭／錄影指令或設定 setter。每個事件最多移動 24 個一位元組項目 id。
渲染器、檔案儲存與原生設定的執行者不在此核心內。

`QsLayout` 的 id 是本專案穩定識別碼，**不是原廠 QS UI id 或 internal id**。
相機持久化應採自己的版本化設定檔，逐欄序列化並檢查版本／長度／校驗；
不要直接保存含 padding 的 C struct，更不能把新 id 寫入原廠設定區。
本輪只有版面提交結果，尚未實作相機設定檔與原子替換。

原型沿用八格幾何，v14 恢復 v7 的滑動翻頁、手勢方向、距離／速度判定與 Mac wheel 輸入規則，與 C 核心的舊 80 px 換頁門檻不同。
v10 瀏覽器亦改為排序放手即保存，與 C 核心的舊編輯交易語意不同。
它是另外撰寫的瀏覽器展示，
沒有執行 C 核心，不能用它宣稱 ARM 的實際效能或韌體畫面正確性。

2026-10-21 修訂：參照既有 [QS 畫面](../open-gate/build/restore_entry_test_20260923/SS__0972_early_QS.JPG)
的四欄兩列、白色標籤／數值、青色選取框與下方調整列，移除前版圓角卡片及全頁數值選擇器。
此為原廠風格互動原型，沒有聲稱重用所有原廠 XCI 或像素級還原；觸控抽屜仍增加頂端操作列。
格子範圍為 x=0..1023、y=110..533；下方調整列與底部把手分區。
依使用者已操作的狀態，預覽保留 ISO、快門角度、光圈、解析度、格率、錄影格式、白平衡、
音訊增益、假色的九項順序。可讀舊版狀態，之後保存為版本 3（新增背景設定）；不在載入時回寫。

### 背景與即時回饋修訂

頂端「背景」在同一個底部調整列開啟滑桿，拖動立即顯示背景變化，不等放手或儲存。
提供符合原生 ARGB4444 的 16 段 alpha（0..15），畫面換算顯示 0..100% 不透明度。
0%／「關閉」隱藏唯一背景遮罩且清除其填色；中間值只繪製一層黑色半透明背景；
100% 使用實色。格子、選取格及底部調整列不再各自疊加半透明底色。
背景關閉仍保留文字、分隔線與選取框；這不等於關掉整個相機 OSD 硬體圖層。

`core/qs_appearance.c` 提供獨立的背景繪製計畫：0 跳過 fill、1..14 一次 blend、15 一次 opaque fill。
它尚未接入相機渲染器；整合時 alpha 改變必須先使整個面板背景失效，清除先前的像素並重畫前景，
不能在保留舊 framebuffer 的情況下僅停止後續 fill。文字及實際狀態仍由原生執行者處理。

預覽的取景底圖來自專案既有的
`projects/open-gate/build/angle_fps_camera_20260915_verified_modes/fhd_qs2_iso800_2997_angle180_idle.jpg`，
以 CSS 裁切避開原畫面的 OSD，內嵌原始 JPEG；它是靜態照片，不是相機直播，也不模擬曝光效果。

為減少操作卡頓，預覽已改為：

- 每個接觸只讀一次畫面尺寸（選值／添加清單手勢另讀一次對應容器寬度）；移動事件每幀合併，只保留最新位置，放開仍同步處理最後座標。
- 拖曳與翻頁使用位置變換；拖曳排序僅跨格時重算版面，翻頁跟手顯示相鄰頁。
- 下方五個選項按鈕常駐重用，其中三個可見、兩個預留在裁切區外供拖動；未變動的文字不回寫，不在每次移動時重建調整列。
- 數值先更新格子並短暫以青色提示，再延後合併保存狀態；背景拖動同樣立即呈現。
- 展開收合為 100 ms、底部選值列歸位 110 ms；手指翻頁使用連續的位置與速度計算，遵循減少動態效果設定。

這些是已實作的瀏覽器呈現改善，尚未量測原型 fps，也不能推論相機效能已改善。

### 翻頁放手銜接修訂（v5，主頁已由 v6 取代）

移除先更新頁碼／格子座標、清空容器位移，再另起一段 110 ms 動畫的流程。
現在放手保留最後位移，最近 80 ms 的移動決定初始速度，使用 `qs-motion.js` 的臨界阻尼解析解逐幀延續；
每幀只改同一個容器的位移，到位後才在同一幀重定位格子、更新頁碼與選取狀態。
低於 0.25 px 且速度低於 0.008 px/ms 時完成，另有 700 ms 的收斂上限。
這些是原型的呈現參數，並非相機輸入或 LCD 延遲測量。

動畫途中再次按住項目區會保留當前位置並交回手指，支援反向拖動；短滑或頁面邊界以同一機制回彈。
添加清單也改用同一套翻頁流程，預先建立相鄰頁，在滑動時不重建選項。
底部選值手勢保持獨立；按鈕及鍵盤翻頁仍直接切換。

`python3 build_preview.py --qa` 另建立 `preview/qa-direct.html`，只在此 QA 包裝開啟逐幀紀錄。
正式對話顯示的 fragment 不記錄逐幀資料；QA 記錄可從根元素的 `data-qs-motion-trace` 讀取。
`tests/test_qs_motion.js` 測試放手位置及速度連續、更新間隔獨立性、反向速度、有限時間收斂與過期速度清除。

### Mac 水平捲動修訂（v6，吸附已由 v7 取代）

依使用者補充，主要在 Mac 測試 QS 左右翻頁。前版只接收 pointer 按住拖曳，沒有真正可水平捲動的容器，
漏掉了觸控板雙指水平捲動這條輸入路徑。主頁現在使用 `overflow-x: auto` 與 CSS Scroll Snap，
不攔截原生 wheel 位移；被動監聽只同步頁碼與選取狀態。垂直捲動及縮放不被轉換成翻頁。
這是瀏覽器原型的 Mac 輸入處理，並非相機端的原生圖層或觸控輸入實作。

各頁常駐在固定的頁面容器中；捲動只改變可見範圍，翻頁時不重排格子座標，也不再隱藏或重建相鄰頁。
中間分隔線仍固定在外層。頁面到達整頁位置即同步控制列，捲動結束通知另有相容性回退。

按住拖曳仍受支援：超過 4 個畫面像素才辨識水平拖動，之後直接跟隨指標更新捲動位置；
慢拖超過半頁才換頁，快速撥動按最後速度判斷，強烈反向會回到原頁。
放手使用有界、單向的緩出，參數為 110..240 ms，不再讓主頁以彈簧拖尾；原生觸控板慣性由瀏覽器處理。
這些參數及自動化輸入不能代表實際 Mac 觸控板的主觀手感驗收。

底部調值、長按排序與添加清單保留原流程。`qs_touch.c` 尚未接收 wheel，也未移植新的主頁翻頁規則；
不能把 C 的離線手勢測試當成本版 Mac 翻頁的驗證。新的指標判定及緩出有獨立測試，瀏覽器另實際測試水平 wheel、
垂直捲動不翻頁、短拖回原頁、快速撥動換頁，以及排序／取消。

### 放手立即快速吸附（v7）

依使用者實測，v6 仍有放手先停頓、再慢慢吸附的感受。主頁停用 CSS Scroll Snap，
水平 wheel 與按住拖曳改用同一套 55..110 ms 的單向緩出。
緩出一開始就有朝目標的速度，之後只減速；不再從零速加速。
小於半個畫面像素的殘餘位移立即完成，避免肉眼已到位卻仍在等待收尾。

指標放開時不把相同位置的 pointerup 重複樣本混入速度；真的停留至少 64 ms 才清除舊速度。
短拖仍回原頁、快速撥動仍換頁。重新按住可保留當前位置接手，底部調值與添加清單保持原流程。

水平 wheel 由非被動監聽器接收並直接更新位置，垂直輸入及 ctrl 縮放保留給瀏覽器。
在下一個畫面更新檢查輸入是否暫歇至少 16 ms，直接啟動快速吸附；起始時間回溯到最後輸入，
同一幀消化已經過的時間，沒有額外等待 scrollend 或 120 ms debounce。
同一次 wheel 手勢完成後不再讓慣性尾段啟動另一頁；反向輸入或間隔超過 160 ms 才開始下一段。
120 ms 相容性計時器僅清理捲動狀態，不啟動吸附。

`tests/test_qs_motion.js` 另檢查零速放手的下一個 16 ms 更新至少完成四分之一剩餘距離、
吸附單向減速、有界完成，以及放手相同位置與實際停留的速度差異。
直接預覽以真實座標拖曳及水平 wheel 驗證；QA 包裝另提供固定時間的合成 wheel／尾段回放，
檢查第一幀有位移、全段單向及只提交一次。逐幀資料存於 `validation/quick-snap-v7.json`。
這些是瀏覽器寫入與回放證據，仍不等於使用者實際 Mac 觸控板的主觀手感或 LCD 顯示延遲測量。

QS 呈現的目標：

1. 常駐的 QS 資源及文字，不在每次手指移動時解析 NBU、解壓 XCI 或建立元件。
2. 移動事件每幀取最新座標；按下／放開／取消保序且不得丟棄。
3. 下拉用容器位移或圖層呈現，避免每幀更新原生 955 物件的整棵 QS 樹。
4. 預先準備卡片背景／字形；排序只更新卡片位置與必要區域。
5. 先量 LCD 掃描與 commit 時序再選更新頻率。60 fps 是目標，不是現有效能。
6. 錄影模式分別驗收回應性與錄影穩定性；尚未決定錄影中編輯功能的政策。

## 相機端接點與下一個必要工作

| 層 | 已有證據 | 本輪未完成 |
|---|---|---|
| 觸控資料 | `XC_TouchPanelMgr`、`C04456E8` 解出兩組座標；`TouchOperationObserver::v1` 送出 0x1D 事件 | 接觸旗標語意、取樣率、DOWN/MOVE/UP/CANCEL 轉接、單一事件擁有者 |
| 原生 GUI 輸入 | `UicContentsIfBase::v2 C06D1550` → `C055DC38` → GUI queue | 確定在原廠觸控 AF 之前辨識頂端手勢且不重送 |
| QS 頁面 | [CUSTOM_QS.md](../../research/ui/CUSTOM_QS.md) §10 的 Q1，沿用 GUI id 159 與原生訂閱 | 下拉拖曳時適合的容器／圖層位移接點；既有必要物件的保留與生命週期 |
| 設定調整 | 同筆記 §8／§12 的 app 變數、converter、原生 setter、EXCL | 為每項功能建立正式能力表；相機實際值回讀及失敗回復 |
| 擴充功能 | RES/FPS/FMT 可使用私有變數 | 自訂格式的編號保存在私有設定；原廠設定僅接收合法 donor 值 |
| 執行環境 | sys-perf 已確認非快取執行的問題 | 先確立有界、cache-line 對齊的程式／私有資料擁有權，DMA 分離，避免在慢別名跑新互動核心 |

Q1 仍適合保留原生設定行為，但「每次手指移動都驅動整棵原生頁面」未被證明足夠快。
先做頂端手勢的離線事件回放與單一項目的位移／調值驗證，再決定沿用原生容器
或使用獨立輕量 drawer。此評估不授權操作相機或部署。

點假色直接 OFF→ON；右滑返回；長按後水平拖曳仍為排序；添加清單左右翻頁後可加入水平儀。
320 px 畫面保留每頁六項的添加清單與獨立底部調整列。

2026-10-21 選值拖曳修訂：使用同一份 fragment 的直接預覽，實際拖動確認 ISO 800→1600→3200→6400、
反向減小、上限停止、垂直拖動不改值、光圈 F2.8→F4、假色 OFF→ON，以及點按與鍵盤相容。
QS 左右翻頁前後分隔線位置不變，父層是固定面板而非移動項目容器；下拉及長按排序／取消亦已回歸檢查。
底部選值的瀏覽器取消／多指情境仍未實際操作；還原邏輯已實作但需觸控裝置再驗。

v5 的放手銜接曾實際記錄：720 px 寬的 QS 在放手及接觸清理後都維持 −350 px，下一幀繼續到 −382.98 px；
滑入到 −720 px 後才切換頁面座標，切換前後實際相對位置一致。328 px 寬度亦確認連續。
反向重新接手及添加清單翻頁有各自的追蹤紀錄，保存在 `validation/*trace-v5.json`。
這些保留為舊版證據，不能作為 v6 主頁或 Mac 觸控板的手感驗收。

v6 的直接預覽另實際確認一個水平 wheel 輸入就能將捲動位置從 0 改為 704，頁面從 1/2 變為 2/2；
全程沒有 pointer 拖曳更新或按下幾何讀取，假色保持 OFF，分隔線位置不變。資料在 `validation/mac-native-scroll-v6.json`。
內嵌包裝的版面及按鈕導航已驗證；本機 UI 自動化未將 wheel 送進該 iframe，因此仍需使用者在實際對話預覽中檢查 Mac 雙指滑動與慣性。

## FORMAT／DC／RES 的內容與就地自訂（v8，比例行為由 v9 更新）

2026-10-22 使用者確認 FORMAT 為五個選項：MOV、CDNG 8bit、CDNG 10bit、CDNG 12bit、CDNG 14bit。
DC 提供 OG、HD、S35、APS-C；RES 提供 1K、2K、3K、3.5K、4K。
DC=HD 時將 2K／4K 顯示為 FHD (2K)／UHD (4K)，預覽輸出分別為 1920×1080／3840×2160。
FPS 本次沒有新增需求，保留現有選項，沒有按新格式推算任何實機可用格率。

選中 DC 或 RES 時，下方顯示「更多選項」。按下後僅刷新既有 QS 的格子：
DC 留下「DC、裁切寬度、裁切高度、比例」，RES 留下「RES、解析寬度、解析高度、比例」。
原本的 DC／RES 預設選擇格持續可用：用戶把尺寸改亂時，直接選常用預設就會還原對應寬高與比例，仍停在同一個自訂 QS。
共用同一個面板、背景、底部調整列與返回操作，沒有網頁／全頁導覽，也不修改使用者的 QS 排序。
數字可以直接輸入、以滑桿拖動或箭頭逐像素調整；比例仍用原本可拖曳的底列。
固定比例時改寬度會算高度、改高度會算寬度；「自由」允許分別輸入。
DC 與自訂 RES 分開保存，改 DC 不會覆寫已自訂的輸出尺寸；未自訂 RES 則依 DC 比例重算高度。

資料模型在 `preview/qs-recording.js`，與手勢核心分開。
目前 DC 的範例幾何為 OG 6000×4000、HD 6000×3375、S35 4000×2250、APS-C 4000×2667，
非 HD 的 K 寬度為 1024／2048／3072／3584／4096。**這些是互動示範資料，不是 fp 實機能力表或已驗證的感測器窗口。**
數字輸入的 1..16384 是預覽的資料驗證上限，不代表相機支援任意尺寸、奇數像素、RAW14 或所有位深／格率組合。
接入實機時必須由模式資料提供窗口、像素對齊、格式與 FPS 限制，不能直接寫原廠設定。
靜態取景照片本次沒有按 DC 或 RES 作影像裁切模擬。

狀態保存升為版本 4，額外保存 recording 的格式、DC 與 RES；可讀舊版 DNG／FHD／UHD 的選取值。
DC 使用新的穩定 id 20，沒有重新編號原有項目；舊版版面在 FORMAT 後插入 DC，並保留波形及既有排序。
可攜 C 核心只將目錄容量擴為 21，不執行瀏覽器的格式／尺寸模型。
主頁左右翻頁保留 v7，先前使用者回報的主觀卡頓仍未驗收通過；本次沒有再調整吸附。

獨立模型測試覆蓋格式、HD 別名、獨立尺寸、比例、非法值、保存／還原與舊狀態遷移。
QA 包裝以 sessionStorage 模擬 host 的狀態保存，只在離線 QA 使用；正式 fragment 不含此替代儲存。

## 即時比例、DC 自動辨識與外層 mm（v9）

依使用者後續指定，手動改寬度或高度時只修改該軸，另一軸不跟著改；DC 與 RES 的比例都從實際整數寬高重新計算。
比例欄不再停留在「自由」或舊比例；優先顯示常見比例（允許半個像素捨入及很小的相對誤差），
v9 其餘顯示約分比例、太長則用小數比一；v10 改為下述電影比例標示。只有主動選取比例時才用目前寬度重算高度，下一次手動改數字仍為獨立調整。

DC 同時比對寬高是否完全符合預覽中的 OG／HD／S35／APS-C 尺寸；符合即恢復該名稱，
不符合則顯示 `CUSTOM(實際比例)`，主 QS 和自訂 QS 的 DC 選擇格同步。
因此 6000×3375 → HD、6000×4000 → OG，但 3200×1800 雖然也是 16:9，仍為 CUSTOM(16:9)。
預設選擇格仍可隨時用來復原常見尺寸。

外層 QS 的 DC 尺寸改顯示 mm，自訂寬高仍以像素精確輸入。
目前換算將預覽 OG 的 6000×4000 對應到 [SIGMA 官方 fp 規格](https://www.sigma-global.com/en/cameras/fp/?local=table&tab=support&table_id=11934)
所列的 35.9×23.9 mm；這是原型的線性估算，並未驗證感測器實際讀出窗口、有效區／遮蔽區或像素對齊。
不得將此換算當作已量測的實機裁切面積。

保存升為版本 5，仍可讀 1..4 版。還原時以合法寬高為準重算比例及 DC 名稱，
不使用舊比例去回寫高度，避免重新載入後尺寸變動。格式、排序、背景及各自保存的 RES 尺寸保持相容。
`tests/test_qs_recording.js` 新增兩軸獨立性、四種精確辨識、相同比例不誤認、CUSTOM 標籤、mm 換算和舊比例遷移檢查。

## 放手保存、雙點與更多選項轉場（v10）

排序不再有「取消／完成」。長按後移動、放手即保存並回到一般 QS；長按原地放手也退出排序，
不會切換開關或打開更多選項。系統取消只回復該次接觸的暫時變動。添加項目亦立即保存。
鍵盤 E 與方向鍵保留為排序替代操作，每次移位保存，Esc 只退出，不回復已保存的位置。

單點 DC／RES 仍在下方調整；同項目兩次點按相隔不超過 350 ms、位置相距不超過 24 螢幕像素時，
進入同框的更多選項。拖曳、長按、其他控制項及換項目會清除連點判定；「更多選項」按鈕仍可用於鍵盤操作。

進入時原 QS 內容向下 18 px、90 ms 淡出，再換成自訂 QS，從上方 22 px、140 ms 淡入。
背景底層維持原本的不透明度，不增加一份背景交疊。轉場期間暫停內容輸入，完成後移除動畫與暫時鎖定；
QS 鍵／Esc 可中斷，避免關閉後動畫又把選項帶回。系統減少動態效果設定會直接刷新。

常見比例維持 3:2／16:9／4:3／1:1／2.39:1，其餘採兩位小數的 `寬高比:1`，例如 2048×1200 → 1.71:1、
4093×1711 → 2.39:1，不再出現 128:75 或 4093:1711。非常窄的直式窗口保留足夠有效位數，避免顯示 0:1。
這是比例的顯示方式，原始寬高仍完整保存，也沒有新增變形鏡頭的反擠壓處理。

離線模型檢查與 Mac 瀏覽器實際滑鼠事件已驗證保存、重載、單點／雙點、轉場位置與透明度、320 px 排版。
這些不代表實體觸控、多指取消或相機性能已驗收；主頁翻頁手感維持先前待驗收狀態。

## 上滑導覽與 RES 不超過 DC（v11）

普通 QS 上滑跟手收起，放手後退出；在 DC／RES 更多選項，上滑只返回原本 QS。
更多選項的欄位、空白區及底部文字選值列都支援此手勢，不必尋找底部橫槓。
垂直向上超過 8 螢幕像素、距離大於水平的 1.25 倍時鎖定；放手距離門檻依畫面高的 14% 調整，限制在 36..72 螢幕像素。
短滑會復位，取消不啟用項目；已鎖定橫向翻頁／調值或進入長按排序時不改判成上滑。
更多選項返回時內容延續向上淡出，再將主 QS 從下方帶入；一般 QS 延續面板原有收起動畫。
數字輸入與 range 滑桿保留原生操作。QS 鍵、返回按鈕與鍵盤替代操作仍可使用。

模型在所有 RES 修改、DC 修改與狀態還原後維持：`RES.width ≤ DC.width`、`RES.height ≤ DC.height`。
兩軸以像素比較，與外層 DC 的 mm 顯示分開。寬高欄位顯示各自上限，輸入、滑桿與增加按鈕同步受限；
超出的輸入立即收回上限。切換寬高欄位時先結束舊輸入，避免共用輸入框殘留前一軸的值。

RES 預設清單排除超過裁切尺寸的項目；例如 S35 的 4000 px 裁切寬度不列出本原型 4096 px 的 4K。
縮小 DC 時，自訂 RES 只截低超出的軸；原本標準 RES 若因裁切改變而超出，收回尺寸並顯示「自訂」，不再用原預設名稱。
主動選比例時會在裁切界限內配合比例縮放；手動寬高仍各自獨立。舊紀錄超出的尺寸在還原時一併收回，不在初始化時寫回。

`tests/test_qs_recording.js` 覆蓋預設過濾、各軸限制、DC 縮小、比例調整、舊紀錄及極端直／橫窗口。
Mac 瀏覽器實際座標拖曳檢查主 QS 收起、更多選項返回、短滑復位、翻頁與排序優先、底部調值及 320 px 手勢；
另檢查輸入 8000 被收回 1977／1600、滑桿上限、欄位切換、保存與重載。
這些仍是瀏覽器呈現政策，未移植到可攜 C 核心或相機；實體觸控取消與多指仍需裝置驗證。

## DC／RES 統一自訂標示（v12）

修正 RES 自訂時只顯示「自訂」、未帶比例的問題。DC 與 RES 的自訂標示統一為 `CUSTOM(實際比例)`，
在主 QS 與更多選項均分成兩行顯示；下方選值列使用相同的完整值，避免選取索引失配而變空白。
手動尺寸、DC 限制收回尺寸及舊紀錄還原都重新計算比例；標準預設仍顯示其名稱。
已檢查主頁／更多選項、切回標準預設、320 px 排版及重新載入。

## 垃圾桶移除與淡入淡出（v13）

長按拾起項目或使用鍵盤 E 進入排序時，下方調整列改顯示垃圾桶。
拖入目標會變紅並提示「放開移除」；放手才移除，拖離目標仍可繼續排序。
取消接觸還原該次拖曳，移除成功立即保存並選取附近項目；末頁刪空會回到有效頁面。
只移除 QS 入口，原有數值保留，項目會重新出現在「＋」清單並可加回。
鍵盤排序時亦可用 Delete／Backspace 或垃圾桶按鈕移除；目前版面維持非空，剩最後一項時停用垃圾桶。
目標範圍每次拖曳只讀取一次，後續用已快取範圍判定；底部垃圾桶區不觸發跨頁邊緣停留。
垃圾桶使用 host 的 Lucide 圖示與文字標籤，直接離線 QA 未供應圖示執行環境時保留文字標籤。

下滑開啟的面板透明度跟隨展開距離，放手後補完淡入。
一般 QS、添加清單與翻頁按鈕現在都使用淡出／淡入：拖動時原頁保持位置並逐漸淡出，
成功翻頁時再用 65 ms 淡出、更新內容、95 ms 淡入；短拖則淡回原頁。
不再沿用 v7 的橫向位移吸附呈現。長按排序的跨頁停留仍直接切頁，避免打斷正在拖曳的項目。
只使用既有 QS 內容層與背景，不建立第二份背景交疊。系統減少動態效果設定會直接更新。
Mac 水平 wheel 亦走同一呈現方式，轉場期間忽略尾段並延長同次輸入的去重時間。

Mac 瀏覽器實際座標拖曳已檢查移除、拖離、加回且 ISO 800 保留、第二頁刪空、320 px 操作、最後一項保護與重載。
動畫逐幀觀察檢查下滑中間透明度，以及主 QS／添加清單／原生 wheel 正反向翻頁的淡出、淡入和固定橫向位置。
舊版位移模型仍保留離線測試，不能把它當作 v13 淡入淡出的測量結果；新行為以瀏覽器證據為準。
上述功能尚未移植至 C 核心或相機，多指取消、實體觸控與主觀順暢度仍需裝置驗證。
