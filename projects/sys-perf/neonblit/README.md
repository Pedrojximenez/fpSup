目標：讓 UI 畫進 ARGB4444 OSD 圖層的那幾個最常用迴圈變快，**輸出與原廠逐位元相同**，不改任何畫面行為。
狀態：離線完成，unicorn 對拍通過。**沒有上機、沒有寫卡、沒有 commit。**
**[靜]** = 反組譯看到；**[模]** = unicorn 跑出來；**[推]** = 推論。

## 1. 先更正一件事：原廠已經有「等倍」路徑 [靜]

`UI_DRAW_CPU_COST.md` §2 寫「所有 span 都走仿射取樣」，這不對。
- 繪圖引擎依目的格式分成 6 個 driver(id 0,1,2,3,4,6),每個 driver 有 8 張 span 表(每張 16 格，以來源格式索引)。
  記錄在 `0xC2EB337C` 起，每份 0x248 B;註冊函式 `C06DD530` 以 `record[0]` 當索引放進 `ctx+0xCB30`。
- **ARGB4444 目的(OSD 主圖層)= driver 6**,記錄 `0xC2EB3EE4`;顏色轉換 `C06FB438` 輸出 A/R/G/B 四個 nibble。
  其他 driver:0 = RGB565(`C06E4xxx` 那批，筆記裡列的 `C06E4A4C`/`C06E4FFA` 屬於它)、1–4 = 各種 32bpp。
- 貼圖函式 `C06DF128` 判斷：轉換是平移/翻轉 **而且** 目的矩形等於圖片大小 → 模式 0 → `C07080D0`,
  用 **表 1(不仿射、逐列)**;否則才走表 2–7(仿射最近鄰、雙線性、透視)。
- `C07080D0` 還支援每列 4 段的 run 表(圖片 `+0x28`):每段標成「不透明 / 半透明 / 全透明跳過 / 結束」，
  不透明段用 `[r5+0x4E0]` 的 span,半透明段用 `[r5+0x4E4]`。原廠已經是「該跳就跳」的設計。
- 所以真正值得加速的是 **driver 6 的表 1**,但它仍然逐像素、每像素 12–38 指令。

| `0xC2EB3F78`(v2) | `C06FBCD9` | `nb_a4_blend` | ARGB4444 來源 source-over(0x10011;時間碼 `font_M_*` 字形) |

## 4. 正確性

`python3 -B test_neonblit.py`(約 3 秒):

  非預乘的「溢位」來源(欄位互相 OR 重疊的情況)、真實 `.xci` 圖示當目的與來源色。原廠與新版從同一份記憶體跑，

- `--mutate`:8 個故意改壞的版本(捨入、OR 改 ADD、尾巴少一像素、nibble 位移、565 常數、LUT 索引、fill 少寫一格、少存 d12/d13)全部被抓到。

## 5. 執行環境的限制(查過的)

- **TK-OS 每次換任務、每次進 IRQ 只存 d0–d15 + FPSCR**(`C0000D24`、`C0000E78`),不存 d16–d31。
  所以本檔只用 d0–d13,並自己保存 d8–d13。**任何 NEON 程式碼都不可用 q8–q15**,clang 自動向量化做不到這個限制，所以用手寫組語。
- 呼叫者是 DrawMgr(DrawThread → UIC)任務，原廠這條路本來就用 VFP(`C0617248` 有 `vstr s0`)。不在中斷內執行。
- 堆疊：最多多用約 56 B;DrawMgr 剩約 13.6 KB(tskmon)。
- 位址對齊：只用元素對齊的 `vld1.16/vst1.16` 與 `vld4.8/vst2.8`,目的只需 2-byte 對齊。

## v2(2026-10-20，離線):加 idx 7 + 「真實資料下不比原廠慢」

**起因**:v2 初版上機(只開時間碼)DrawMgr 8.6%→21.5%,時間落在 a4 的逐像素尾段。離線測速用隨機 alpha、單一長列，
不代表實機：字形大半透明、run 表把列切成很短的段(1–7 像素),每次呼叫都 vpush+框架，而尾段每像素比原廠多 ~6 指令。

**原廠事實 [靜]**
- 五個 span(idx 0/1/2/3/7)都**沒有任何 alpha 捷徑**,每像素完整計算。
- 分派器 `C06E0A94/C06E0A9A` 把同一個 `table[idx]` 同時放進 opaque-run 與 blend-run 槽(只有 LUT/0x10021 的 opaque 改用 idx+1),
  所以 ARGB4444 字形的**不透明段也走 idx 7 的完整混色**。
- `C06FBCAA` 在 idx 3(LUT blend,v1 已換)。

**改法(逐位元相同)**
- idx 7 公式的恆等式：來源 `s==0` → 目的不變;`s>=0xF000`(A=F)→ 目的 = s。純量路徑用 3 指令判斷(cmp/rsbscc/bcs),
  需混色的像素用與原廠相同的 33 指令核心 → **混色像素 = 原廠成本，透明/不透明像素遠低於原廠**。
- 寬度 <16 的 a4 呼叫完全不碰 VFP(沒有 vpush);≥16 才走 NEON,每 8 像素組先判「全 0 跳過 / 全 A=F 直接複製」。
- p32_blend、lut8_blend:寬度 <8 走不碰 VFP 的純量短路徑;p32_opaque、565:寬度 <8 走純量列迴圈(列測試放底部，同原廠)。
- 全部:rows≤0 在任何框架/VFP 工作之前就返回。

**真實資料測速(整個 C07080D0 呼叫的 unicorn 指令數，原廠→新版)**

| 同上，無 run 表(整列) | 1,030,494 | 156,235 | ×6.60 |
| p32 / 565 / lut8 各 60 個隨機場景(裁切、短 run) | 236,789 / 119,411 / 293,585 | 116,253 / 66,364 / 140,470 | ×2.04 / ×1.80 / ×2.09 |
