# uicoalesce:UI 訊息合併 / 值沒變不重畫 —— 結論：不做(2026-10-19，離線)

**沒有修補、沒有 patch.json。** 調查發現原廠已經做了「同變數合併」，而「值沒變不重畫」的上限
已被上機量測封頂在 <1% CPU,寫 hook 的風險不值得。證據腳本 `evidence.py`(全部 OK)。
**[靜]** = 反組譯;**[量]** = 10-19 上機 profiler(`projects/sys-perf/README.md` 實測 3)。

## 1. 同變數的重複更新：原廠已經合併 [靜]

- 生產者 `C059CCC8` → `C055E1E8` 只把 0x38 B 訊息 `{type=2, valtype, name*, value}` 附加到**寫入緩衝**
  (`[Q+0x2986C]`,Q=`0xC378BF30`;兩個緩衝輪替，`C055EDF0` 在鎖內交換)。
- 消費：每一輪 Gui update `C0561198` 呼叫 `C0560868` → `C055E3E8` → `C055E4B8`,**一次把整個緩衝處理完**。
  - type 2 交給 `C0563F40`:用名稱指標查 64 格的待處理表(`C0564068`),**同名就原地覆寫值**，新的才加一格;
    滿 64 個不同名稱或批次結束(`C055E7D0`)才 flush 一次(`C0563FF0` → `C055F8F0` → `C05DC778`)。
  - flush 做一次「樹走訪」(`C05D1FB8` + `C05DCCF0`,元件用位元遮罩比對變更集)，再由命中的元件處理。
- 所以時間碼影格欄位不論每秒 set 30 或 60 次，**每輪(48 ms)只套用一次、樹只走一次**。
  「在入列處合併」不會減少任何樹走訪或重畫，收益 ≈ 0。
- 佇列積壓的推論(`TIMECODE_DISPLAY_COST.md` §3)也要修正：積壓的是便宜的 0x38 B 附加，不是逐筆重畫。

## 2. 值沒變就不重畫：上限 <1% [量]

- 原廠沒有比較新舊值(`C0563F40`/`C055F8F0`/`C05ED248` 都沒有)，沒變的值也會進變更集、觸發走訪。
- 但上機量到：**所有 UI 元素關閉時 DrawMgr 只有 0.8%**(包括 CYC_DRAW 每 3 次無條件標 4 個 slot dirty、
  LV 變數反覆重發)。這就是「沒變也在做的工作」的上限。
- 有成本的元素(波形 +24.9%、時間碼 +6.6%、音訊表 +3.4%)值**每輪都真的在變**，跳過不了。
- 實作風險：要正確判斷「沒變」必須跟 UIC 的實際變數值比，而 Lua/`gui seti`/其他路徑也會寫變數;
  只靠自己的快取會在別人改過值後把應該套用的值丟掉(畫面錯)。為 <0.8% 不值得。
- 無條件標 dirty(問題 2)同理：落在同一個 0.8% 裡。

## 3. 時間碼的熱點 `C06FBD28` / `C06FBCAA` [靜]

- `C06FBCAA` 在 `C06FBC08` 裡 = span 表 1 idx 3/6/11–14 的 **8bpp LUT 混色**,neonblit 已經接手(×4.7)。
  實測 3 的逐項量測是在 70PERF 全關下做的，所以它還出現在熱點裡。
- `C06FBD28` 在 `C06FBCD8` 裡 = span 表 1 **idx 7**(`0xC2EB3F78`,ARGB4444 來源混到 ARGB4444 目的;
  數字字形 `font_M_*` 走這條)。**neonblit 沒有換 idx 7**(README 列為「照走原廠」)。
  → 真正能省時間碼 CPU 的是**把 idx 7 也做成 NEON**(逐位元對拍，同 neonblit 的做法)，不是合併訊息。

## 建議(取代原任務)

1. 放棄 uicoalesce。
2. neonblit 加 idx 7(`C06FBCD9`):時間碼與其他 ARGB4444 圖示的混色。
3. 時間碼剩下的成本在每輪走訪 + `C0563BA8`(alpha 縮放)+ 整快取/整層複製，這些已在 v2 清單上。

- 70PERF `nb=1` 下重跑 `validation/20261019-live/ui_cost.py` 的 TimeCode 項：`C06FBCAA` 應消失、`C06FBD28` 仍在。
