# 撥開關重開時，韌體映像為什麼有時保留、有時重載(2026-10-20,離線)

對象：瞬間啟動(Fast Start 2)= 映像留在 DRAM、loader hook 0xC03DA420 被執行。
上機樣本(`../validation/README.md`):觸發 ⇔ 映像保留;USB 拔 4/5、插 0/3。
**[靜]** = 反組譯直接看到;**[推]** = 推論;位址 MAIN 以 0xC0000000 為基底，IPL 以 decomp 的 0x2E000000(檔案 +0x4000)。

## 1. IPL 怎麼決定(答案：一個硬體位元)[靜]

IPL 主流程 `FUN_00004428`(ipl_v7.c 第 1811 行起):
```
if (FUN_00004958() == 1) {          // = [0x2D000280] & 1
    printf("selfrefresh!\n");        // 0x2E00D50C
    FUN_000078d8(..., 0x10000012);    // 只讀一個小分割區
    jump(entry)                       // 回到 DRAM 裡還活著的 MAIN → 瞬間啟動
} else {
    FUN_000040b8(...)                 // 依分割表從 NAND 整個載入 → "finished." → 冷開機
}
```
- **判斷只看 `0x2D000280` bit0**(電源/重置控制區塊的狀態暫存器)。沒有映像校驗、沒有 RAM 魔數。
- MAIN 開機時也讀同一位元(`C0016918`):為 1 時跳過部分初始化 [靜]。
- 所以「映像有沒有保留」不是運氣：是**上一次關機時，電源控制器有沒有進入 DRAM 自我刷新待機**。

## 2. 關機路徑怎麼決定進不進自我刷新

### 2a. 最後一道命令 `C0122F90(mode, wake)`(Thumb)[靜]
寫電源控制器命令暫存器 **`0x2D000400`**(= `0x2D000288+0x178`),之後無限等斷電:

| mode | 命令 |
|---|---|
| 1 | 0x40 |
| 2 | 0x20 |
| 3 | 不關機，只設 `[0xC31D848C+0x234]=1` |
| 0(一般) | **0x10**;但若 `r5=1` 改 **0x40** |

`r5=1` 的條件(任一):
- `[0xC31D848C+0x234]==1` 且喚醒因子暫存器 `0x2D000308` / `0x2D00030C` 非 0;
- 已註冊的回呼 `[0xC31D848C]`(= `C0023B60`,由 `C0023A20` 註冊)回傳非 0。
- 另外：`[+0x230]!=2` 且 r5=0 時，先把 `0x2D000308/30C` 寫 -1(清喚醒因子)。

**[推]** `0x10` = 自我刷新待機(下次 IPL 看到 `0x2D000280` bit0=1 → 瞬間啟動);`0x40`/`0x20` = 完整斷電/重置(下次冷開機)。
這要上機用 §5-1 證實(看保留成功那幾次的 0x2D000280)。

### 2b. 關機主程序 `C0023C50`(XC_PowerOffMgr,物件 `0xC30756C4`)[靜]
- mode 由關機原因 `[obj+0x60]` 決定：原因 1、2、5 → mode 0;3、4、6 → mode 2;其他 → 錯誤分支。
- 喚醒來源遮罩：自我刷新時間 `[obj+0x6C]`(=900,`C0024310`)非 0 → OR 來源 0;
  **`[obj+8]` 非 0 → OR 來源 1,並 `C00CDD58(…,6,1)`**;否則走 `C0122780`。
- `[obj+8]` 由 `C00CDDC8()` 寫入(`C00239F8`)。**[推]** 是「外部供電/USB 連接」——它同時決定喚醒來源與分支，與「插 USB 就不保留」吻合。

### 2c. 回呼 `C0023B60`(決定 0x10 或 0x40 的那個)[靜]
- `r5 = [obj+0x69]!=0 && [obj+0x60]!=5`。
- r5 時：某裝置物件(`C00CC290()` 的 vt+0x10)回 0 **且** `C0024878()` 非 0 → **回傳 1(→ 0x40,不保留)**。
- 否則 `C0023AD8(obj)`(自我刷新啟用 `C0024210` + `[obj+0x68]` + `[obj+0x6A]` 等)為真 → 設定並呼叫 `C01F9320`
  (讀分割區 `0x10000012`——與 IPL 自我刷新路徑讀的同一個——再寫 `0x2D000400=1` 重置)→ 這是另一條「快速重開」路徑 [推]。
- 回傳 0 → 一般 `0x10`。

## 3. USB 為什麼有影響、剩下的隨機性從哪來 [推]
1. **USB/外部供電**:`[obj+8]`=1 → 喚醒來源加入來源 1(VBUS)。VBUS 一直在，關機當下喚醒因子 `0x2D000308/30C` 很可能就非 0,
   或回呼 `C0023B60` 的裝置檢查回 1 → 命令變 0x40 → 不保留。
2. **喚醒因子殘留**:關機瞬間若有按鍵彈跳、電源開關抖動、陀螺/加速度中斷、電池事件，因子非 0 → 0x40。這可解釋「拔線也偶爾失敗(3a)」與「插線也不一定」。
3. **關機原因**:非一般關機(原因 3/4/6,例如低電量、某些錯誤)→ mode 2 → 0x20 → 必不保留。
4. 自我刷新本身有 900 s 上限(`[obj+0x6C]`,已實測)與實體保留界線 10–25 分鐘(記憶 warm-restart-keeps-the-cave)。

## 4. 能不能提高保留率(只提出，未做)
| 方案 | 做法 | 風險 |
|---|---|---|
| A. 使用者側 | 撥開關前拔 USB | 無;目前最可靠 |
| B. 關機前清喚醒因子 | 在 PowerOffMgr 回呼(loader journal 已有關機回呼)把 `0x2D000308/30C` 寫 -1 | 中：可能吃掉真正要的喚醒事件;若 USB VBUS 持續存在，因子會立刻再被設 |
| C. 讓回呼 `C0023B60` 不否決 | RAM 補丁(可逆、journal 還原) | **高**:USB 供電下進自我刷新可能立刻被喚醒、反覆開機、或影響充電模式;原廠刻意這樣設計的可能性大 |
| D. 強制命令 0x10 | 改 `C0122F90` 的分支 | **高**,同上，且關機原因 3/4/6(低電量)強制待機有資料/電池風險 |
**絕不碰 IPL/BOOT 分割區**(無 A/B 救援槽，寫壞即磚)。B 以外都要先完成 §5 的唯讀驗證。

## 5. 上機最小驗證(唯讀為主)
1. **每次開機讀 `0x2D000280`**:瞬間啟動那幾次應 bit0=1、冷開機 bit0=0(直接證實 §1,可併進 boot_timeline.py)。
2. **關機前讀** `0x2D000308`、`0x2D00030C`(USB 插/拔各讀幾次):插著時應常非 0。
3. 讀 PowerOffMgr 欄位 `[0xC30756C4 + 0x08/0x60/0x68/0x69/0x6A/0x6C/0x70]` 與 `[0xC31D848C]`(應 = C0023B60)、`[0xC31D848C+0x230/0x234]`,USB 插/拔各一次 → 確認 `[obj+8]` 是不是「外部供電」。
4. (選做，需另議)在 `C0122F90` 前掛唯讀計數器，記下每次關機寫入 0x2D000400 的值，存到 DRAM 頂端(撐得過自我刷新)，下次開機讀出——直接把「命令值」與「是否保留」對起來。

## 6. 插 USB 為何送 0x40:否決回呼 C0023B60 拆解(2026-10-20,離線)

**結論(靜態+推論)**:插 USB 時是**否決回呼回 1**(不是喚醒因子)。條件全成立才否決:
1. `mgr+0x69 != 0 && mgr+0x60 != 5`(mgr=0xC30756C4;上機讀到 +0x69=1、+0x60=1 → 成立)[靜+上機]。
2. `C00CC290()->vt[+0x10]()` == 0:物件 0xC31CC164,vtable 0xC07499D0,類別 **XC_TargetConfig_w71c1**;方法 `C00CC008`:`+0x10` 旗標或某設定 ==0x10 → 1;否則讀一個 4 B 設定值，**為 0 或 -1(未設定)才回 1**。一般出貨機應回 0 → 成立 [靜/推]。
3. `C0024878() != 0`:**不是純讀取**(見下),回 1 的條件 =「相機不忙」且「(輸入 id2 為 1)或(電池管理的外部供電旗標)」:
   - `C0024730`(忙碌檢查):`C00178D8()→C0017AC8()` 物件的 `+0x19/+0x2C/+0x2D/+0x2E/+0x2F` 任一非 0,或 `[0xC3075748]` 非 0 → 忙 → 整體回 0(**不否決**)。同時寫 0x2D000320 的 id7 位元。
   - `C00247D0`:`r5 = C01226B8(2)==1`(Thumb;→ `C01242C8(2)` 讀 **0x2D000314** 原始輸入，經表 0xC07D1308/0xC07D1398 取 id2 位元——推為 **VBUS/USB 偵測腳**);
     `r6 = [[0xC30783D8+4]+0xB8]`(`C002C268()`→`C002C360`,電池管理單例的**外部供電**位元組);回 `r5||r6`;並寫 0x2D000320 的 id4 位元。
- 不否決時(條件 1 不成立或 2/3 回 0)走 `C0023AD8(mgr)`:若成立，寫 0x2D000320 id5=1、`C0024018(mgr,0,[mgr+0x6C])`、投遞 `C01F9320(&evt)`(evt 帶 C0024730/C00247D0 回呼)→ 回 0 → **0x10 自我刷新**。推:這是「接著 USB 關機 → 進 USB 供電/充電待機」的正規路徑之一。
- **0x2D000320** = `C00CDD58(obj 0xC31CC2C4, id, val)` 讀改寫的位元遮罩(id→位元映射在 obj 的 32 格表;讀 `C01227C8`、寫 `C01227B0`)——推為 PMIC 的「保持/喚醒致能」遮罩。
- 解釋「插 USB 也不一定冷開機」:關機瞬間若 `C0024730` 判定忙(錄影/寫卡/某狀態 [0xC3075748] 等),條件 3 回 0 → 不否決 → 0x10 [推]。

**上機唯讀驗證(插 USB vs 拔 USB 各讀一次)**
- 直接讀:`0x2D000314`(原始輸入;看哪個位元隨 USB 變)、`0x2D000320`(保持遮罩)、`[0xC3075748]`、`[[0xC30783D8+4]+0xB8]`(外部供電)、`[0xC31CC164+0x10]`、`mgr+0x60/+0x69`。
- 可安全 callfn(純讀取，已看完全部路徑):`C01226B8|1`(r0=2)、`C00CDDC8(0xC31CC2C4, 1)`(讀 0x2D000320 位元)、`C002C360(C002C268())`(C002C268 是已建構的單例 getter)。
- **不可呼叫**:`C0024878`、`C0024730`、`C00247D0`(會寫 0x2D000320)、`C0023B60`(後段投遞事件)、`C00CC008` 只在確認 C04CDB20 為純建構後才可。

**修法候選(都會改變原廠行為，只做成除錯開關、預設關)**
| # | 做法 | 風險 |
|---|---|---|
| F1 | 我們已在關機時包住否決回呼(`--pwroff-log` 的 pl_wrap);加 RAM 開關:插 USB 時讓包裝回 0 | **中-高**:原廠刻意在外部供電時完全重置;改成自我刷新後(a)關機充電是否照常、(b)醒來時 USB 是否正常重新列舉(先前見過介面停在 PTP)、(c)VBUS 是否讓 PMIC 立刻再喚醒造成開機循環——都未知 |

## 7. 插 USB 為何是 reason 3(2026-10-20,實測 + 靜態)

**實測**(\fpSup\PWROFF.LOG):插 USB 撥開關 → reason 3、mgr+0x60=3 → 冷開機;拔 USB → reason 1 → 瞬間。0x2D00030C 兩者皆非 0(0x400 / 0x600)→ **喚醒因子不是決定因素;§6 的「否決回呼」也不是**(開關改回呼已實測無效)。

**誰把 1 改成 3**[靜]:撥開關的關機處理 `C0450068`(r1==1)→ `C0450080: bl C04B22C0`。
`C04B22C0(holder=[C04B2168()]=0xC3768DD0)`:若 holder 原值為 1 或 5,且外部供電(`C002C360(C002C268())`)≠0、且 XC_TargetConfig vt+0x10 回 0 →
`C00CDD58(C00CDCB0(),4,1)`(PMIC 保持遮罩 id4=1,推:USB 供電路徑保持)、holder = 3(原 5 則 6),回傳後 `C0023FC0(mgr,3)` 存 mgr+0x60 並投給關機任務。

**reason 的意義**[靜]:shell 指令表(0xC0BAC56C 起)——`poff`=`C0405D60`:可選參數 N → `C0024088(mgr,0,N)`(1..65535,存 mgr+4=N、**mgr+8=1=「排定喚醒」**,更正 §3「+8=USB」的推測),清 mgr+0x69,`C0023F38(mgr,1)`;
`reboot`=`C0405DD8` → reason **3**;`rebootf`=`C0405DF8` → reason 4(走強制清單)。
→ **插 USB 撥開關 = 韌體當成「reboot」**(reason 3),C0023C50 對 3/4/6 走 mode 2(0x20),映像必重載。

**C0023C50 的順序**[靜]:先 `C0023EB8(mgr,+0x60)`、跑普通清單(我們的 poff_hook 在這裡)、之後 `C0023D54` 才依 **mgr+0x60** 分派:
1 → 若 mgr+8 則 `C0024018(mgr,1,mgr+4)` 設鬧鐘、`obj->vt[0x1C](1)`、mode 0;2 → vt[0x1C](0)、mode 0;3/4/6 → mode 2;5 → mode 0。

**除錯開關的新做法(建議，未實作——編輯被權限擋下)**:在 `fu_arm`(poff_hook 內，清單階段)開頭，開關=1 且 `mgr+0x60==3` 且 `[0xC3768DD0]==3`(只有 C04B22C0 會設;shell `reboot` 不碰 holder → 照樣重開)時:
mgr+0x60=1、holder=1、`C00CDD58(C00CDCB0(),4,0)`(把 C04B22C0 設的保持位元還原成 reason 1 時的值)、計數。之後既有的否決回呼改寫仍需要(reason 1 路徑下否決回呼會因外部供電回 1)。
不需新的程式碼補丁(mgr+0x60 在清單之後才被讀)。風險：略過「USB 供電保持 + 重開」→ 插著 USB 關機後進自我刷新待機;(a)是否被 VBUS 立刻喚醒(開機循環)(b)醒來 USB 列舉(c)關機期間不充電/耗電——皆未知，僅供開發。

**`poff` 能否代替撥開關**[靜]:`poff` 走 reason 1 + 清 mgr+0x69(→ 否決回呼條件 1 不成立 → 不否決)→ mode 0。**插著 USB 用 `poff N` 可能直接得到 0x10 + N 秒後鬧鐘喚醒的自我刷新重開**(喚醒源 1 會加進 C0023E54 的遮罩)。但 C0122F90 對「喚醒因子非 0」送 0x40 的分支是否被鬧鐘喚醒觸發未確認——**上機一試即知**:`poff 5` 後看 0x2D000280 bit0。不帶 N 的 `poff` 則需撥開關開機。
`rebootf` 與 `reboot` 差別：4 走 C0023F38 的強制清單分支(不經 C0023FC0/關機任務)、同為 mode 2 → 兩者都重載映像，都不是暖重開。
